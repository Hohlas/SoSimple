## Детали реализованных skills

### ✅ update-docs-on-code-change
**Команды**: `sync docs`, `обнови документацию`, `синхронизируй docs`

**Что делает**:
1. Находит изменённые .py/.mq4/.ipynb файлы (через `git diff --cached`)
2. Обновляет file headers (дата "Обновлён")
3. Обновляет соответствующие .md файлы в `docs/data_preprocessing/` или `docs/data_analysis/`
4. Обновляет `docs/architecture.md` (если изменился pipeline)
5. Показывает diff и запрашивает подтверждение

**Использование**:
```bash
# После изменения кода, перед коммитом
> sync docs
```

**Документация**: [.ai/skills/update-docs-on-code-change/SKILL.md](.ai/skills/update-docs-on-code-change/SKILL.md)

## Планируемые skills (приоритет реализации)

### Приоритет 1 (критичные для работы)

#### ⏸️ create-module-docs

**Команда**: `doc this [файл]` или `document [файл]`

**Зачем**: Быстрое создание документации для нового/недокументированного модуля без ручного копирования шаблонов.

**Что делает**:

- Проверяет наличие file header, создаёт если нужно
- Создаёт `docs/[категория]/[модуль].md` по шаблону
- Добавляет запись в `MODULE_INDEX.md`
- Обновляет `DATA_FLOW.md` (если модуль участвует в pipeline)


#### ⏸️ validate-docs-sync

**Команда**: `check docs` или `validate docs`

**Зачем**: Обнаружить устаревшую документацию (когда код изменился, а .md — нет).

**Что делает**:

- Сканирует все .py/.mq4/.ipynb с file headers
- Сравнивает дату "Обновлён" с `git log`
- Проверяет наличие соответствующих .md файлов
- Выводит отчёт: ❌ нет документации, ⚠️ устарела, ✅ актуально


### Приоритет 2 (полезные для разработки)

#### ⏸️ add-new-module

**Команда**: `create module [имя]` или `new script [имя]`

**Зачем**: Автоматизировать создание нового модуля с полным набором документации.

**Что делает**:

- Интерактивно спрашивает параметры (директория, назначение, входы/выходы)
- Создаёт файл с file header по шаблону
- Создаёт `docs/[категория]/[имя].md`
- Добавляет в `MODULE_INDEX.md` и `DATA_FLOW.md`
- Открывает файл в редакторе


#### ⏸️ check-data-impact

**Команда**: `check data impact [файл]` или `impact analysis [файл]`

**Зачем**: Предотвратить breaking changes — показать, какие скрипты сломаются при изменении формата данных.

**Что делает**:

- Читает секцию "Выходные данные" из file header
- Находит в `MODULE_INDEX.md` все downstream-скрипты
- Рекурсивно строит граф зависимостей
- Выводит ASCII-дерево зависимостей


### Приоритет 3 (удобство)

#### ⏸️ explain-pipeline-step

**Команда**: `explain step [название]` или `what does [название] do`

**Зачем**: Быстро получить детальное объяснение шага pipeline без чтения исходного кода.

**Что делает**:

- Ищет шаг в `DATA_FLOW.md`
- Загружает связанные .md документы
- Формирует краткое резюме: что делает, входы/выходы, команда запуска, особенности


#### ⏸️ generate-module-index

**Команда**: `rebuild module index` или `refresh MODULE_INDEX.md`

**Зачем**: Автоматически пересоздать `MODULE_INDEX.md` после массовых изменений или если индекс потерял синхронизацию.

**Что делает**:

- Сканирует все .py/.mq4/.ipynb в проекте
- Извлекает file headers и парсит секции
- Генерирует новый `MODULE_INDEX.md`
- Показывает diff и запрашивает подтверждение


#### ⏸️ create-eda-report

**Команда**: `analyze [файл.csv]` или `run eda [файл.csv]`

**Зачем**: Автоматизировать базовый EDA для датасета.

**Что делает**:

- Загружает датасет (sampling если > 10MB)
- Выполняет: `df.info()`, `df.describe()`, проверка пропусков/дубликатов, распределение целевой переменной
- Генерирует отчёт в `docs/data_analysis/[файл]_eda_[дата].md`
- Опционально создаёт графики в `plots/[файл]/`

## Как использовать skill

1. **Проверь индекс**: открой `SKILLS_INDEX.md` и найди нужную команду
2. **Запусти команду**: напиши команду в чат с ИИ-агентом (Cursor/Antigravity)
3. **Дождись подтверждения**: агент покажет diff и попросит подтверждение перед применением изменений
4. **Проверь результат**: убедись, что изменения корректны

---

## Как запросить новый skill

Если нужна автоматизация задачи, которой нет в индексе:

1. Опиши задачу: "Мне нужно автоматизировать [описание]"
2. Укажи триггер: "Я хочу запускать это командой `[команда]`"
3. Опиши ожидаемый результат: "Команда должна [что делать]"

ИИ-агент создаст skill по шаблону `SKILL.md` и добавит его в проект.
