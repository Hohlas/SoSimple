
Мы генерируем индексный файл. Этот файл строится автоматически из существующего контента и содержит проверяемые ссылки на все значимые артефакты проекта.

2.1. Структура нового индекса (wiki/WIKI_index.md)
файл WIKI_index.md, который будет:
Начинаться с инструкции для агента (как использовать вики).
Содержать сводку всех сущностей проекта с путями к файлам и хешами/временными метками.
Включать категории: Модули кода, Отчёты, MQL библиотеки, CSV схемы, Решения (из CHANGELOG и docs/reports/*).


2.2. Скрипт генерации (wiki/scripts/generate_wiki.py)
Создам Python-скрипт, который:
Обходит репозиторий по правилам (игнорируя .git, __pycache__, venv и т.д.).
Для каждого значимого файла вычисляет blake2b хеш или просто сохраняет mtime + size.
Парсит существующие индексы (MODULE_INDEX.md, CHANGELOG.md, заголовки отчётов) и связывает их с реальными путями.
Генерирует WIKI_index.md.
Скрипт можно запускать перед каждым коммитом (pre-commit hook) или по требованию.

2.3. Верификация целостности (wiki/scripts/verify_wiki.py)
Отдельный скрипт, который агент (или человек) может запустить перед началом работы:
Сравнивает хеши/временные метки в WIKI_index.md с текущим состоянием файловой системы.
Выдаёт отчёт о расхождениях: какие файлы изменились, какие ссылки устарели.
Может предложить запустить генерацию заново.
Зачем это нужно: Агент будет знать, что если verify_wiki.py возвращает "OK", индекс полностью актуален. Если нет — попросит пользователя обновить вики, или обновит сам.

2.4. Интеграция с существующими инструкциями агента
Добавим в AGENTS.md (или CLAUDE.md) директиву:

```
LLM Wiki Access Protocol
1. **First action:** Check `WIKI_index.md` for project map.
2. **Integrity check:** Run `python wiki/scripts/verify_wiki.py`. If fails, inform user to regenerate wiki.
3. **Navigating:** Use paths from wiki to locate source files, reports, or data schemas.
4. **Updating:** When you modify significant project content (code, docs), remind user to run `python wiki/scripts/generate_wiki.py` and commit the new `WIKI_index.md`.
```

2.5. Обработка изменений в живых файлах (py / md)
Это ключевое отличие от Карпати. Вместо "immutable raw" мы принимаем версионированную изменчивость.
Решение: Вики привязана к коммиту.
При каждом изменении кода или документации разработчик запускает generate_wiki.py.
Новый WIKI_index.md коммитится вместе с изменениями.
Агент, читая вики из конкретного коммита, получает снимок проекта на этот момент.
Это работает точно так же, как MODULE_INDEX.md, но автоматически и с хешами для проверки.
