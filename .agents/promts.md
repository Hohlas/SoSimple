## Проверь
```md
**Проверь его полностью**
Точечно изучи контекст проекта, необходимый для погружения в тему данного документа.
Точечно проверь только реально связанные с ним артефакты (ссылки из документа, упомянутые файлы, ближайшие README, планы, отчёты, методики, код). 
Для поиска и навигации по проекту используй graphify и knowledge-rag.

Проведи аудит доказательно по фактам и уликам, а не по впечатлениям, уверенности и доверию. 
Не пиши общие замечания без доказательств.

Для каждого утверждения, вывода, измененного кода и прочих созданных артефактов  проверь:
  - фактические, принципиальные, алгоритмические ошибки и противоречия;
  - неподтверждённые утверждения;
  - прагматичность, эффективность, качество, полноту и точность;
  - несоответствия методологии docs/methodology;
  - что стоит исправить / добавить / убрать / уточнить.

Если были изменения кода, проведи проверки смыслового уровня:
  - результат соответствует заявленной функции: на контрольном примере код выдаёт ожидаемое значение, а не просто завершается без ошибок;  
  - алгоритм точно соответствует описанному в методике/документе, а не «примерно» (порядок операций, формулы, параметры);
  - корректность на краевых данных: пустой вход, единичная запись, пропуски, экстремальные значения;
  - правильность подтверждается независимым способом: пересчёт метрики вручную или альтернативным путём, сверка с эталоном.

Для каждого замечания укажи:
  - важность: критично / важно / улучшение / вопрос;
  - место: файл, раздел или строка, если возможно;
  - суть проблемы;
  - доказательство: файл / строка / команда / документ или явное указание, что это гипотеза;
  - почему это важно;
  - рекомендуемое исправление.

Полностью очисти файл `docs/superpowers/audit.md`, не читай его содержимое. 
Сохрани аудит в этот файл. 
```

## Исправь и аргументируй
```md
**Аудит**
Это аудит твоей работы: docs/superpowers/audit.md. Он не является источником истины. Прочитай его полностью. 
Если есть неясные замечания, сначала явно укажи, что именно непонятно, и не исправляй их без уточнения.
Проверь каждое замечание критически по исходным файлам проекта, релевантной методологии и применимым проверкам.

Для каждого пункта аудита:
  - определи статус: принято / частично принято / отклонено / требует уточнения;
  - если принято — внеси минимально необходимые исправления;
  - если частично принято — исправь подтверждённую часть и кратко объясни, что не принято;
  - если отклонено — кратко докажи почему, со ссылкой на артифакт (файл, строку, команду, ...);
  - если требует уточнения — явно укажи, чего не хватает для решения.

Не делай посторонний рефакторинг и не исправляй то, что не относится к аудиту.

После исправлений запусти применимые проверки. 
В финальном ответе перечисли:
  - что исправлено;
  - что отклонено и почему;
  - какие проверки выполнены;
  - какие риски остались.
```

```md
**Правила диалога**

- Относись к моим идеям критически: не принимай их как истину без проверки.

- Задавай уточняющие вопросы, если запрос неоднозначен или требует дополнительного контекста.
```
