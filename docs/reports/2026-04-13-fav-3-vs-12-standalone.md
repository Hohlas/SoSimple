# Fav 3 vs 12 Standalone Verdict

> **Date**: 2026-04-13
> **Status**: CLOSED
> **Verdict**: `reject_as_standalone`
> **Goal**: Проверить, можно ли считать `fav_3_vs_12` самостоятельным устойчивым режимом отбора без `quantile`

---

## 1. Вывод

`fav_3_vs_12` не проходит как самостоятельный торговый режим.

Причина простая:

- устойчивой зоны порога на `validation` не найдено;
- ни один порог не проходит базовые требования;
- лучший `PF` на `validation` намного ниже `1.0`;
- по годам есть множественные слабые срезы;
- `test` тоже не показывает самостоятельного качества.

Это означает, что `fav_3_vs_12` сам по себе не годится как отдельная вторая система.

## 3. Метод

Проверка намеренно не использует `quantile`.

Для каждого порога считается правило:

```text
fav_3_vs_12 <= threshold
```

Сетка порогов:

```text
0.20, 0.22, ..., 1.20
```

Порог выбирается только на `validation`.
`test` используется только после выбора порога.

Критерии:

- `min_trades_validation = 30`
- `min_trades_test = 30`
- `min_pf_validation = 2.0`
- `min_pf_test = 1.5`
- `max_negative_year_slices_validation = 0`
- `max_negative_year_slices_test = 0`
- `min_year_trades = 3`
- `window_size = 5`
- `min_passing_in_window = 3`

Плохой годовой срез:

```text
yearly PF < 1.0
```

Годы с числом `trades < 3` не используются как самостоятельный gate-fail.

## 7. Почему результат отличается от fav_only в composition-отчёте

В composition-отчёте `fav_only` считался внутри baseline universe.

Здесь проверка строже:

- `quantile` не применяется;
- baseline-отбор не применяется;
- проверяется именно самостоятельный режим `fav_3_vs_12` на active universe.

Поэтому этот результат отвечает на другой вопрос:

```text
Может ли fav_3_vs_12 сам по себе быть отдельной системой?
```

Ответ:

```text
Нет.
```

- Это не проверка `fav_3_vs_12` внутри baseline universe.
- Это не проверка комбинаций с другими признаками.
- Это не production-план.

---

## 9. Решение

Направление `fav_3_vs_12` как самостоятельной второй торговой системы закрывается.

Практический вывод:

- не использовать `fav_3_vs_12` как отдельный режим;
- не переносить его в MT4;
- не тратить время на productization standalone-варианта;
- если возвращаться к признаку, то только как к вспомогательному фактору внутри другого уже сильного отбора, но не как к отдельной системе.
