# Fractal Stop Stage 4 — XGBoost Trading Layer

> **Date**: 2026-06-12
> **Status**: Completed, updated with Stage 4.1 controls and Stage 4.2 diagnostic
> **Verdict**: FAIL — XGBoost breach-классификатор (AUC 0.68) не конвертируется в устойчиво прибыльный PF на validation. 7/8 Stage 4 primary-таргетов PF < 1.0. Winner `sell_H6_off05` (PF=1.106, BS_p05=0.923) не статистически значим. Stage 4.1 проверил два контрольных улучшения: XGBoost-fav ухудшил PF на всех 4 SELL-таргетах, combined breach H6+H12 дал PF=1.065 с `perm_p=0.050` и не превзошёл Stage 4 winner. **Stage 4.2 (DIAGNOSTIC)**: после исправления методических проблем (трёхслойный split, spread-коррекция под OHLC=Bid, early stopping на val_stop, block bootstrap) PF winner снизился с 1.106 до **1.015** — совокупный эффект исправленного диагностического протокола (Δ = −0.091). Breach-модель добавляет реальный сигнал для фиксированного правила (0/500 перестановок, p ≈ 0.002), но его силы недостаточно для gate > 1.15. Табличные модели на текущем представлении фракталов достигли практического потолка для этой торговой постановки.
> **Goal**: Проверить, транслируется ли прирост XGBoost breach-классификатора (Stage 3.2) в положительный торговый PF на validation. Primary: `base_raw_plus_time`, control: `relative_geometry_clean`.

## Context

Stage 2 (RF breach + RF fav) дал PF < 1.0 на всех 8 таргетах. Oracle-диагностика показала PF=∞ — проблема в модели, не в механике. Stage 3.1/3.2 довели AUC breach-классификатора с RF 0.645 до XGBoost 0.680 (+345 bp). Stage 4 проверяет, достаточно ли этого прироста для статистически значимого торгового PF и gate PF > 1.15.

Гипотеза: XGBoost breach + RF fav → торговое правило (как в Stage 2) → PF > 1.0 на validation. Fav-регрессор оставлен RF для изоляции вклада breach-классификатора.

После аудита Stage 4 выполнен Stage 4.1: XGBoost-fav вместо RF-fav, combined breach-фильтр H6 AND H12 и permutation test для проверки, насколько winner отличается от случайной перестановки breach-вероятностей.

## What Was Done

### 1. Модели

- **Breach**: XGBoost, `n_estimators=200`, `max_depth=6`, `learning_rate=0.05`, `subsample=0.8`, `colsample_bytree=0.8`, `scale_pos_weight`, early stopping по validation AUC.
- **Fav**: RandomForestRegressor, `n_estimators=200`, `max_depth=12`, `min_samples_leaf=50` (без изменений от Stage 2).

### 2. Профили признаков

| Профиль | N фич | Состав |
|---------|-------|--------|
| `base_raw_plus_time` (primary) | 1005 | 10 каналов × 100 фракталов + ATR + 4 time-фичи |
| `relative_geometry_clean` (control) | 1011 | base_raw с price→(price−f0_price)/ATR + density_excl_f0 + time |

### 3. Торговый симулятор

- Entry: Open следующего H1-бара
- Stop: за экстремум fractal0 + stop_offset × ATR
- TP: доля `tp_fraction` от `fav_pred`, потолок 5.0 ATR
- Spread: 0.20 (canonical)
- Выход: first-touch SL/TP/TIMEOUT по `evaluate_fractal_stop_trade()` (Stage 2)
- Вход только при: `breach_proba < p` (модель уверена — стоп НЕ пробьётся), `fav_pred ≥ min_fav_val`, `fav_pred / stop_val_actual ≥ min_rr`
- Направление: каждая сторона (buy/sell) торгуется изолированно

### 4. Grid search (малый, фиксированный)

| Параметр | Значения |
|----------|----------|
| p | [0.3, 0.4, 0.5] |
| min_fav_val | [0.3, 0.5] |
| min_rr | [1.0, 1.5] |
| tp_fraction | [0.4, 0.6] |

24 комбинации на таргет. Winner: максимальный PF при `trades/year ≥ 30`. Bootstrap PF: 500 итераций, median / p05 / p95.

### 5. Скрипт и данные

- **Скрипт**: `ML/baseline/benchmark_fractal_stop_stage4.py`
- **JSON base_raw_plus_time**: `ML/reports/stage4_trade.json`
- **JSON relative_geometry_clean**: `ML/reports/stage4_trade_geom.json`
- **Stage 4.1 скрипт**: `ML/baseline/benchmark_fractal_stop_stage4_1.py`
- **Stage 4.1 JSON**: `ML/reports/stage4_1.json`
- **Validation**: 2019–2022, 9451 строк, purge 12 баров
- **OHLC**: `DATA/XAUUSD_H1_OHLC.csv` (126 637 баров)
- **Test не открывался**

### Stage 4.2 — диагностический пересчёт winner с исправленной методикой

После аудита Stage 4 (GLM + Qwen) выполнена диагностика: тот же winner `sell_H6_off05` с теми же параметрами (`p=0.4, mf=0.3, rr=1.0, tf=0.4`), но с исправленной методикой. **Статус: DIAGNOSTIC_ONLY** — winner был выбран на Stage 4 по validation 2019–2022, поэтому val_eval косвенно участвовал в выборе. Это не чистый out-of-sample бенчмарк.

#### Что исправлено относительно Stage 4

| # | Проблема Stage 4 | Исправление Stage 4.2 |
|---|-----------------|----------------------|
| 1 | Тройное использование validation (early stopping + grid search + оценка на одном наборе) | Трёхслойный split: train (2004–2016) → val_stop (2017–2018, early stopping) → val_eval (2019–2022, оценка) |
| 2 | Grid search 24×8 = 192 конфигураций | Фиксированная конфигурация, без нового перебора (конфигурация унаследована из Stage 4) |
| 3 | Early stopping на том же validation, где оценивается AUC/PF | Early stopping на val_stop (2017–2018), оценка на val_eval (2019–2022) |
| 4 | Spread-модель неконсистентна с OHLC=Bid | Корректная модель: BUY — entry+spread (Ask), exit bars as-is (Bid); SELL — entry as-is (Bid), exit bars shifted +spread (Ask) |
| 5 | i.i.d. bootstrap не учитывает временную корреляцию | Block bootstrap (block_size=15, 500 итераций) |
| 6 | Нет permutation test для индивидуального winner | Permutation test (500 итераций) для одного унаследованного target |

**Совокупный эффект исправленного диагностического протокола:** PF 1.106 → 1.015 (Δ = −0.091). Stage 4.2 одновременно меняет train-период (2004–2016 вместо 2004–2019), слой early stopping (val_stop вместо val_eval), spread-модель (коррекция под OHLC=Bid), отказ от нового grid search и число сделок (344 → 503). Разложить вклад каждого фактора без отдельной абляции нельзя. Наблюдаемая Δ = −0.091 — совокупный эффект всех исправлений протокола.

**Permutation test:** 0/500 перестановок breach-вероятностей достигли PF ≥ 1.015 (консервативная оценка p ≈ 1/501 ≈ 0.002). Это справедливо **только для фиксированного диагностического правила** `sell_H6_off05, p=0.4, mf=0.3, rr=1.0, tf=0.4` — winner был выбран ранее на Stage 4 по validation 2019–2022, и permutation test не исправляет этот исторический selection bias. Медианный PF при случайных breach = 0.817, максимальный среди 500 перестановок = 0.959. Наблюдаемый PF = 1.015 находится выше всего случайного распределения для данного правила. Breach-классификатор **добавляет реальный сигнал**, но его недостаточно для стабильной прибыльности (gate > 1.15).

**Годовая устойчивость (Stage 4.2):**

| Год | Сделок | PF |
|-----|--------|-----|
| 2019 | 107 | 0.774 |
| 2020 | 172 | 1.071 |
| 2021 | 99 | 1.267 |
| 2022 | 125 | 1.011 |

По сравнению со Stage 4: годовой профиль значительно ровнее (1/4 убыточных лет вместо 3/4). 2019 улучшился с 0.48 до 0.774 за счёт включения данных января–июня 2019 из train-файла (более репрезентативная выборка). Три из четырёх лет имеют PF ≥ 1.0 — но ни одно не показывает уверенной прибыльности (максимум 1.267 при 99 сделках — шумная оценка).

**Почему больше сделок (503 vs 344):** исправленная spread-модель для SELL убрала `entry − spread` (раньше entry занижалась на спред). При более высокой entry цена:
- Больше `stop_val_actual` (стоп дальше от entry)
- Больше сделок проходят фильтр `pred_fav / stop_val_actual ≥ min_rr`

**Ключевой вывод Stage 4.2:** breach-модель добавляет реальный сигнал для фиксированного правила (0/500 перестановок, p ≈ 0.002, ΔPF ~ +0.20 над случайным), но этого сигнала недостаточно для gate PF > 1.15. Проблема не в отсутствии сигнала, а в его слабости — даже «хороший» breach-классификатор не даёт достаточного edge для покрытия спреда и шума fav-предсказаний.

## Verification

- Test не использовался ни на одном этапе (Stage 4, 4.1, 4.2).
- Stage 4.2 использует трёхслойный split: train (2004–2016), val_stop (2017–2018), val_eval (2019–2022).
- Early stopping XGBoost на val_stop — val_eval не участвует в обучении.
- OHLC загружается один раз, entry_prices вычисляются до симуляции.
- Stage 4: 8 breach targets × 2 профиля = 192 симуляции (24 grid × 8 targets).
- Stage 4.1: 4 SELL individual targets с XGBoost-fav + 2 combined SELL targets.
- Stage 4.2: 1 target (sell_H6_off05), 1 конфигурация, без grid search.
- Bootstrap PF в Stage 4: 500 i.i.d. итераций. Stage 4.2: 500 block bootstrap итераций (block_size=15).
- Permutation test: Stage 4.1 — 500 перестановок для combined winner. Stage 4.2 — 500 перестановок для индивидуального winner.
- Fav-регрессор — RF (без изменений от Stage 2) для изоляции вклада breach-классификатора.
- Торговый симулятор: first-touch SL/TP/TIMEOUT, ambiguous bar = SL.
- Stage 4.2: исправленная spread-модель под OHLC=Bid (SELL bars shifted +spread, BUY entry+spread).
- Purge 12 баров на хвосте каждого слоя.

## Методологические примечания

1. **PF proxy из Stage 3.2 не заменил торговый PF.** Stage 3.2 показывал PF=10–30 для всех таргетов — это был диагностический PF, использующий `fav_val` как perfect exit knowledge. Реальный торговый PF в 20–30 раз ниже.
2. **AUC не предсказывает PF на уровне отдельных таргетов.** `sell_H12_off02` имеет лучший AUC (0.696) но PF=0.976. `sell_H6_off05` имеет AUC=0.674 но PF=1.106. Асимметрия breach_rate и распределения fav_val создаёт нелинейность между качеством ранжирования и торговым результатом.
3. **Buy-сторона структурно невыгодна для этой механики.** XAUUSD находится в долгосрочном восходящем тренде (2004–2022). Buy-фракталы (поддержки) реже ломаются с профитом — цена чаще отскакивает от поддержки и идёт вверх без пробоя стопа. Sell-фракталы (сопротивления) в аптренде пробиваются чаще, но когда НЕ пробиваются — дают более сильное движение. Это объясняет асимметрию PF: sell 0.91–1.11 vs buy 0.79–0.94.
4. **Замена RF-fav на XGBoost-fav не решила проблему.** RF fav имеет MSE 1.6–3.8 ATR², что означает ошибку предсказания 1.3–1.9 ATR при типичном стопе 0.2–0.5 ATR. Stage 4.1 показал, что более гибкий XGBoostRegressor ухудшает PF на всех проверенных SELL-таргетах. Это снимает гипотезу "достаточно заменить fav-модель", но не доказывает, что fav-цель не шумная.
5. **Time-фичи несут риск календарного фильтра.** +205 bp AUC от 4 time-признаков — крупнейший единичный вклад. Но это может означать торговлю по сессиям (London open, Asian), а не по фрактальной структуре. Такие паттерны неустойчивы при смене провайдера или ликвидности. Нужна проверка per-year stability time-важности и permutation-тест.
6. **Winner не проходит тест на статистическую значимость.** BS_p05=0.923 означает: 5% бутстрап-выборок дают PF≤0.92. Доверительный интервал (0.92–1.36) включает 1.0. С учётом 192 протестированных конфигураций (24 grid × 8 таргетов) без коррекции на множественное тестирование, 1–2 таргета с PF≥1.0 — это уровень случайного шума. Stage 4.1 permutation test подтвердил этот риск: лучший combined-кандидат имеет `perm_p=0.050`, то есть не отделяется от случайной перестановки с достаточным запасом.
7. **Годовая устойчивость отсутствует.** Stage 4 winner: 2019 PF=0.48 (52 сделки) — катастрофический убыток. Совокупный PF=1.106 держится на одном сильном годе (2020, 145 сделок, PF=1.279). Stage 4.2 улучшил картину (1/4 убыточных лет вместо 3/4), но годовые PF всё равно нестабильны: 0.77–1.27 при 99–172 сделках — шумные оценки без уверенной прибыльности.
8. **Совокупный эффект исправленного диагностического протокола:** PF 1.106 → 1.015 (Δ = −0.091). Stage 4.2 одновременно меняет train-период, слой early stopping, spread-модель, отказ от нового grid search и число сделок. Это согласуется с оценкой GLM-аудита (+0.10–0.25 PF), но разложить вклад отдельных факторов без отдельной абляции нельзя.
9. **Breach-модель добавляет реальный, но слабый сигнал для фиксированного правила.** Permutation test Stage 4.2: 0/500 перестановок breach-вероятностей достигли PF ≥ 1.015 (консервативная оценка p ≈ 1/501 ≈ 0.002). Однако winner был выбран ранее на Stage 4 по validation 2019–2022, и permutation test не исправляет этот исторический selection bias. Медианный случайный PF = 0.817. Для данного правила breach-классификатор даёт +0.20 PF над случайным. Проблема не в отсутствии сигнала, а в его недостаточной силе для покрытия спреда и шума fav-предсказаний.

## Conclusions

1. **Улучшение breach-классификатора с RF (AUC 0.645) до XGBoost (AUC 0.680) не конвертируется в устойчиво прибыльный торговый PF.** Рост AUC на +345 bp дал лишь маргинальное улучшение PF (с ~0.975 Stage 2 до ~1.015 Stage 4.2 после коррекции методики). PF=1.015 не проходит gate > 1.15 и не является статистически надёжным при учёте исторического selection bias winner.
2. **Stage 4 PF=1.106 включал совокупный эффект методических проблем.** Stage 4.2 (исправленный диагностический протокол) показал PF=1.015 (Δ = −0.091). Основные факторы: тройное использование validation, grid search на 192 конфигурациях, неконсистентная spread-модель и изменение train-периода. Без отдельной абляции разложить вклад каждого фактора нельзя.
3. **Breach-модель даёт реальный, но слабый сигнал для фиксированного правила.** Permutation test: 0/500 (p ≈ 0.002), модель добавляет ~+0.20 PF над случайным (1.015 vs 0.817). Сигнал реален для данного правила, но не исправляет исторический selection bias winner и недостаточен для стабильной прибыльности.
4. **`base_raw_plus_time` и `relative_geometry_clean` эквивалентны для торговли.** Разница winner PF 1.106 vs 1.142 — шум. Для практического использования `base_raw_plus_time` предпочтительнее как более простой.
5. **Проблема не решается локальной заменой fav-регрессора или пересечением H6/H12.** Stage 4.1 ухудшил PF при XGBoost-fav и не улучшил Stage 4 winner через combined breach.
6. **Годовая устойчивость улучшилась, но недостаточна.** Stage 4.2: 1/4 убыточных лет (vs 3/4 в Stage 4), но годовые PF (0.77–1.27) — шумные оценки без уверенной прибыльности.
7. **Текущий табличный кандидат закрыт как торговый.** Breach-классификатор добавляет реальный сигнал (~+0.20 PF), но его силы недостаточно. Дальше нужен новый исследовательский цикл: sequence-представление (Transformer) или пересмотр торговой постановки.

## Next Step

Stage 4.1 закрыл быстрые контрольные эксперименты из аудита:
- XGBoost-fav — rejected: PF хуже RF-fav на всех 4 SELL-таргетах.
- Combined breach H6 AND H12 — rejected: PF=1.065, `perm_p=0.050`, хуже Stage 4 winner.

Stage 4.2 диагностировал совокупный эффект исправленного протокола:
- Исправленный протокол: PF = 1.015 (было 1.106, Δ = −0.091 — совокупный эффект, не изолированное «завышение»).
- Breach-модель добавляет реальный сигнал для фиксированного правила (0/500 перестановок, консервативная оценка p ≈ 0.002, +0.20 PF над случайным).
- Но сигнал недостаточен для устойчивой прибыльности (gate > 1.15, исторический selection bias winner не исправлен).

Test не открывать: validation gate не пройден ни в одной конфигурации.

Следующий разумный путь — новый исследовательский цикл, а не донастройка Stage 4:

### A. Transformer encoder на фрактальной sequence
Фракталы — естественная последовательность (100 уровней × 10 каналов). Transformer может выжать сигнал из отношений между фракталами (ближний/дальний, плотность, кластеризация), который табличные модели не видят. **Методология — сразу чистая** (трёхслойный split, seed-устойчивость, годовые AUC/lift, проверка календарных признаков):

- **Stage 5.0 — модельный слой (без торговли):** breach-классификация. Сравнение с XGBoost на том же split. Gate: +100 bp mean AUC или значимый lift в low-risk зоне. Метрики: per-year AUC, lift на bottom-30% breach prob, seed-устойчивость (3 seed), calibration (reliability diagram), permutation importance time-фичей.
- **Stage 5.1 — торговый слой:** только если Stage 5.0 пройден. Методология: block bootstrap, permutation test для одного заранее зафиксированного target.

Риски:
- CHANGELOG (2026-05-21): Transformer на fractal features не дал direction-сигнала (но breach — бинарная задача, может сработать иначе)
- AUC 0.70–0.72 может не закрыть gap до PF > 1.15
- Долгая разработка (5–7 дней)

### B. Пересмотр торговой постановки
Если Transformer не даёт явного прироста, текущую схему `breach -> fav -> fixed TP/SL` нужно закрывать и формулировать новый таргет: прямой `trade_positive_flag`, `expected_pnl_val`, порядок касания TP/SL или trailing/partial exit.
