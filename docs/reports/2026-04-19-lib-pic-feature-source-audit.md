# lib_PIC Feature Source Audit

Дата: 2026-04-19  
Ветка: `lib-pic-feature-audit`

## Цель

Проверить `lib_PIC.mqh` как источник признаков для ML: что он уже считает, что экспортирует в `Nero.csv`, что реально использует Python, и где есть потери информации.

Это read-only аудит. Торговая логика `lib_PIC.mqh` в этом этапе не менялась.

## Проверенные факты

### Текущий формат `Nero.csv`

Файл `MT/MQL4/Files/Nero.csv` сейчас имеет формат:

```text
time;signal;predict;ATR;fractal0;...;fractal99
```

Каждый фрактал содержит 22 поля:

```text
T:P:Dir:Frnt:Back:Strong:Brk:Rev:Pwr:Cnt:Imp:Up12:Dn12:Up24:Dn24:Up48:Dn48:Up3:Dn3:Up6:Dn6:FractalAtr
```

Текущий файл в проекте определяется как ASCII text с CRLF. Старое описание `raw, UTF-16LE` для этого файла не соответствует фактическому файлу в репозитории.

### Что экспортирует `NERO_CSV_CREATE()`

| CSV idx | Поле | Источник MQL4 | Текущий смысл |
|---------|------|---------------|---------------|
| 0 | `T` | `F[f].T` | время формирования фрактала |
| 1 | `P` | `F[f].P` | цена уровня |
| 2 | `Dir` | `F[f].Dir` | направление уровня |
| 3 | `Frnt` | `F[f].FrntVal` | амплитуда переднего движения |
| 4 | `Back` | `F[f].BackVal` | амплитуда заднего движения |
| 5 | `Strong` | `F[f].Strong` | сильный/первый уровень |
| 6 | `Brk` | `F[f].Brk` | статус пробоя/касания |
| 7 | `Rev` | `F[f].Rev` | сила разворотного признака |
| 8 | `Pwr` | `F[f].PwrSum` | суммарная сила совпадающих уровней |
| 9 | `Cnt` | `F[f].Cnt` | количество совпадений уровня |
| 10 | `Imp` | `F[f].Imp` | импульс из пика |
| 11–16 | `Up12`...`Dn48` | `F[f].Up/Dn[H12/H24/H48]` | движение цены за длинные горизонты |
| 17–20 | `Up3`...`Dn6` | `F[f].Up/Dn[H3/H6]` | движение цены за короткие горизонты |
| 21 | `FractalAtr` | `F[f].Atr` | быстрый ATR в момент формирования фрактала |

### Что реально получает модель

`ML/data_loader.py` ожидает 22 поля, но формирует 20 входных признаков на фрактал:

```text
price, direction, front, back, strong, break,
reverse, power, count, impulse,
up_12, dn_12, up_24, dn_24, up_48, dn_48,
ATR_ratio, hour_sin, hour_cos, time_pos
```

Поля `Up3/Dn3/Up6/Dn6` не попадают в X как входные признаки. Они используются как целевые/служебные значения для коротких горизонтов.

`fractal_time` тоже не подаётся как сырое абсолютное время. Из него строятся `hour_sin`, `hour_cos`, `time_pos`.

### Что использовал текущий feature-bank

`ML/entry_path_feature_bank.py` строит сводки по окнам 5/10/20/50/100 только по 7 полям:

```text
direction, back, strong, break, power, count, impulse
```

Это полезный, но неполный слой. Он не использует цену, front, reverse, Up/Dn горизонты, ATR ratio и многие внутренние состояния `lib_PIC`.

## Потенциально потерянная информация

`head_PIC.mqh` показывает, что `PICS` содержит больше информации, чем экспортируется в `Nero.csv`.

Кандидаты на будущую проверку:

| Поле/группа | Сейчас экспортируется? | Комментарий |
|-------------|------------------------|-------------|
| `Tr`, `TrBrk`, `TrMid` | нет | состояние трендового уровня |
| `Mir` | нет | зеркальный уровень |
| `Near`, `NearVal` | нет | насколько близко цена подходила к уровню |
| `BackT`, `BrkT`, `ExT`, `Per` | нет | временная структура формирования/пробоя |
| `StrongImp` | нет | сильный отскок от уровня |
| `PwrImpCnt` | нет | агрегат силы, импульса и количества совпадений |
| `BarTch` | нет | касания уровня барами; в коде сейчас почти не задействован |
| `Flt` | нет | состояние флэта вокруг уровня |
| `Fls` | нет | состояние ложного пробоя |
| `TRG` | нет | треугольники, сейчас опциональная/отключенная область |
| `Trnd.Local/Global/Flat` | нет в строке фрактала | общий контекст рынка на текущем баре |

Вывод: перед переписыванием `lib_PIC` разумнее проверить, можно ли получить прирост от уже вычисляемых, но не экспортируемых состояний.

## Риски утечки будущего

Не все поля безопасны как входные признаки.

Предварительная классификация:

| Группа | Риск | Причина |
|--------|------|---------|
| Геометрия текущего уровня: `P`, `FrntVal`, `BackVal`, `Cnt`, `PwrSum`, `Imp`, `Atr` | низкий | уже используется или формируется на момент фрактала |
| `Near/NearVal`, `TrBrk`, `Flt`, `Fls` | средний | нужно доказать, что значение на момент строки не включает будущее относительно входа |
| `Up/Dn` горизонты | высокий как вход для той же задачи | это уже будущий ход цены; использовать как вход нельзя, если цель связана с будущим результатом сделки |
| Времена `BrkT`, `BackT`, `ExT`, `Per` | средний | безопасны только если момент обновления строго не позже текущей строки |

## Рекомендация

Следующий этап не должен начинаться с переписывания `lib_PIC`.

Более безопасный порядок:

1. Построить диагностику важности текущих признаков.
2. Разделить признаки на смысловые группы: геометрия уровня, сила, пробой, импульс, время, ATR, Up/Dn, сводки по окнам.
3. Проверить, какие группы реально влияют на validation/test benchmark.
4. Только после этого расширять `Nero.csv` безопасными внутренними состояниями `lib_PIC`.

Практический следующий шаг: `current-feature importance diagnostics` на уже существующих `DATA/Nero_*_labeled.csv`, без нового MT4-экспорта и без изменения `lib_PIC`.
