# Торгово-ориентированное исследование ML-сигналов по OHLC

> **Дата**: 2026-04-01
> **Статус**: Draft
> **Основа**: `API/signal_research.py`, `DATA/XAUUSD_H1_OHLC.csv`, `MT/MQL4/Files/ml_signals.csv`
> **Цель**: получить интерпретируемые торговые метрики для выбора логики `entry / SL / TP / hold` до модификации EA

---

## Контекст

На 2026-04-01 рабочая production-ветка использует `regression_updn` модель с 10 таргетами:

- `up_3`, `dn_3`, `up_6`, `dn_6`, `up_12`, `dn_12`, `up_24`, `dn_24`, `up_48`, `dn_48`
- текущее решение о входе по-прежнему строится вокруг `ratio_12`
- текущий `API/signal_research.py` уже считает MFE/MAE/Net, ratio-бакеты, корреляции и упрощённую сетку `SL/TP`

По текущему OOS-отчёту (`2603` BUY/SELL сигналов):

- на горизонте `12H` средний ход по сигналу `17.6`, против сигнала `16.8`, `PF=1.13`
- бакет `ratio_12 = 3-4` убыточен: `PF=0.87`
- бакет `ratio_12 = 4-5` лучший: `PF=1.95`
- `Filter3` и `Filter6` как directional ratio-фильтры почти бесполезны
- корреляция `prediction -> reality` слабая (`~0.13-0.21`)
- в упрощённой симуляции лучший фиксированный сет сейчас `SL=5`, `TP=30`, `PF=1.43`

Главный вывод из текущего состояния: проблема уже не в том, чтобы "ещё немного улучшить направление", а в том, чтобы понять, как именно монетизировать сигнал в торговой механике.

## Что должно ответить исследование

После расширения `signal_research.py` отчёт должен давать ответы на практические вопросы:

1. Есть ли смысл входить сразу по рынку, или типичен откат в первые `1/3/6` баров?
2. Какие `SL/TP` реально жизнеспособны при path-dependent проверке по H1 OHLC?
3. Полезны ли короткие горизонты `3H/6H` как амплитудный фильтр, даже если они бесполезны как ratio-фильтр?
4. Не смешиваем ли мы в одной статистике разные режимы, где сигнал работает по-разному?
5. Какие гипотезы надо будет уже проверять в варианте 3 через моделирование алгоритмов входа?

## Дизайн отчёта

### 1. Signal Passport

Расширение текущей таблицы по горизонтам.

Для каждого горизонта `H in {3, 6, 12, 24, 48}` выводить:

- `N`
- `MFE_mean`, `MFE_median`
- `MAE_mean`, `MAE_median`
- `Net_mean`, `Net_median`
- `MFE_p75`, `MFE_p90`
- `MAE_p75`, `MAE_p90`
- `MFE/MAE`
- `WinRate`
- `PF`

Назначение:

- быстро увидеть "сколько обычно проходит по сигналу" и "какой типичный откат"
- не опираться только на средние, которые искажаются хвостами

### 2. Pullback Profile

Новый блок для оценки качества входа.

Для каждого сигнала и окна `W in {1, 3, 6}` внутри базового горизонта `12H` считать:

- `fav_W`: максимальный ход в сторону сигнала за первые `W` баров
- `adv_W`: максимальный ход против сигнала за первые `W` баров
- `close_net_W`: направленный результат по `Close[t+W]`

Отдельно выводить:

- all signals
- `BUY`
- `SELL`
- бакеты `ratio_12`

В таблице показывать:

- `fav_mean`, `fav_median`
- `adv_mean`, `adv_median`
- `fav/adv`
- `%adv>=5`, `%adv>=10`, `%adv>=15`
- `%fav>=5`, `%fav>=10`, `%fav>=15`
- `%close_net_W > 0`

Назначение:

- понять, типичен ли откат сразу после сигнала
- оценить, насколько реалистичен `limit on pullback`
- увидеть, есть ли разница между BUY и SELL

### 3. First-Hit Barrier Matrix

Замена упрощённой симуляции `SL/TP`, которая сейчас не учитывает порядок достижения барьеров.

Для каждого сигнала, горизонта и пары `(SL, TP)` считать path-dependent исход:

- `TP_FIRST`
- `SL_FIRST`
- `NEITHER`

Определение:

- скан H1 OHLC bar-by-bar от `t+1` до `t+H`
- BUY:
  - если `High >= entry + TP` раньше `Low <= entry - SL` -> `TP_FIRST`
  - если `Low <= entry - SL` раньше `High >= entry + TP` -> `SL_FIRST`
- SELL аналогично
- если оба барьера внутри одного бара:
  - использовать расстояние от `Open` текущего бара до барьеров
  - ближний к `Open` барьер считается достигнутым первым
- если ни один барьер не достигнут -> `NEITHER`

Начальная сетка:

- горизонты: `6H`, `12H`, `24H`
- `SL`: `[5, 10, 15, 20, 30]`
- `TP`: `[5, 10, 15, 20, 30, 50]`

В таблице выводить:

- `N`
- `%TP_FIRST`
- `%SL_FIRST`
- `%NEITHER`
- `WinRate = TP_FIRST / N`
- `PF`
- `AvgPnL`
- `TotalPnL`

Правило PnL:

- `TP_FIRST -> +TP`
- `SL_FIRST -> -SL`
- `NEITHER -> Net_H`

Назначение:

- получить таблицу, непосредственно пригодную для выбора `SL/TP` в EA
- убрать искажение от path-independent приближений

### 4. Amplitude Filters

Новый блок вместо directional filter-идеи `ratio_3/ratio_6`.

Исследуем абсолютные значения коротких и средних предсказаний:

- для BUY: `up_3`, `up_6`, `up_12`, `dn_3`, `dn_6`
- для SELL: симметрично через "в сторону сигнала" и "против сигнала"

Подход:

- использовать унифицированные поля:
  - `pred_fav_3`, `pred_fav_6`, `pred_fav_12`
  - `pred_adv_3`, `pred_adv_6`
- строить бакеты по квантилям или фиксированным порогам

Первая версия использует квантили:

- low: `0-25%`
- mid: `25-75%`
- high: `75-100%`

Дополнительно для практики можно вывести fixed thresholds по самим значениям, если распределение окажется удобным.

Для каждого бакета считать:

- `N`
- `Net_12_mean`
- `PF_12`
- `%TP_FIRST`, `%SL_FIRST` для 1-2 лучших `SL/TP` сетов
- `MFE_12`, `MAE_12`

Назначение:

- проверить, полезны ли короткие горизонты как фильтр силы, а не направления
- найти признаки "сигнал сильный сразу" и "сигнал хороший, но с вероятным откатом"

### 5. Regime Split

Новый блок для разрезов статистики.

Первая версия должна поддерживать:

- `BUY` vs `SELL`
- `ratio_12` buckets: `[2,3)`, `[3,4)`, `[4,5)`, `[5,+inf)`
- `ATR` buckets по квартилям
- при необходимости `year` или `half-year`

Для каждого режима выводить укороченный набор:

- `N`
- `MFE_12_mean`
- `MAE_12_mean`
- `Net_12_mean`
- `PF_12`
- лучший `SL/TP` по `Barrier Matrix`

Назначение:

- отделить сигнал, который "в среднем хороший", от сигнала, который работает только в конкретном режиме
- не строить одну механику входа для смеси разных рынков

### 6. Practical Conclusions

В конце отчёта нужен короткий текстовый summary без попытки принимать решение за пользователя.

Формат выводов:

- `Entry:` что видно про мгновенный вход и ранний откат
- `SL/TP:` какие пары выглядят живыми по first-hit статистике
- `Filters:` какие фильтры стоит рассматривать дальше
- `Regimes:` где статистика заметно отличается
- `Next for Variant 3:` какие конкретные гипотезы теперь стоит симулировать

Назначение:

- чтобы после запуска отчёта можно было сразу перейти к обсуждению варианта 3

## Интерпретация результатов

После реализации варианта 2 должны появиться критерии для перехода к варианту 3.

### Признаки в пользу `limit entry`

- в первые `1/3` бара `adv_mean` заметно выше нуля
- значимая доля сигналов даёт откат, но потом восстанавливается в сторону сигнала
- `Barrier Matrix` показывает улучшение при меньшем риске входа

### Признаки в пользу `market entry`

- ранний adverse ход мал
- сильный `fav_1/fav_3` без обязательного отката
- лучшие результаты достигаются при входе без ожидания pullback

### Признаки в пользу amplitude filter

- high bucket по `pred_fav_3` или `pred_fav_6` даёт заметно лучший `PF`
- low bucket по `pred_adv_3` или `pred_adv_6` даёт ниже `SL_FIRST`

### Признаки в пользу regime-specific rules

- BUY и SELL сильно различаются
- отдельные ATR-режимы резко меняют `PF`
- лучший `SL/TP` различается между режимами
