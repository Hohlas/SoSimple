> **Дата**: 2026-04-02
> **Статус**: Draft
> **Основа**: `API/signal_research.py`, `DATA/XAUUSD_H1_OHLC.csv`, `MT/MQL4/Files/ml_signals.csv`, `MT/MQL4/Scripts/ExportOHLC.mq4`
> **Цель**: выделить `ex-ante` подгруппы сигналов с наилучшим торговым профилем и подготовить канонические входные данные для последующего `Variant 3` сравнения сценариев входа

---

## Контекст

`Signal Research Variant 2` уже завершён и дал важные практические выводы:

- текущий ML-сигнал даёт не сильный импульс, а слабый положительный drift;
- ранний adverse move после сигнала типичен;
- бакет `ratio_12 = 3-4` стабильно слабый;
- бакет `ratio_12 = 4-5` лучший;
- высокий текущий `ATR(14)` даёт лучший edge, чем спокойные режимы;
- `BUY` на текущем OOS сильнее `SELL`, но это может быть regime bias периода.

При этом остаются два нерешённых вопроса:

1. какие именно подгруппы сигналов реально имеют `tradable` edge, если смотреть только на признаки, известные в момент входа;
2. как убрать лишний рассинхрон между MT4 и Python при анализе волатильности.

Сейчас `signal_research.py` умеет считать `ATR(14)` в Python, но для долгосрочной стабильности лучше сделать `atr14` частью канонического OHLC-экспорта из MT4, чтобы исследовательские данные и торговая среда опирались на один и тот же источник.

---

## Что должен ответить этап

После завершения этого этапа должно быть понятно:

1. какие `ex-ante` когорты сигналов выглядят сильнее остальных;
2. есть ли у этих когорт профиль, который оправдывает `market`, `pullback`, `delayed` или `cancel-window` логику входа;
3. устойчивы ли лучшие когорты во времени, или их edge является артефактом конкретного куска рынка;
4. какие 3-5 когорт нужно брать в полноценный `Variant 3`, а какие стоит исключить заранее.

## Дизайн

### 1. Канонический ATR в OHLC CSV

### Требование

`MT/MQL4/Scripts/ExportOHLC.mq4` должен экспортировать:

```text
time;open;high;low;close;volume;atr14
```

Где:

- `atr14` — значение `ATR(14)` на H1-баре экспорта;
- источник ATR — MT4, а не пост-обработка в Python.

### Причина

- уменьшается риск расхождения между MT4 и Python;
- `signal_research.py` получает канонический volatility field из тех же данных, что и торговая среда;
- упрощается воспроизводимость future-исследований.

### Правило совместимости

- если в `DATA/XAUUSD_H1_OHLC.csv` есть колонка `atr14`, Python должен использовать её;
- если колонки нет, Python может временно досчитывать `ATR(14)` как fallback для старых файлов.

### 2. Cohort Map

Новый исследовательский блок должен строить таблицы не по одиночным сигналам, а по подгруппам, распознаваемым в момент входа.

### Обязательные срезы

1. `BUY/SELL × ratio_12`
2. `BUY/SELL × atr_bucket`
3. `ratio_12 × atr_bucket`
4. `ratio_12 × pred_fav_3 bucket`
5. `ratio_12 × pred_adv_3 bucket`

### Базовые бакеты

- `ratio_12`: `<2`, `2-3`, `3-4`, `4-5`, `5+`
- `atr_bucket`: квартильные бакеты `Q1..Q4`
- amplitude buckets: минимум `low / mid / high`

### Метрики по каждой когорте

- `N`
- `Net_12 mean`
- `Net_12 median`
- `PF_12`
- `MFE_12 mean`
- `MAE_12 mean`
- `TP_FIRST%`
- `SL_FIRST%`
- `NEITHER%`
- `AvgPnL` для базового сетапа `12H / SL=5 / TP=50`

### Назначение

- быстро понять, какие группы действительно сильнее;
- не смешивать в одной статистике разные рыночные режимы и разные типы сигналов;
- выбрать shortlist когорт для `Variant 3`.

---

### 3. Entry Opportunity Profile

Этот блок должен отвечать не на вопрос “хороший ли сигнал вообще”, а на вопрос “какой вход для него имеет смысл”.

### Для каждой ключевой когорты считать

- вероятность adverse move хотя бы на `3 / 5 / 8` пунктов;
- вероятность favorable move хотя бы на `10 / 20 / 30` пунктов;
- вероятность, что adverse move случился раньше favorable move;
- вероятность, что `pullback entry` вообще был бы исполнен в окно `1H / 3H / 6H`;
- результат по `close_net` после такого сценария.

### Цель

- отделить сигналы, где разумен `market entry`, от сигналов, где разумнее ждать откат;
- понять, в каких когортах есть смысл тестировать `delayed entry`;
- увидеть, где нужны окна отмены сигнала.

---

### 4. Stability Split

Лучшие когорты нужно проверять на устойчивость, а не только на aggregate OOS.

### Обязательные разрезы

- по годам или полугодиям;
- отдельно `BUY` и `SELL`;
- отдельно лучшие 3-5 когорт.

### Метрики

- `N`
- `PF_12`
- `Net_12 mean`
- `TP_FIRST%`
- `SL_FIRST%`

### Цель

- проверить, является ли найденный edge устойчивым;
- отделить рабочую когорту от regime artifact;
- понять, какие подгруппы не стоит переносить в EA без дополнительных ограничений.

---

### 5. Priority Cohorts

В конце отчёта должен появиться короткий shortlist:

### Best candidates

- 3-5 когорт, которые выглядят лучшими по сочетанию:
  - `PF`
  - `AvgPnL`
  - `N`
  - устойчивости по времени

### Anti-pattern cohorts

- когорты, которые стабильно плохи и не должны идти в `Variant 3` как приоритет:
  - минимум `ratio_12 = 3-4`;
  - при наличии подтверждения — другие слабые подгруппы.

---

### 6. Обязательные стартовые когорты

Даже если позже появятся дополнительные разрезы, в первой версии этапа обязательно сравнить:

- `ratio_12 = 3-4`
- `ratio_12 = 4-5`
- `ratio_12 = 5+`
- `ATR Q4`
- `non-Q4`
- `BUY`
- `SELL`

Отдельный приоритетный кандидат для анализа:

- `ratio_12 = 4-5 × ATR Q4`

---

### 7. Критерии успеха этапа

Этап считается успешным, если:

1. `XAUUSD_H1_OHLC.csv` получает каноническую колонку `atr14` из MT4-экспорта;
2. отчёт умеет выделять когорты по признакам, известным в момент входа;
3. для лучших когорт есть понятный shortlist для `Variant 3`;
4. для худших когорт есть аргументированное исключение из приоритетного тестирования;
5. следующий этап можно формулировать уже как прямое сравнение логик входа, а не как слепой перебор по всей выборке.

## Что делать дальше

После утверждения и реализации этого этапа следующим шагом должен стать уже полноценный `Variant 3` execution research:

- `market entry`
- `pullback limit entry`
- `delayed entry`
- `cancel-window`

Но сравнивать их нужно не по всем сигналам подряд, а на shortlist когорт, полученном здесь.
