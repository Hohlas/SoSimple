# Mutual Information Upper Bound Design

## Цель

Оценить фундаментальный предел предсказуемости XAUUSD H1 через mutual information (MI) между live-safe признаками и таргетами. MI даёт теоретический верхний предел R², который может достичь любая модель — без предположений о линейности, форме связи или классе модели.

Главный вопрос: текущие R² = 0.08-0.18 — это потолок (выше не подняться) или недостаток моделей (можно лучше)?

## Почему MI, а не корреляция

Pearson/Spearman измеряют линейную/монотонную связь. MI измеряет **любую** статистическую зависимость — линейную, нелинейную, немонотонную. Если MI = 0, никакая модель (линейная, дерево, нейросеть, ensemble) не может предсказать таргет лучше случайного.

Это не ограничение конкретной модели — это ограничение самой задачи, как скорость света в физике.

## Теоретическая основа

**Information Processing Inequality:**
```
I(features; target) >= I(model_output; target)
```
Никакая модель не может извлечь больше информации о таргете, чем содержится в признаках.

**Связь MI → R²:**
```
R² <= 1 - 2^(-2·I(features; target))
```

Обоснование: при фиксированной корреляции гауссово распределение минимизирует MI (экстремальное свойство гауссова распределения), и для гауссовой пары I = −½·log₂(1−R²). Следовательно, для любого распределения I ≥ −½·log₂(1−R²), откуда R² ≤ 1 − 2^(−2I).

Примеры:
- MI = 0.05 bits → max R² ≈ 0.067
- MI = 0.10 bits → max R² ≈ 0.129
- MI = 0.30 bits → max R² ≈ 0.340
- MI = 0.50 bits → max R² ≈ 0.500

Если текущие модели R² = 0.08-0.18, а MI ceiling ≈ 0.09 (MI = 0.07) — модели уже на пределе. Если MI ceiling ≈ 0.57 (MI = 0.40) — есть запас.

## Метод оценки

**kNN-оценщик KSG-типа** (Kraskov-Stögbauer-Grassberger, 2004; реализация sklearn по Ross, 2014):
- Non-parametric, не предполагает линейность или распределение
- Работает для непрерывных переменных
- Стандартный метод в литературе
- Реализация: `sklearn.feature_selection.mutual_info_regression` (непрерывный таргет) / `mutual_info_classif` (дискретный таргет) или `npeet`

Параметры (фиксируются до запуска):
- `n_neighbors` (k): 5 — основной; k = 10, 15 — robustness-проверка (не для выбора по результату)
- `random_state`: фиксированный для воспроизводимости
- Единицы MI: **bits**. sklearn возвращает MI в nats (натуральный логарифм); конверсия `I_bits = I_nats / ln(2)` выполняется внутри оценки. Формула R²-потолка `1 − 2^(−2I)` верна только для I в bits (без конверсии потолок занижается в ~1.4× и может оказаться ниже достижимой R²)
- Дискретные признаки: `session_hour` (23 уровня) и `weekday` (5 уровней) передаются оценщику с discrete-маской; остальные 40 признаков — continuous
- CI: разброс MI по непересекающимся временным фолдам (n_folds = 10) — метрика **стабильности по времени**, не статистический доверительный интервал; в вердикте PASS/FAIL не участвует. Row-bootstrap для kNN/KSG-оценщика неприменим — дубли строк раздувают оценку MI (проверено численно). Точечная оценка на полном объёме может лежать выше fold-CI — это ожидаемое следствие конечновыборочного смещения KSG (оценка на фолдах смещена сильнее), а не ошибка
- Permutation test (≥200 перестановок y): проверка H0 «MI = 0» — единственный критерий вердиктов PASS/FAIL

**Joint MI:** оценка I(X1..X42; Y) в 42-мерном пространстве ненадёжна при доступных объёмах данных. Основная метрика — среднее и максимум **маргинальных** MI (по одному признаку). Это не оценка joint MI; интерпретация R²-потолка из неё — диагностическая (см. Ограничения, п. 4).

## Таргеты для оценки

Все таргеты требуют ценовых колонок и строятся после джойна с `DATA/XAUUSD_H1_OHLC.csv` (см. Данные).

| ID | Target | Формула | Зачем |
|---|---|---|---|
| `T1_direction` | three-class direction | `sign(close[t+1] - open[t+1])`, домен {−1, 0, +1} | Основная цель прошлых моделей |
| `T2_amplitude` | absolute return | `|log(close[t+1] / open[t+1])|` | Amplitude устойчивее direction (ретроспектива 2.10) |
| `T3_amplitude_atr` | ATR-normalized amplitude | `|close[t+1] - open[t+1]| / ATR[t]` (колонка `ATR` labeled CSV) | Нормализованная амплитуда |
| `T4_multi_horizon` | amplitude на H3/H6/H12 | `|close[t+n] - open[t]|` для n=3,6,12 | Проверка горизонта |

T1 — дискретный таргет (оценивается `mutual_info_classif`), T2–T4 — непрерывные (`mutual_info_regression`).

**Домен T1 (факт, проверен):** `sign()` возвращает 0 при `close[t+1] == open[t+1]` — в train это 1590 строк из 41 362 (~3.84%). Таргет фактически трёхклассовый, класс 0 («нет движения») не удаляется; его доля фиксируется в disclosure. Сравнение с legacy-моделями (up/dn на горизонтах 12/24/48H) остаётся ориентировочным и по этой причине тоже.

## План анализа

### Шаг 1. MI для direction vs amplitude

Сравнить:
- `MI(features; direction)` — если ≈ 0, direction непредсказуем в принципе
- `MI(features; amplitude)` — если > MI(direction), amplitude действительно лучший таргет

Это количественная проверка вывода ретроспективы (2.10): "amplitude устойчивее direction".

### Шаг 2. MI по отдельным признакам

Каждый признак отдельно → понять, какие несут информацию:
- time (`session_hour`, `weekday`): MI = ?
- fractal aggregates (strong/break/back/impulse/power/count/direction_balance): MI = ?

Если `MI(time_features) >> MI(other_features)` — это количественное подтверждение time-only dominance (7.6).

### Шаг 3. Rolling MI (time-varying predictability)

```python
window = 500 bars  # ~2 месяца при плотности этого датасета (~246 баров/мес)
for t in range(window, len(data)):
    mi_t = mutual_info_regression(
        X[t-window:t], y[t-window:t]
    )
```

Rolling MI считается по **конкатенации train + validation + test** (2004–2026): только так видно поведение после 2022. Если MI падает после 2022 — это количественное подтверждение regime drift (6.3). Не «сигнал перестал работать», а «информация в признаках исчезла».

### Шаг 4. MI → R² ceiling

```python
result = estimate_mi(X, y)          # dict со средним/максимумом MI, CI, p-value
r2_ceiling = result['r2_ceiling']   # = 1 - 2**(-2 * mean_marginal_mi_bits)
```

Потолок считается из среднего/максимума маргинальных MI и носит диагностический характер (Ограничения, п. 4).

Сравнить с текущими R² = 0.08-0.18 — см. ограничения сравнения в Шаге 5.

### Шаг 5. Сравнение с текущими моделями

| Модель | Текущий R² | Источник | MI ceiling | Gap | Вывод |
|---|---|---|---|---|---|
| BiLSTM | 0.10 | ретроспектива, стр. 17 (r=0.32, горизонты 12/24/48H) | ? | ? | Ориентировочно |
| Transformer | 0.18 | ретроспектива, стр. 17 (r=0.43, up/dn, 12/24/48H) | ? | ? | Ориентировочно |
| baseline_clean | 0.084 | ретроспектива 2.5 (feature bank) | ? | ? | Ориентировочно |

**Ограничения сравнения (обязательно указывать в отчёте):**
1. Legacy-модели обучены на future-derived признаках — live-safe аудит всех 5 систем дал FAIL (ретроспектива 2.6). MI-потолок по live-safe признакам их не ограничивает; превышение R² над потолком не доказывает переобучение.
2. Горизонты legacy-моделей (12/24/48H) не совпадают с таргетами T1–T4 (t+1, H3/H6/H12).
3. Строгий вывод «потолок vs недостаток моделей» требует R² live-safe модели на том же таргете и горизонте.

## Критерии интерпретации

| MI значение | max R² | Вывод для SoSimple |
|-------------|--------|---------------------|
| < 0.01 bits | < 0.014 | Предсказуемость отсутствует. Проект нужно закрывать или менять инструмент/таймфрейм. |
| 0.01-0.05 bits | 0.014-0.067 | Предсказуемость минимальна. Потолок формально ниже legacy R² = 0.08, но сравнение ориентировочное (см. Шаг 5). |
| 0.05-0.15 bits | 0.067-0.188 | Низкая, но ненулевая. Amplitude tail (идея из research.md) может работать на хвосте распределения. |
| 0.15-0.30 bits | 0.188-0.340 | Умеренная. Текущие live-safe модели близко к пределу. Нужны лучшие признаки, не модели. |
| > 0.30 bits | > 0.340 | Существенная предсказуемость. Проблема в моделях, не в данных. Менять архитектуру. |

## Связь с другими идеями из research.md

- **Amplitude Tail Trading (идея 1):** если `MI(features; amplitude) > MI(features; direction)` — количественное подтверждение, что amplitude правильный таргет.
- **Regime-Gated Rules (идея 2):** если rolling MI падает после 2022 — regime detection необходим, потому что предсказуемость нестационарна.
- **Time-Effect Decomposition (идея 3):** если `MI(time_features) >> MI(other_features)` — time-only dominance подтверждён количественно.

## Ограничения метода

1. **Объём данных.** Train 44 159 строк (2004–2019), validation и test по 9 463 строки. Для маргинального MI этого достаточно; rolling-окно 500 строк даёт шумные оценки — интерпретировать как тренд, а не точные значения.
2. **MI не говорит, как извлечь информацию.** MI = 0.30 означает «можно», но не «как».
3. **Оценка MI — сама по себе нетривиальная задача.** Разные оценщики (KSG, kernel, binning) дают разные значения. Нужна кросс-валидация оценщиков.
4. **Joint MI по 42 признакам не оценивается.** Среднее/сумма маргинальных MI не являются ни оценкой joint MI, ни её общей верхней границей (возможна синергия). R²-потолок из маргинальных MI — диагностическая оценка, не строгая граница. Joint-оценка (например, npeet на пониженной размерности) — отдельное follow-up исследование.

## Stop Rules

Остановить анализ или пометить результат `INCONCLUSIVE`, если:
- MI ≈ 0 для всех признаков и таргетов (предсказуемость отсутствует)
- CI по временным фолдам слишком широкие (данных недостаточно)
- Rolling MI показывает полную нестабильность (режимы непредсказуемы)
- MI оценщик даёт систематические ошибки на синтетических данных
- Джойн с OHLC теряет существенную долю строк (>5% после дедупликации `time`) или OHLC содержит дубли `time`
