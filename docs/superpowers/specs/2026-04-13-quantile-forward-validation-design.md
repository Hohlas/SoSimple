# Quantile Forward Validation — Design Spec

> **Date**: 2026-04-13
> **Status**: Draft
> **Track**: Проверка устойчивости production `quantile`
> **Goal**: Дать operational verdict для текущего frozen `entry_path_v1_quantile` на новых данных без перенастройки правила

---

## 1. Context

Сейчас в проекте есть один подтверждённый сильный parallel mode:

- `entry_path_v1_quantile`
- production rule: `lb_gt_m_q35`
- frozen rule file: `ML/reports/entry_path_v1_quantile_selected_rule.json`

Также уже закрыты две соседние идеи:

- `quantile × fav_3_vs_12` как composition
- `fav_3_vs_12` как самостоятельный режим

Значит, следующий практический вопрос теперь другой:

- держится ли сам `quantile` на новых данных после production verdict.

Это не исследование нового фильтра.
Это проверка того, можно ли и дальше доверять уже выбранному режиму.

---

## 2. Main Idea

Этап должен быть полностью frozen:

- текущее правило не перенастраивается;
- пороги не меняются;
- новый winner не ищется;
- оценивается только поведение уже выбранного `quantile` на новых данных.

Итогом должен быть не просто отчёт, а operational verdict:

- `confirmed`
- `watch`
- `revisit`

---

## 3. Scope

### Входит в этап

- применение текущего frozen `quantile` rule к новым данным;
- расчёт `trades`, `PF`, `win_rate`, `mean_pnl_atr`;
- временная разбивка новых данных;
- сравнение с уже зафиксированным историческим уровнем качества;
- operational verdict.

### Не входит в этап

- новый search по правилам;
- новый quantile sweep;
- новый seed selection;
- composition с другими фильтрами;
- изменение MT4-логики;
- execution improvement;
- переобучение моделей.

---

## 4. Success Principle

Главный вопрос этапа:

- жив ли edge у текущего `quantile`.

Главный приоритет:

- просадка `PF` важнее, чем отдельные слабые временные куски.

Это значит:

- если общий `PF` остаётся рабочим, единичные слабые куски сами по себе не обязаны ломать verdict;
- если `PF` заметно проседает, это главный тревожный сигнал.

---

## 5. Data Design

Для проверки должны использоваться только новые данные после последней точки решения по `quantile`.

Смысл этапа:

- не повторять старые validation/test;
- а смотреть именно на следующий по времени кусок.

Временное окно должно быть зафиксировано явно:

- дата начала;
- дата конца;
- число сигналов;
- число прошедших сделок.

Если данных пока слишком мало, это должно быть явно отражено в verdict.

---

## 6. Evaluation Design

Должны считаться:

- `trades`
- `PF`
- `win_rate`
- `mean_pnl_atr`
- временная разбивка

Временная разбивка должна быть достаточно крупной, чтобы не ловить шум.

Если данных ещё мало для годовой разбивки, допустима разбивка по более крупным блокам:

- например по кварталам;
- или по rolling-окнам;
- но выбор должен быть один и зафиксирован в отчёте.

---

## 7. Operational Verdict Design

### 7.1. `confirmed`

Статус `confirmed` означает:

- текущий `quantile` сохраняет рабочий `PF`;
- число сделок не выглядит аномально малым;
- нет признака явного распада режима.

### 7.2. `watch`

Статус `watch` означает:

- режим ещё не сломан явно;
- но есть признаки ослабления:
  - `PF` заметно хуже historical уровня;
  - support пока малый;
  - есть слабые временные куски;
  - вывод ещё рано считать окончательным.

Это не запрет на использование, а сигнал, что режим нужно наблюдать дальше.

### 7.3. `revisit`

Статус `revisit` означает:

- текущий `quantile` уже нельзя считать достаточно подтверждённым;
- `PF` просел слишком сильно или edge исчез;
- нужен пересмотр режима, а не просто дальнейшее наблюдение.

---

## 8. Failure Signals

Признаки плохого исхода:

- сильная просадка `PF`;
- слишком малое число `trades` для внятного вывода;
- повторяющиеся слабые временные куски;
- явный разрыв с историческим уровнем качества.

---

## 9. Deliverables

Итог этапа должен дать:

- frozen forward-validation benchmark;
- таблицу с ключевыми метриками;
- временную разбивку;
- operational verdict:
  - `confirmed`
  - `watch`
  - или `revisit`
- краткое практическое решение:
  - продолжать использовать как есть;
  - использовать под наблюдением;
  - или готовить пересмотр.

---

## 10. Decision Rule

После этапа должен быть дан простой ответ:

Можно ли и дальше доверять текущему frozen `quantile` без изменений?

Возможны только три честных исхода:

- да, режим подтверждён;
- пока да, но режим под наблюдением;
- нет, режим требует пересмотра.
