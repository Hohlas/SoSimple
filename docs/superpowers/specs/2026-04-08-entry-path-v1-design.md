# Entry Path v1 — Design Spec

> **Date**: 2026-04-08
> **Status**: Draft
> **Track**: Параллельный (не заменяет `regression_updn` и `triple_barrier`)
> **Goal**: Построить новый ML-трек, который оценивает силу идеи после реального входа на следующем баре и отдельно описывает путь цены, без жёсткой привязки к одному SL/TP или одному способу выхода

---

## 1. Context

В проекте уже есть два важных вывода:

1. Старый `regression_updn` плохо переносится в торговую систему, если оценка в Python опирается на слишком удобные для модели величины.
2. `triple_barrier` лучше связан со сделкой, но слишком жёстко привязывает обучение к конкретной сетке SL/TP.

Новый трек должен занять середину между этими двумя крайностями.

Он должен:

- смотреть на реальный вход с `Open[t+1]`;
- оценивать общую полезность идеи на нескольких горизонтах;
- отдельно описывать путь цены после входа;
- не вшивать внутрь модели конкретные trailing / pullback / reversal правила;
- оставлять право слою стратегии в EA докручивать сопровождение сделки.

---

## 2. Main Idea

`Entry Path v1` состоит из двух частей:

1. **Главная группа таргетов** отвечает на вопрос: была ли идея полезной после реального входа на следующем баре.
2. **Вспомогательная группа таргетов** отвечает на вопрос: как именно шла цена после входа.

Отдельно поверх прогнозов этого трека позже может быть добавлен `conformal prediction` слой для решения `trade / no-trade`.

`Conformal prediction` в этом дизайне не используется для размера позиции. Размер позиции остаётся обычным правилом риска вне ML.

---

## 3. Scope

### Входит в `v1`

- новая разметка таргетов в `processing`
- новый ML-трек `entry_path_v1`
- обучение на наборе новых таргетов
- отчёты по качеству прогноза
- подготовка слоя для будущего `trade / no-trade`

### Не входит в `v1`

- замена текущего `regression_updn`
- замена текущего `triple_barrier`
- подбор конкретных SL/TP для EA
- подбор trailing
- подбор pullback входа
- размер позиции
- полный перенос нового трека в MT4 на этом же этапе

---

## 4. Design Principles

### 4.1. Реальный вход

Все новые таргеты считаются от `Open[t+1]`, а не от текущего закрытия и не от внутренних времён фрактала.

### 4.2. Несколько горизонтов вместо одного

Главная ошибка дизайна с одним итоговым таргетом в том, что он слишком жёстко пришивает модель к одному времени выхода. Поэтому главный сигнал должен оцениваться хотя бы на трёх горизонтах.

### 4.3. Путь цены отделён от общей пользы идеи

`fav/adv` полезны для понимания поведения цены, но их нельзя делать единственной целью модели. Они хорошо работают как вспомогательные таргеты.

### 4.4. MT4 и Python должны говорить про одну и ту же сделку

Новый трек не должен повторять ошибку старых слишком удобных таргетов. Поэтому все формулы строятся только из цен, доступных после сигнала, и от реальной точки входа.

---

## 5. Target Set

### 5.1. Главная группа таргетов

Три регрессионных таргета:

- `ret_6_dir_atr`
- `ret_12_dir_atr`
- `ret_24_dir_atr`

Формула для горизонта `h`:

```text
ret_h_dir_atr = dir * (Close[t+h] - Open[t+1]) / ATR[t]
```

Где:

- `dir = +1` для BUY
- `dir = -1` для SELL
- `ATR[t]` — ATR строки сигнала

Смысл:

- положительное значение значит, что идея в среднем шла в нужную сторону;
- отрицательное значение значит, что идея на этом горизонте была плохой.

Почему именно эти три таргета:

- `6` баров показывает ранний итог;
- `12` баров даёт средний рабочий горизонт;
- `24` бара показывает более длинную реализацию идеи.

### 5.2. Вспомогательная группа таргетов пути цены

Регрессионные таргеты:

- `fav_6_atr`, `fav_12_atr`, `fav_24_atr`
- `adv_6_atr`, `adv_12_atr`, `adv_24_atr`

Для BUY:

```text
fav_h_atr = (max High[t+1..t+h] - Open[t+1]) / ATR[t]
adv_h_atr = (Open[t+1] - min Low[t+1..t+h]) / ATR[t]
```

Для SELL:

```text
fav_h_atr = (Open[t+1] - min Low[t+1..t+h]) / ATR[t]
adv_h_atr = (max High[t+1..t+h] - Open[t+1]) / ATR[t]
```

Смысл:

- `fav` — лучший ход в прибыльную сторону;
- `adv` — худший ход против позиции.

Зачем они нужны:

- для анализа формы движения;
- для будущего выбора SL/TP и trailing;
- как вспомогательные задачи совместного обучения.

### 5.3. Ранний классификационный таргет

Один трёхклассовый таргет:

- `path_6_class`

Значения:

- `+1` — раньше достигнут уровень `+1 ATR`
- `0` — за `6` баров не достигнут ни `+1 ATR`, ни `-1 ATR`
- `-1` — раньше достигнут уровень `-1 ATR`

Смысл:

- грубая и понятная оценка раннего качества входа.

Правило расчёта:

- класс задаётся по реальному первому касанию в окне `6` баров;
- используется тот же принцип упорядочивания по пути цены, который уже был нужен для честной TB-разметки;
- если в одном и том же окне достигаются обе стороны, берётся то, что произошло раньше по пути цены.

### 5.4. Исследовательские колонки, но не для первого обучения

В разметку стоит добавить:

- `fav_3_atr`
- `adv_3_atr`

Но в первый обучаемый набор `v1` они не входят.

Причина:

- горизонт `3` часа слишком шумный для первого прохода;
- эти колонки полезны для анализа, но пока не нужны в основной модели.

---

## 6. Final v1 Training Set

В первый обучаемый набор входят 10 таргетов:

### Главные

- `ret_6_dir_atr`
- `ret_12_dir_atr`
- `ret_24_dir_atr`

### Вспомогательные

- `fav_6_atr`
- `adv_6_atr`
- `fav_12_atr`
- `adv_12_atr`
- `fav_24_atr`
- `adv_24_atr`
- `path_6_class`

Логика выбора:

- главная группа отвечает за общую полезность идеи;
- вспомогательная группа учит модель понимать путь цены;
- набор ещё достаточно мал, чтобы не расползтись по сложности.

---

## 7. Labeling Rules

### 7.1. Общие правила

- Все новые таргеты считаются после формирования строки сигнала.
- Точка входа всегда `Open[t+1]`.
- Для строк около конца датасета, где не хватает будущих баров, таргеты не создаются или строка отбрасывается по тем же правилам, что и для остальных horizon-based таргетов.

### 7.2. Направление

Направление берётся из уже существующего сигнала строки:

- `signal = 1` → BUY
- `signal = -1` → SELL

Если строка не несёт торгового направления, она не участвует в новом треке.

### 7.3. Нормализация

Все новые числовые таргеты хранятся в ATR-единицах.

Это нужно, чтобы:

- не смешивать периоды разной волатильности;
- сохранить сопоставимость между разными годами;
- не возвращаться к сырым ценам при сравнении разных режимов рынка.

---

## 8. Model Design

### 8.1. Тип задачи

`Entry Path v1` — это multi-task модель:

- 9 числовых таргетов;
- 1 трёхклассовый таргет.

### 8.2. Предпочтительная архитектура

Для первого запуска лучше переиспользовать текущий `transformer` backbone.

Рекомендуемая голова модели:

- один общий encoder;
- одна регрессионная голова для 9 числовых таргетов;
- одна классификационная голова для `path_6_class`.

### 8.3. Loss

Рекомендуемая схема:

- для числовых таргетов: `HuberLoss` или `MSELoss`
- для `path_6_class`: `CrossEntropyLoss`
- итоговый loss: взвешенная сумма

Рекомендация для `v1`:

```text
total_loss = 1.0 * loss_ret
           + 0.5 * loss_path_reg
           + 0.5 * loss_path_cls
```

Где:

- `loss_ret` — средний loss по `ret_6/12/24`
- `loss_path_reg` — средний loss по `fav/adv`
- `loss_path_cls` — loss по `path_6_class`

Причина:

- главная группа должна иметь больший вес, чем вспомогательная.

---

## 9. Evaluation

### 9.1. Что считать главным результатом

Главный результат трека — не PF сам по себе, а качество прогноза по главным таргетам:

- correlation / rank-correlation для `ret_6/12/24`
- ошибка регрессии
- качество классификации для `path_6_class`

### 9.2. Что считать прикладным результатом

После обучения модель должна позволять ответить на такие вопросы:

- если прогноз по `ret_24_dir_atr` высокий, растёт ли реальная полезность идеи;
- если `fav_12_atr` высокий, можно ли строить более уверенные TP;
- если `adv_6_atr` высокий, стоит ли избегать такого типа входа;
- если `path_6_class = -1`, ухудшается ли раннее качество сделки.

### 9.3. Чего не делать на первом этапе

На первом этапе не нужно сразу считать “готовый PF новой системы” как окончательный результат нового трека.

Причина:

- сначала надо проверить, что сами таргеты действительно несут полезную структуру;
- уже потом поверх них строить слой `trade / no-trade` и торговые правила.

---

## 10. Conformal Prediction Layer

`Conformal prediction` в этом дизайне используется только для `trade / no-trade`.

### Предлагаемая логика

Базовая идея для первого эксперимента:

- прогнозируется `ret_24_dir_atr`;
- на validation строится conformal-слой;
- сделка пропускается, если нижняя граница для ожидаемого результата `<= 0`.

Важная оговорка:

- для временного ряда не нужно считать conformal prediction “магической гарантией”;
- в проекте его надо использовать только в последовательной схеме `train -> validation -> test` или в rolling-схеме, без заявлений о строгой универсальной гарантии на любых данных.

Это не часть первого этапа разметки и обучения. Это следующий слой поверх прогнозов модели.

### Почему не использовать conformal для размера позиции

- размер позиции в проекте уже определяется простым процентом от депозита;
- conformal полезнее использовать как фильтр на вход, а не как замену money management.

## 11. Implementation Boundaries

### Что нужно изменить

- `processing/label_signals.py`
  - добавить новые колонки `ret_*`, `fav_*`, `adv_*`, `path_6_class`
- `processing/label_main.py`
  - встроить новые таргеты в общий pipeline
- `ML/data_loader.py`
  - добавить новый target mode `entry_path_v1`
- `ML/train.py`
  - добавить новый task с multi-task loss
- `ML/evaluate_test.py`
  - добавить отчёт для нового трека
- `API/generate_signals.py`
  - пока не выпускать финальный MT4 CSV, а ограничиться исследовательским выводом и отчётами

### Что пока не менять

- MQL4-торговую логику
- размер позиции
- старые track-specific CSV для MT4
- `triple_barrier` и `regression_updn`

---

## 12. Success Criteria

Этап можно считать удачным, если выполняются все условия:

1. Новый датасет собирается без сдвигов времени.
2. Модель стабильно обучается на новом наборе таргетов.
3. Главные таргеты `ret_6/12/24` показывают полезную предсказательную силу на test.
4. Вспомогательные таргеты `fav/adv/path_6_class` дают понятную структуру пути цены.
5. Появляется осмысленная основа для следующего слоя `trade / no-trade`.

---

## 13. Risks / Open Questions

- Может оказаться, что `ret_24_dir_atr` всё ещё слишком зависит от выбранного горизонта.
- `fav/adv` могут улучшать обучение не всегда; это нужно проверять на реальных результатах.
- `path_6_class` может оказаться слишком грубым или слишком шумным.
- SELL-часть может снова быть заметно слабее BUY-части.
- Возможно, позже понадобится `v2`, где `ret_6/12/24` будут заменены на более устойчивый состав горизонтов.

---

## 14. Recommendation

Для проекта рекомендуется идти именно через `Entry Path v1`, а не через новый TB-grid.

Причины:

- этот подход лучше отделяет ML от торговой механики EA;
- он сохраняет связь с реальным входом;
- он даёт материал и для стратегии, и для будущего `trade / no-trade` слоя;
- он не мешает держать `triple_barrier` как отдельный трек сравнения.
