# Дизайн: относительная стоимость пар (статистический арбитраж) — убивающий тест

Дата: 2026-08-17. Ветка: `feature/idea-01-pair-spread`.
Источник: пункт 1 роэдмэпа `docs/audit/best_ideas.md`.
Статус: RESEARCH_ONLY / DIAGNOSTIC_ONLY — кандидат в диагностику конверсии (правило 4 роэдмэпа), не в торговлю до прохождения kill-теста.

## 1. Цель

Проверить гипотезу класса: торгуется ли разрыв спреда двух коррелированных пар
без предсказания направления? Гипотеза атакует главную стену проекта — отсутствие
знака в признаках (2.1, MI direction FAIL): целевой переменной служит относительный
знак двух ног, который проект никогда не проверял.

Результат в любом случае закрывает вопрос класса: либо пары дают конверсию в
прибыль после издержек, либо тема убита предрегистрированными критериями.

## 2. Структура: две ступени

- **Ступень 1 — скрининг** (только train): статистика расхождений и покрытие
  издержек, пороговый отбор без ML.
- **Ступень 2 — kill-тест** (только test): примитивная z-score mean-reversion,
  PF с bootstrap CI.

Без ML по решению обсуждения. ML-модели — вне скоупа.

## 3. Данные

### 3.1 Инструменты

| Роль | Инструменты | Источник |
|---|---|---|
| Скачать из MT5 (M5) | AUDUSD, NZDUSD, USDCAD | история MT5, с 2005 |
| Уже локально (есть H1; догрузить M5 с 2005) | EURUSD, GBPUSD, USDCHF, XAUUSD, XAGUSD | существующие `*_H1_OHLC.csv` в `MT/MQL4/Files/` + догрузка M5 из MT5 |

Общий старт всей корзины — 2005-01-01 (ранние EURUSD-данные до ~2000 выглядят
нерыночными; единая дата старта для всех). Конец данных — текущий момент экспорта
(ориентир 2026-04+).

### 3.2 Синтетические кроссы (7 кандидатов)

- AUD/NZD = AUDUSD / NZDUSD
- AUD/CAD = AUDUSD × USDCAD
- NZD/CAD = NZDUSD × USDCAD
- EUR/GBP = EURUSD / GBPUSD
- EUR/CHF = EURUSD × USDCHF
- GBP/CHF = GBPUSD × USDCHF
- XAU/XAG = XAUUSD / XAGUSD

### 3.3 Таймфреймы

- **M5 — основной**: честная мера длительности и амплитуды расхождений; задержка
  входа «следующий бар» = 5 минут; укладывается в ограничение роэдмэпа (решения M5+).
- **H1 — контрольный срез**: скрининг дублируется на H1; расхождение вердиктов
  M5/H1 по одной паре — красный флаг нестабильности.
- Если ступень 1 покажет, что большинство эпизодов возвращается быстрее 5 минут:
  отдельный следующий шаг — тиковая диагностика длительности и амплитуды (правило 7
  роэдмэпа разрешает тики для симуляции исполнения и диагностик). В этом этапе не делается.

### 3.4 Темпоральный сплит

- train: 2005-01-01 … 2022-12-31 (скрининг, оценка β, порогов, издержек);
- test: 2023-01-01 … конец данных (kill-тест, строго OOS).
- Validation как отдельная роль не вводится; статус результатов явно понижается
  до RESEARCH_ONLY (методология 09).
- Сплит фиксируется в этом документе до первого запуска.

## 4. Определение спреда

- Спред: `s_t = ln(A_t) − β · ln(B_t)` по ценам close (mid-конвенция).
- β — одна OLS-оценка на всём train, замораживается; не роллинг. Устойчивость β
  между половинами train — диагностическая метрика, не условие отбора.
- Ценовая конвенция (методология 12, урок 2.12): OHLC трактуется как mid;
  спред каждой ноги применяется как неблагоприятный сдвиг при входе и выходе.
  Вход и выход — на открытии следующего бара после сигнала; внутрибаровые
  допущения о fill запрещены.

## 5. Ступень 1 — скрининг (train, предрегистрированные пороги)

Метрики по каждому из 7 кандидатов:

1. **Коинтеграция**: ADF-тест остатков спреда (β из train). Порог: p ≤ 0.05.
2. **Полураспад возврата** (OU-оценка по авторегрессии остатков): рабочий
   диапазон от ~30 минут (6 баров M5) до ~10 суток (2880 баров M5).
   Быстрее — не исполняется на M5-решениях; медленнее — капитал заперт, своп съест профит.
3. **Запас после издержек**: round-trip стоимость раунда
   `c = 2 × (спред ноги A + спред ноги B)` в единицах спреда.
   Убивает (критерий роэдмэпа): `c > P75(|s − mean|)` на train.
   Дополнительно: медианное |отклонение| внутри эпизодов |z| ≥ 2 должно
   превышать `c` (иначе вход по сигналу в среднем не окупает раунд).
4. **Частота расхождений**: число эпизодов |z| ≥ 2 в год на train. Порог: ≥ 5/год.

Пара проходит, только если прошла все четыре порога. Прошедших может быть 0–7.
Отчёт показывает таблицу метрик по всем 7, включая убитые.

Диагностика структурного слома: отдельный тест связи EUR/CHF вокруг января 2015
(снятие пола SNB) — иллюстрация главного риска парного трейдинга.

Дополнительный вывод скрининга: распределение длительности эпизодов (от выхода
за порог до половины возврата) — ответ на вопрос, краткосрочный ли процесс.

## 6. Ступень 2 — kill-тест (test, правила заморожены до запуска)

Для каждой пары, прошедшей ступень 1:

- **Вход**: z-score спреда относительно train-среднего и train-σ; |z| ≥ 2.
  Спред завышен — short ноги A / long ноги B; занижен — наоборот.
- **Выход** (первое из): пересечение z = 0; таймаут 10 суток (2880 баров M5);
  стоп при |z| ≥ 4 (защита от структурного слома).
- **Исполнение**: открытие следующего бара; издержки по спецификации MT5
  (снимок спредов счёта) + обязательный стресс 2x; конвенция цен секции 4.
- **Вердикт по роэдмэпу**:
  - проходит: PF ≥ 1.3 и нижняя граница bootstrap CI > 1.0 (net, после издержек);
  - убита: PF < 1.3 или нижняя CI ≤ 1.0;
  - убита независимо от PF: ADF спреда на test p > 0.10.
- **Гейт размера выборки**: сделок < 30 → вердикт не выше DIAGNOSTIC_ONLY
  (методология 06).

## 7. Издержки

- Источник: спецификация инструментов MT5 (текущие спреды по каждой паре и ноге).
- Ограничение источника: один спред-снимок не отражает ночные расширения и
  всплески; компенсируется обязательным стрессом 2x.
- Своп: пренебрежим при hold до 10 суток, проверяется в отчёте по фактическим
  длительностям сделок; при существенном влиянии — вычитается отдельно
  (по аналогии с правилом для кэрри в п. 13 роэдмэпа).
- Известный риск быстрого исполнения: 5 секунд исполнения на 30-секундном окне —
  впритык; телеметрия MT5 проекта (2.13) показывала реквоты (ERROR-138) и
  OPEN_FAILED. Фиксируется как ограничение; решение о более быстром исполнении
  принимается только если тиковая диагностика покажет амплитуду, покрывающую
  издержки.

## 8. Артефакты и код

- Данные M5 из MT5: `MT/MQL4/Files/M5/` (формат как у существующих OHLC CSV).
- Генерируемые спреды и кроссы: `DATA/pair_spread/`.
- Код: `statistics/pair_spread/` — три части: (1) загрузка/сборка кроссов и
  спредов; (2) скрининг; (3) примитивный бэктестер z-score правила с bootstrap CI.
  Части с чистыми интерфейсами, тестируются отдельно.
- Тесты: `tests/test_pair_spread*.py` — математика кроссов, z-score, модель
  издержек, хронология входа «следующий бар».
- Отчёт этапа: `docs/reports/2026-08-…-pair-spread.md` — таблица метрик
  скрининга по всем 7 парам (включая убитые), вердикты ступени 2 по парам,
  распределение длительности эпизодов, стресс издержек 2x, сверка M5/H1.
  Вердикты: KILLED / SURVIVED по каждой паре; DIAGNOSTIC_ONLY при N сделок < 30.

## 9. Предрегистрация и честность

- Все пороги ступени 1 и правила ступени 2 зафиксированы этим документом до
  первого запуска. Изменение после просмотра результатов — только отдельным
  документированным решением (прецеденты автовыбора 2.4, 2.12 убили кандидатов
  именно через подглядывание).
- Выбор пар — пороговый, не топ-N и не ручной: отбираются все пары, прошедшие
  пороги на train; подтверждение — на test, не участвовавшем в отборе.

## 10. Вне скоупа

- ML-модели и предсказание возврата спреда.
- Оптимизация порогов входа/выхода после просмотра результатов.
- Торговля на реальном счёте.
- Тиковая диагностика (следующий шаг только при коротких эпизодах на M5).
- JPY-кроссы и расширение корзины за пределы 7 кандидатов.
