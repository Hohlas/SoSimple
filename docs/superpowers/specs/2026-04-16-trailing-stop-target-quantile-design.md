# Trailing Stop Target Quantile Design

> **Date**: 2026-04-16
> **Status**: Draft
> **Track**: Следующая bounded-ветка после `trailing_stop_target_v1`
> **Goal**: Проверить, поможет ли квантильная постановка для trailing-stop target-а найти хотя бы один validation-candidate с `PF > 1`
> **Related materials**: `docs/reports/2026-04-16-trailing-stop-target-first-wave.md`, `docs/reports/2026-04-12-quantile-status-decision.md`, `docs/superpowers/specs/2026-04-16-trailing-stop-target-design.md`

## Context

Первая волна `trailing_stop_target_v1` дала полезный отрицательный результат:

- path-dependent target оказался обучаемым;
- лучшая конфигурация была `seq_len=20`;
- лучший target family был `trail_48_pnl_atr_x3`;
- но ни один candidate не дошёл даже до `PF > 1` на `validation`.

Это значит, что полный новый sweep по `X = 2 / 3 / 5` и `seq_len = 20 / 50 / 100` повторять сейчас не нужно. Следующий шаг должен быть уже не “ещё одна обычная регрессия”, а более точечная проверка: может ли квантильная постановка извлечь из того же target-а полезную нижнюю границу результата сделки.

Ключевая идея взята из уже подтверждённого `entry_path_v1_quantile`: для торговли часто важнее не средняя оценка сделки, а оценка того, насколько плохим может оказаться результат в неблагоприятном, но не экстремальном случае.

## Main Idea

Новый трек не меняет сам target. Он меняет только способ обучения.

Базовый target остаётся:

- `trail_48_pnl_atr_x3`

Модель вместо одного числа должна предсказывать три оценки этого же результата:

- `q10` — нижняя оценка,
- `q50` — центральная оценка,
- `q90` — верхняя оценка.

Практический смысл:

- `q10` отвечает на вопрос “насколько плохим может быть результат в осторожном сценарии”;
- `q50` даёт центральную оценку;
- `q90` показывает более оптимистичную часть распределения.

Эта схема лучше подходит для торгового отбора, чем обычная регрессия на среднее значение.

## Scope Boundary

Этот этап должен оставаться жёстко ограниченным.

Фиксируется:

- только `trail_48_pnl_atr_x3`,
- только `seq_len = 20`,
- только одна quantile-модель,
- без sweep по нескольким архитектурам,
- без повторного перебора `X = 2 / 3 / 5`,
- без нового matrix по `20 / 50 / 100`.

Причина:

- в первой волне уже видно, что `x3` и `seq20` были лучшей комбинацией;
- сначала нужно понять, даёт ли сама квантильная постановка качественный сдвиг;
- если сразу снова расширить пространство поиска, результат станет трудно интерпретировать.

## Target Contract

### Base Target

Целевая переменная:

- `trail_48_pnl_atr_x3`

Она уже определена и не пересматривается на этом этапе.

### Quantile Outputs

Модель должна выдавать три числа на каждую строку:

- `pred_trail_48_pnl_atr_x3_q10`
- `pred_trail_48_pnl_atr_x3_q50`
- `pred_trail_48_pnl_atr_x3_q90`

Требования к контракту:

- `q10 <= q50 <= q90`
- export должен сохранять эти три прогноза и true-target
- benchmark должен работать только по этим полям, без опоры на старые `entry_path` головы

Если ordering quantile-ов нарушается, это должно исправляться на уровне выхода модели или post-processing export-а.

## Model Design

Первый проход использует одну архитектурную линию:

- тот же transformer-класс, который уже использовался для `trailing_stop_target_v1`

Но выходная голова и loss меняются:

- одна общая sequence encoder часть,
- три выходных значения вместо одного,
- quantile loss для `q10 / q50 / q90`.

Новый трек не требует `dual_stream` и не требует отдельной сложной архитектуры. На этом этапе важно проверить именно objective, а не смешивать objective-change и architecture-change.

## Training Policy

Обучение делается только для одного bounded run:

- task: `trailing_stop_target_quantile_v1`
- target family: `trail_48_pnl_atr_x3`
- `seq_len = 20`
- одна модель
- один seed на первом проходе

Это deliberately маленький этап.

Success criterion не в том, чтобы сразу построить production-ready систему, а в том, чтобы ответить на один вопрос:

- даёт ли quantile-формулировка рабочую зону лучше, чем обычная регрессия на том же target-е?

## Selection Layer

Selection layer тоже должен оставаться коротким.

### Primary Candidates

Основные candidate families:

- `q10 > 0`
- `q10 > m`, где `m` подбирается на `validation`
- `q10 > 0` и `q50 > 0`

Это базовые, понятные и экономически интерпретируемые правила:

- брать сделки только когда нижняя оценка уже положительна;
- либо когда нижняя оценка выше небольшого safety-margin;
- либо когда положительны и нижняя, и центральная оценки.

### Secondary Candidate

Допустим один secondary candidate:

- `q10 / (abs(q90 - q10) + eps)`

Смысл:

- отдавать предпочтение сделкам, где нижняя граница высока, а разброс между осторожным и оптимистичным сценарием не слишком велик.

Но это должен быть именно вторичный кандидат, а не центр benchmark-а.

### What We Avoid

На этом этапе не делаются:

- большие families из десятков формул,
- возврат к `path6`-подобной логике,
- смешивание нового quantile-трека с прежними `entry_path_v1` score-ами.

## Evaluation Policy

Оценка остаётся двухслойной.

### 1. Quantile Diagnostics

Вспомогательные метрики:

- pinball loss по каждому quantile,
- MAE для `q50`,
- проверка доли нарушений порядка `q10 <= q50 <= q90`,
- корреляция `q50` с true target как вторичная диагностика.

Эти метрики нужны для контроля качества модели, но не выбирают winner сами по себе.

### 2. Validation-First Trading Benchmark

Главный выбор идёт через validation benchmark.

Обязательные метрики:

- `PF`
- `trades_per_year`
- `negative_year_slices`
- `profit_concentration_top_10`, если доступен в текущем benchmark stack
- `ulcer_index`
- `max_drawdown_atr`, если доступен без нового сложного scaffolding

Правило выбора:

- winner выбирается только на `validation`
- `test` открывается только для validation winner
- если кандидатов с `PF > 1` нет, этап считается неуспешным

## Success / Failure

### Success

Этап считается успешным, если найден хотя бы один validation-candidate, который:

- даёт `PF > 1`
- не выглядит как случайный пик на нескольких сделках
- не разваливается по period slices

### Failure

Этап считается неуспешным, если:

- даже quantile-постановка на лучшем `x3 + seq20` не находит `PF > 1`
- или находит только хрупкие варианты с плохой структурой результата

В этом случае будет уже сильное основание считать, что сам trailing-stop target family в текущем виде не вытягивает вход даже после перехода к quantile-обучению.

## Expected Outcome

Этот этап не должен отвечать на все вопросы сразу. Он должен дать один чёткий вывод:

- либо quantile-подход оживляет лучший trailing-stop target,
- либо даже лучшая локальная версия trailing-stop target-а не даёт рабочей validation-zone.

После этого уже можно решать:

- продолжать ли линию trailing-stop target дальше,
- идти ли в ranking,
- или возвращаться к усилению уже подтверждённого `entry_path_v1_quantile`.
