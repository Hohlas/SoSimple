# Повышение PF торгового эксперта: от 0.53 к ≥ 2.0

> **Дата**: 2026-03-27
> **Статус**: Draft v2 (обновлено с идеями пользователя)
> **Цели**: PF ≥ 2.0 (агрегат), PF ≥ 1.5 (каждый год), ≥ 50 сделок/год
> **Скоуп**: полный цикл (модель, таргеты, лейблинг, EA)

---

## Контекст и диагностика

### Текущее состояние (лог 20260324, 922 сделки)

| Метрика | Значение |
|---------|----------|
| PF(SL/TP) | 0.53 |
| Win Rate | 37.3% |
| Сделок/год | ~370 |
| PF по годам | 0.44 / 0.53 / 0.63 |

### Корневые причины низкого PF

1. **Недостижимый TP при высоком ratio**: ratio ≥ 4.5 → TP = 4–8 ATR → 0.7–0.9% достигают TP. Сделки "протухают" по MARKET или выбиваются по SL.
2. **Path-independent таргеты**: модель предсказывает max(up) и max(dn) за 12 баров. Но для EA важен порядок: "TP раньше SL" ≠ "up > dn". Категория BOTH_HIT (оба барьера достигнуты) — 100% убыток в MT4, но прибыль в Python OOS.
3. **MARKET-таймаут**: 51% сделок не достигают ни SL, ни TP. Из них 55% — убыток. Нет механизма раннего выхода.
4. **Модель недооценивает adverse excursion**: pred_dn ≈ 0 для BUY-сигналов, но 40% выбиваются по SL. MSE-loss не штрафует за это асимметрично.

#### A.2.2d: Варианты динамического MaxRR

Вместо фиксированного `ML_MaxRR = 4.0`, R:R масштабируется с ratio, но с демпфированием:

| Вариант | Формула | ratio=4 | ratio=7 | ratio=14 | ratio=100 |
|---------|---------|---------|---------|----------|-----------|
| Текущий | `min(ratio/3.5, 4.0)` | 1.14 | 2.0 | **4.0** | **4.0** |
| Линейный k=0.5 | `k * ratio / MinRatio` | 0.57 | 1.0 | 2.0 | 14.3 |
| Sqrt | `sqrt(ratio / MinRatio)` | 1.07 | 1.41 | 2.0 | 5.35 |

| **Log + cap** | `min(ln(ratio/MinRatio)+1, 2.5)` | 1.13 | 1.69 | 2.39 | **2.5** |

**Рекомендация**: `Log + cap` — плавный рост R:R с потолком 2.5. Тестировать все 4 на MT4 Strategy Tester.

## Фаза B: Новые таргеты и loss function

**Цель**: PF ~1.5–2.5, устранение корневой причины (path-dependent).
**Срок**: 1–2 месяца.
**Зависимость**: результаты исследований A.1.

### B.1. Расширение горизонтов: up/dn для 3H и 6H

**Текущие таргеты**: 6 значений — `[up_12, dn_12, up_24, dn_24, up_48, dn_48]`.

**Новые таргеты**: 10 значений — добавить `[up_3, dn_3, up_6, dn_6]`.

**Зачем**: короткие горизонты раскрывают path-структуру. Если `up_3 ≈ 0` и `up_12 > 0` — ожидается задержка перед ростом. Если `dn_3 > 0` и `up_12 > 0` — ожидается откат перед ростом (pullback entry).

**Изменения в pipeline**:
- `MT/MQL4/Include/lib_PIC.mqh` (NERO_CSV_CREATE): добавить расчёт up_3/dn_3/up_6/dn_6
- `processing/label_signals.py`: добавить лейблинг коротких горизонтов
- `ML/data_loader.py`: расширить UPDN_TARGETS до 10
- `API/generate_signals.py`: расширить выход модели

**M1/M5 не нужен**: SL=2ATR, TP≥2ATR → барьеры на расстоянии 4+ ATR. Один H1-бар (≈1 ATR) не может зацепить оба. Порядок hit определяется по H1 OHLC.

### B.2. Pullback entry: вход на откате

**Текущий вход**: market order сразу на сигнале.

**Новый вход**: если `up_12 > X` (потенциал роста) и `dn_3 > Y` (ожидается откат) → ставим Buy Limit на уровне `price - dn_3 * ATR * k` (ожидаемая глубина отката).

**Варианты параметризации** (тестировать на MT4):
- Горизонт отката: H=3, 6 (какой dn_H использовать)
- Глубина: `limit_price = price - dn_H * ScaleK * ATR * limit_k`
- Время жизни ордера: 3–6 баров (после чего отменить)

**Альтернатива (основная идея)**: Limit-ордер по цене фрактала. Проблема: EA открывает сделку на баре T+1, цена уже ушла от фрактала в сторону сигнала → вход по худшей цене. Решение: вместо market-ордера ставим Buy Limit (для BUY) или Sell Limit (для SELL) по цене фрактала. Если цена откатится к фракталу — получаем лучшую цену входа. Нет отката — пропускаем сделку (фильтрация "убежавших" цен).

**Изменения в EA**:
- `lib_ML_Signal.mqh`: новый режим входа (LIMIT вместо MARKET)
- Новые extern-параметры: `ML_EntryMode` (MARKET/LIMIT), `ML_PendingExpiry` (баров до отмены)
- SL/TP привязываются к цене лимит-ордера (фрактала), а не к текущей цене

**Исследование (до реализации)**: по all_trades.csv посчитать `entry_slippage = val - fractal_price` — насколько market entry хуже цены фрактала. Если slippage > 0.3 ATR в среднем, limit entry значимо улучшит PF.

### B.3. Новый лейблинг: first-barrier-hit

**Текущий таргет**: `up_12 = max(High[i] - price, i=1..12) / ATR` (нормализован). Path-independent.

**Новый таргет**: для каждой пары (SL_level, TP_level) определить:
```
label = 1 (WIN)  если TP достигнут раньше SL в окне 12 баров
label = 0 (LOSS) если SL достигнут раньше TP
label = 0.5 (TIMEOUT) если ни один не достигнут
```

**Определение порядка**: по H1 OHLC. Проход bar-by-bar: первый бар, где High ≥ TP или Low ≤ SL, определяет результат. Если оба в одном баре — используем Open: если Open ближе к SL, считаем SL first; иначе TP first.

**Grid уровней** (в ATR):
- SL: [1.5, 2.0, 2.5]
- TP: [2.0, 3.0, 4.0, 6.0]
- Итого: 12 бинарных таргетов

**Изменения в pipeline**:
- `processing/label_signals.py` — новая функция `label_first_barrier_hit()` с bar-by-bar scan

### B.4. Asymmetric loss

**Текущий**: MSE, симметричный. Ошибка "предсказал dn=0, а было dn=5 ATR" (пропущенный SL) штрафуется так же, как "предсказал dn=3, а было dn=0" (ложная тревога).

**Новый**: взвешенный MSE для adverse prediction:
```
loss = MSE(pred_up, true_up) + α * MSE(pred_dn, true_dn)  # для BUY
loss = α * MSE(pred_up, true_up) + MSE(pred_dn, true_dn)  # для SELL
```
где α > 1 (2.0–3.0) — штраф за недооценку adverse movement.

**Альтернатива**: Quantile loss (τ=0.8 для adverse) — модель предсказывает 80-й перцентиль downside, а не среднее.

### B.5. Калиброванная вероятность вместо ratio

**Текущий**: ratio = pred_up / pred_dn. При pred_dn → 0, ratio → ∞ (артефакт).

**Новый**: модель выдаёт P(win | SL=2ATR, TP=XATR) — калиброванная вероятность.
- Порог входа: P(win) ≥ 0.55–0.60 (вместо ratio ≥ 3.5)
- Temperature scaling на validation set для калибровки
- Бонус: P(win) напрямую конвертируется в Kelly fraction для position sizing

### B.6. Дополнительные фичи

| Фича | Описание | Обоснование |
|------|----------|-------------|
| volatility_regime | ATR / ATR_slow (20-period EMA of ATR) | Модель может вести себя по-разному в high/low vol |
| time_since_last_fractal | Баров с прошлого фрактала | Длинные паузы = рейндж |
| session_overlap | Лондон/NY overlap flag | Ликвидность и волатильность |
| recent_sl_hits | Количество SL-убытков за последние 10 сигналов | Серийные убытки = плохой режим |

### B.7. ML-сигналы для выхода из позиции

**Текущий выход**: SL, TP, или MARKET (таймаут HoldOverTime).

**Новый выход**: EA на каждом новом фрактале проверяет ML-сигнал для открытой позиции:
- Для BUY: если `dn_12 > threshold` (или `dn_3 > threshold`) → закрыть по рынку
- Для SELL: если `up_12 > threshold` → закрыть по рынку

**Смысл**: модель видит "сейчас будет движение против позиции" → ранний выход до SL. Сокращает убытки из категории TIMEOUT (73% — LOSS).

**Изменения в EA**:
- `lib_ML_Signal.mqh`: новая функция `ML_CHECK_EXIT()`, вызываемая на каждом баре
- Новые extern-параметры: `ML_ExitEnabled`, `ML_ExitThreshold`
- Читает pred_dn (для BUY) или pred_up (для SELL) из `ml_signals.csv`

**Примечание**: для реализации нужно, чтобы `ml_signals.csv` содержал pred_up/pred_dn для каждого бара (не только для баров с signal≠0). Сейчас generate_signals.py записывает только бары с signal=±1. Расширить: записывать все бары, ML_CHECK_EXIT читает dn для текущего бара.

- A/B сравнение: текущая модель (baseline из фазы A) vs новая модель
- Метрики: PF, WR, N trades, max drawdown — по годам
- signal_tracer для обеих моделей → сравнительный отчёт

## Фаза C: Системные улучшения (по необходимости)

**Цель**: PF ≥ 2.0 стабильно, защита от overfitting.
**Срок**: 1–2 месяца после фазы B.
**Условие запуска**: фаза B не достигла PF ≥ 2.0 стабильно.

### C.1. Walk-forward validation

Заменить фиксированный split (train < 2022, test 2023+) на скользящее окно:
- Train: 3 года, Validation: 6 мес, Test: 6 мес
- Шаг: 6 месяцев
- Модель переобучается каждые 6 мес на свежих данных
- PF считается per-window → медиана и min по окнам

### C.2. Multi-task learning: два выхода

```
Transformer Encoder
       ↓
   CLS token
    ↙      ↘
Regression     Classification
(up/dn для     (win/loss/timeout
 SL/TP)         для фильтрации)
```

- Regression head: текущие 6 таргетов (для расчёта SL/TP)
- Classification head: first-barrier-hit (для фильтрации входа)
- Shared encoder видит обе задачи → лучшие representations

### C.3. Adaptive R:R

Вместо фиксированного MaxRR, модель предсказывает оптимальный R:R per trade:
- Обучение: для каждой сделки в train set найти R:R с максимальным expectancy
- Новый таргет: optimal_rr ∈ [1.0, 4.0]
- EA использует предсказанный R:R вместо формулы `min(ratio/MinRatio, MaxRR)`

### C.4. Ensemble (консенсус)

- 5 моделей с разным random seed
- Вход только при консенсусе ≥ 3/5
- Уменьшает false positive rate, ценой снижения числа сделок

### C.5. Динамический HoldOverTime

Модель предсказывает time_to_hit (бары до TP/SL). EA использует:
- Если предсказано 4 бара, а прошло 8 без движения → ранний выход
- Снижает долю MARKET-убытков (сейчас 257 из 922)

| Риск | Вероятность | Митигация |

| Overfitting на тестере | Высокая | Walk-forward validation (C.1) |
| Path-ordering неточен внутри бара | Низкая | SL и TP разнесены на 4+ ATR — один H1-бар не зацепит оба |
