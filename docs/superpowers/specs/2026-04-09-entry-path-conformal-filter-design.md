# Entry Path Conformal Filter v1 — Design Spec

> **Date**: 2026-04-09
> **Status**: Draft
> **Track**: Надстройка поверх замороженного `entry_path_v1` trade filter
> **Goal**: Проверить, улучшает ли простой conformal-слой качество сделок после уже выбранного базового отбора `A @ 7.5%`

---

## 1. Context

Для `entry_path_v1` уже выбран рабочий базовый слой `торговать / не торговать`.

Текущая замороженная база:

- winner: `A`
- target coverage: `7.5%`
- validation: `36 trades`, `PF=2.67`, `stability_ratio=1.00`
- test: `44 trades`, `PF=4.29`
- последовательная проверка: `30 trades`, `PF=2.87`

Эта база уже отбирает только верхний хвост сигналов по `pred_ret_24_dir_atr`. Следующий шаг не в том, чтобы заново выбирать trade filter, а в том, чтобы поверх него добавить слой доверия к прогнозу.

В проекте уже есть старый `split conformal` в [ML/conformal/calibrate.py](../../ML/conformal/calibrate.py). Важный вывод из прошлой попытки уже известен: простой `split conformal` даёт общий размер интервала для всего набора, а не отдельный размер для каждой сделки. Поэтому правило по ширине интервала в таком виде не годится как по-сделочный фильтр.

Отсюда следует ограничение для `v1`: первый conformal-слой нужно строить не через ограничение ширины, а через нижнюю границу интервала.

---

## 2. Main Idea

`Conformal Filter v1` строится только поверх сделок, которые уже прошли базовый отбор `A @ 7.5%`.

Дальше на `validation`:

1. берётся прогноз `pred_ret_24_dir_atr`;
2. считается абсолютная ошибка `|y_true - y_pred|`;
3. по этим ошибкам строится общий conformal-радиус;
4. для каждой сделки считается нижняя граница:

```text
lower_bound = pred_ret_24_dir_atr - q
```

где `q` — conformal-квантиль, посчитанный только на `validation`.

После этого сравниваются правила:

- база без conformal
- `lower_bound > 0`
- `lower_bound > m`, где `m` берётся из небольшой validation-only сетки

Победитель замораживается на `validation` и без перенастройки применяется на `test`.

---

## 3. Scope

### Входит в этап

- conformal-калибровка только для `ret_24_dir_atr`
- применение conformal только поверх замороженного `A @ 7.5%`
- сравнение базы и нескольких `lower_bound`-правил
- выбор победителя только на `validation`
- финальная проверка на `test`
- отдельная последовательная проверка для защиты от ложного улучшения

### Не входит в этап

- новый retrain `entry_path_v1`
- новый trade filter
- adaptive conformal
- conformal с разной шириной интервала у разных сделок
- перенос слоя в MT4
- размер позиции

---

## 4. Design Principles

### 4.1. Только поверх уже выбранной базы

Conformal здесь не заменяет trade filter и не ищет сигналы сам. Он работает только как второй слой поверх уже выбранного `A @ 7.5%`.

### 4.2. Validation-first

Все параметры conformal-слоя выбираются только на `validation`. На `test` применяется уже замороженное правило.

### 4.3. Без ложной точности

Так как текущий `split conformal` даёт общий радиус, нельзя делать вид, будто правило по ширине интервала умеет выбирать сделки по одной. Для `v1` используется только нижняя граница интервала.

### 4.4. Не жертвовать последовательной проверкой

Если кандидат красиво улучшает отдельные сделки, но ухудшает последовательную проверку, он не считается годным.

### 4.5. Сначала простой слой, потом усложнение

Если простой `split conformal` поверх `A @ 7.5%` не даёт пользы, нет смысла сразу идти в более сложный adaptive-вариант.

---

## 5. Calibration Design

### 5.1. Вход

Калибровка использует только validation-сделки, которые уже прошли замороженное правило `A @ 7.5%`.

### 5.2. Целевая величина

Калибруется только:

- `ret_24_dir_atr`

Причина выбора:

- именно по нему выбран текущий победитель `A`;
- это самый прямой и понятный прогноз полезности сделки;
- для первого шага не стоит смешивать несколько выходов в одну conformal-калибровку.

### 5.3. Nonconformity score

Используется простая абсолютная ошибка:

```text
score = |ret_24_true - pred_ret_24_dir_atr|
```

### 5.4. Интервал

Для `v1` строится симметричный интервал:

```text
[pred_ret_24_dir_atr - q, pred_ret_24_dir_atr + q]
```

где `q` — global conformal-квантиль с finite-sample correction, посчитанный на validation-сделках после базового фильтра.

---

## 6. Candidate Rules

### 6.1. База

Для сравнения всегда сохраняется базовый вариант без conformal:

- `A @ 7.5%`

### 6.2. Conformal-кандидаты

Для `v1` сравниваются такие правила:

- `LB > 0`
- `LB > 0.25`
- `LB > 0.50`
- `LB > 0.75`

Где:

- `LB = pred_ret_24_dir_atr - q`
- все пороги измеряются в ATR-единицах целевого таргета

Причина такой сетки:

- это простой и понятный первый диапазон;
- он проверяет, помогает ли не просто положительная нижняя граница, а ещё и запас по нижней границе.

---

## 7. Selection Rules

Победитель выбирается только на `validation`.

Кандидат считается допустимым только если:

1. после conformal-фильтра осталось не меньше `25` сделок;
2. `PF` в последовательной проверке не ниже, чем у базового `A @ 7.5%`;
3. сам кандидат рассчитан без подглядывания в `test`.

Если допустимых кандидатов несколько, приоритет такой:

1. выше `PF` по сделкам по отдельности;
2. при равном `PF` выше `mean_pnl_atr`;
3. при равенстве первых двух метрик выше устойчивость по периодам;
4. при прочем равенстве больше число оставшихся сделок.

Если ни один conformal-кандидат не проходит ограничения, победителем остаётся база без conformal.

---

## 8. Evaluation Protocol

### 8.1. Основная проверка

Главная проверка идёт по сделкам по отдельности.

Ключевые метрики:

- `trades`
- `PF`
- `win_rate`
- `mean_pnl_atr`

### 8.2. Проверка по периодам

Как и в trade filter, нужна простая проверка устойчивости по периодам. Для `v1` используется тот же режим, что уже принят в базовом trade filter.

### 8.3. Последовательная проверка

Для каждого кандидата обязательно считается последовательная проверка с тем же горизонтом удержания, что уже заморожен в baseline.

Она не главный критерий отбора, но жёсткий защитный фильтр:

- если её `PF` ниже, чем у базы, кандидат выбывает.

### 8.4. Test

На `test`:

- не подбирается новый порог;
- не пересчитывается победитель;
- только применяется уже замороженное validation-правило.

## 10. Expected Outcomes

После этапа должен быть получен один из двух честных итогов:

1. conformal-слой поверх `A @ 7.5%` даёт полезный отбор и становится новым замороженным слоем `trade / no-trade`;
2. conformal-слой не даёт пользы, и это тоже фиксируется как полезный вывод без подмены результата.

В обоих случаях проект получает не догадку, а проверенный ответ на вопрос, есть ли смысл в простом `split conformal` поверх текущего `entry_path_v1`.

---

## 11. Risks and Follow-up

### 11.1. Малое число сделок

После `A @ 7.5%` на `validation` всего `36` сделок. Поэтому слишком агрессивный conformal-фильтр легко даст красивую, но шумную картину. Ограничение `>= 25` сделок нужно именно против этого.

### 11.2. Общий радиус может оказаться слишком грубым

Даже если `LB > 0` или `LB > m` немного помогут, это ещё не означает, что простой `split conformal` — лучший возможный слой. Он может оказаться слишком грубым для реальной по-сделочной селекции.

### 11.3. Следующий шаг в случае слабого результата

Если `v1` не даст пользы, тогда уже можно честно переходить к следующему уровню сложности:

- adaptive conformal;
- conformal с отдельной оценкой масштаба ошибки;
- более богатый слой `trade / no-trade` поверх нескольких выходов модели.
