# MT5 Multi-Position Refactoring Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full refactoring of MQL5 order management from single-position `PRICE BUY, SEL` structs to ticket-indexed `POSITION Positions[]` array, so every position (including simultaneous same-direction ones) gets its own CLOSE_BUY, MODIFY, TRAILING, and life-cycle management identical to what a lone position receives now.

**Non-goal:** No winner selection, no `locked_test`, no PnL/trading claims. Diagnostic only. Python pipeline unchanged except `.set` file generation.

**Architecture:** `EXPERT_PARENT_CLASS::BUY/SEL` (line 136) replaced by `POSITION Pos[]` array indexed by MT5 ticket. `ORDER_CHECK()` populates the array. `MODIFY()` iterates the array. `CLOSE_BUY/SEL`, `TRAILING`, `OUTPUT`, `COUNT`, `TIMER` — all work by iterating over matching array entries. `set.BUY` / `set.SEL` (type `ORD_TYPE`, FUNCTIONS.mqh:106-109) remain as pending-order holders (UNCHANGED — they hold the NEXT single order to place per bar, which is fine).

**Tech Stack:** MQL5 using MQL4Compat wrappers, Python `.venv/bin/python` for compile verification and batch runner.

### Core Design: `PositionArray` model

```cpp
#define MAX_MULTIPOS 64  // 64 == enough, test-adjustable
struct POSITIONTracker { int ticket; PRICE data; bool active; };
POSITIONTracker Pos[MAX_MULTIPOS];
int PosCount;
```

Helper functions needed (added to `ORDERS.mqh` or `FUNCTIONS.mqh` after Task 1):

```cpp
void AddPosition(POSITIONTracker p) { ... }
void RemovePositionByTicket(int ticket) { ... }
int FindPositionIndex(int ticket) { ... loop... }
```

Every legacy `BUY.Val`/`BUY.Typ`/... reference becomes `Pos[i].data.Val` etc, with `i` either via iteration or via `FindPositionIndex(ticket)`.

#### `set.BUY` / `set.SEL` disclaimer

`set.BUY` and `set.SEL` remain UNCHANGED — they are pending-order structs of type `ORD_TYPE` (which holds a `PRICE` BUY and a `PRICE` SEL). They hold the containing SINGLE new order to be placed on this bar, which is correct: one bar = one pending order queue.

```cpp
void AddPosition(POSITION_TRACKER p) {
    if (PosCount >= MAX_MULTIPOS) return;
    Pos[PosCount] = p;
    PosCount++;
}
void RemovePositionByTicket(int ticket) {
    for (int i=0; i<PosCount; i++) {
        if (Pos[i].ticket == ticket) {
            Pos[i].active = false;
            Pos[i].data.Val = 0;
            break;
        }
    }
}
int FindPosIndexByTicket(int ticket) {
    for (int i=0; i<PosCount; i++)
        if (Pos[i].ticket == ticket && Pos[i].active) return i;
    return -1;
}
```
