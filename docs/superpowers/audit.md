## Замечания

### 1. Критично — ключевое исправление живёт в файле вне git

- Место: отчёт, раздел «Changed Files», строка про `MT/MQL5/Include/MQL4Compat.mqh`;
  также CHANGELOG.md (новая запись, поле artifacts).
- Суть: `MQL4Compat.mqh` внесён в `.gitignore` (строка 297, коммит `1fbe99e`
  «stop tracking MT5 standard libraries») и не отслеживается git
  (`git ls-files` пуст, `git check-ignore` подтверждает игнор). Правка
  `RefreshPriceArrays()` («копировать всю историю»), без которой tester падал
  с `array out of range`, существует только на диске.
- Доказательство: `git check-ignore -v MT/MQL5/Include/MQL4Compat.mqh` →
  `.gitignore:297`; `git ls-files` не находит файл; сама правка видна в файле
  (строка 58: `void RefreshPriceArrays(int count=0)`).
- Почему важно: план (Task 3 «Compile MT5 Expert From Git Source») и методика
  `13b` («.ex5 собран из текущего git-исходника») требуют сборку из
  версионированного кода. Следующий агент, собрав из git, получит либо другой
  `MQL4Compat.mqh`, либо его отсутствие — прогон невоспроизводим, а отчёт
  представляет файл как «Changed Files», что читается как версионированное
  изменение. CHANGELOG указывает его как artifact, хотя артефакта в истории git нет.
- Рекомендация: либо вернуть `MQL4Compat.mqh` под контроль git (он проектный
  compat-слой, а не стандартная библиотека MetaQuotes — правка авторская),
  либо явно записать в отчёте и в манифесте, что файл не версионируется, и
  приложить его sha256/копию в `ML/reports/mt5_execution_loop/`.

### 2. Важно — compile-verdict относится не к финальному `.ex5`

- Место: отчёт, раздел «Verification», пункт «Компиляция: … 0 errors, 0 warnings».
- Суть: сохранённый compile-лог `/tmp/sosimple_mt5_compile.log` датирован
  2026-07-30 09:40, а `$o$imple.mq5` и `$o$imple.ex5` имеют mtime
  2026-07-31 09:53 — источник правился и пересобирался уже после зафиксированного
  вердикта (финальный прогон tester завершился 31-го в 10:02). Вердикт
  «0 errors, 0 warnings» доказан только для сборки предыдущего дня.
- Доказательство: `ls -la /tmp/sosimple_mt5_compile.log` (Jul 30 09:40);
  `ls -la MT/MQL5/Experts/` (`.mq5` и `.ex5` — Jul 31 09:53); журнал агента
  20260731.log — тест завершён 10:02:02.
- Почему важно: методика `13b` («.ex5 собран из текущего `$o$imple.mq5`»,
  «MetaEditor log сохранён») — сейчас нет лога, подтверждающего чистую сборку
  именно той версии, которая исполнялась. Лог к тому же лежит в `/tmp`
  и исчезнет при перезагрузке.
- Рекомендация: пересобрать финальный источник, сохранить лог компиляции в
  постоянный путь (например, `ML/reports/mt5_execution_loop/`), указать его
  в отчёте; либо уточнить в Verification, что вердикт относится к сборке
  от 30.07, а финальная сборка выполнена терминалом 31.07 без сохранённого лога.

### 3. Важно — 690 `ERROR-4756` (trade request send failed) не упомянуты

- Место: отчёт, разделы «Results» (Lifecycle) и «Limitations».
- Суть: журнал агента за 31.07 содержит 690 строк `ERROR-4756`
  («Trade request send failed»), включая 4 `SET_BUY`, 11 `SET_SEL` и

  агента лежит непроанализированный `ERROR_SoSimple_163856259.csv` (34 МБ).
- Доказательство: `grep -c "ERROR-4756"` по декодированному
  `Tester/Agent-127.0.0.1-3000/logs/20260731.log` → 690; листинг каталога
  `.../MQL5/Files/` → `ERROR_SoSimple_163856259.csv` 34101088 байт.
- Почему важно: план (Task 5) требует «все критические расхождения
  классифицированы»; методика `13b` — «все расхождения исполнения

  часть из них объясняет 32 «pending order was not found» и 9 ORDER_EXPIRED,
  но это гипотеза — построчная связка не выполнена.
- Рекомендация: добавить в отчёт подсчёт `ERROR-4756` с разбивкой по причинам
  (`Market closed` и др.), связать с 32+9 lifecycle-остатками или явно записать
  как неклассифицированный остаток; упомянуть `ERROR_SoSimple_*.csv` как
  сохранённый, но не проанализированный артефакт.

### 6. Улучшение — Split Disclosure и даты прогона сформулированы неточно

- Место: отчёт, «Split Disclosure» («Прогон выполнен на периоде источника

- Рекомендация: переформулировать: «tester-диапазон 2019.06.20–2022.12.03

## Итог

Числовое ядро отчёта честное: все хэши, счётчики событий, lifecycle-арифметика,
тайминг-контракт и результаты тестов воспроизведены проверкой 2026-07-31 без
единого расхождения. Ограничения и запреты интерпретации раскрыты корректно.
Главные проблемы — воспроизводимость, а не факты: критичная правка
`MQL4Compat.mqh` не под git (п.1), compile-verdict не привязан к финальному
`.ex5` (п.2), и 690 отказов отправки ордеров из журнала агента остались вне
классификации исполнения (п.3). Пункты 1–3 стоит закрыть до старта
`NEXT_AFTER_MT5_SINGLE_RULE` (batch selection), потому что batch-этап будет
опираться на этот контур как на доказанный.
