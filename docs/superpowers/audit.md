# Аудит brainstorm-workflow.js

> **Дата**: 2026-08-14
> **Аудитируемый документ**: `docs/audit/brainstorm-workflow.js`

## Критичные дефекты

   1. Баг проверки фальсифицируемости (строка 332). Схема ответа критика кладёт флаг внутрь объекта:   
   "falsification": {..., "falsifiable": true}. А код проверяет r.falsifiable — это всегда undefined,  
   поэтому нефальсифицируемые идеи никогда не помечаются. Должно быть r.falsification &&               
   r.falsification.falsifiable === false.                                                              
                                                                                                       
   2. Неизвестный вердикт превращается в «выживает» (строки 327–330). Если критик вернёт вариант вне   
   тройки («убито», «выжила», английский и т.п.), он не совпадёт с «убита»/«условно», и ветка          
   verdicts.length > 0 даст «выживает». Это опасная сторона ошибки — лучше валидировать вердикт и брак 
   считать «условно» (или отбрасывать рецензию в missingReviews).                                      
                                                                                                       
## Важные                                                                 
                                                                                                       
   3. Идея с 0 рецензий молча становится «условно» (строка 331) и может попасть в топ-10 синтеза.
   Предлагаю отдельный статус «без рецензии» и запрет включения в короткий список.
                                                    
   4. Нет финальной верификации. log('Брэйншторм завершён...') печатается безусловно — если агент
   синтеза не записал файл, скрипт всё равно рапортует об успехе. В retrospective-workflow вы эту дыру
   закрыли шагом 0 верификации; здесь нужен аналог (дешёвый assert-агент: файл существует, размер >
   1K).                                             
                                                    
   5. Нет потолка числа рецензий. 4 генератора × 6–10 = до 40 сырых; дедупликация может сохранить 25–30
    → 50–60 агентов-критиков. Это не сломает рантайм (кэп 16 параллельно), но стоимость удваивается без
    пользы. Предлагаю лимит после дедупликации (например, ≤20 идей) с записью отброшенных в лог.
                                                    
## Мелкие                                           
                                                    
   - Строка 12: комментарий оборван — «// Промпт-основа каждой фазы».
   - Строка 157: «снимает жёсткие запреты» читается наоборот; точнее — «применяет жёсткие запреты,
   удаляя нарушающие идеи».                         
   - Шаг 4 критика: «tags += «спекуляция»» — для JSON-контракта понятнее «добавь в массив tags элемент
   "спекуляция"».                                   
   - Синтез: ранжирование по «потенциал / стоимость» — данных о потенциале в mergedBlock нет, агент
   будет додумывать. Либо критерий «от дешёвых к дорогим», либо явно указать: потенциал оценивать
   только по edge_source.                           
   - MIN_REVIEWS = 1 при двух треках: флаг «недооценена» сработает только при 0 рецензий. Если замысел
   — обязательная двойная проверка, нужно MIN_REVIEWS = 2.

## Предложения по содержанию
 
   - Дедупликации не хватает второго запрета: пока удаляются только индикаторы, а «прямое предсказание
   направления» (закрыто, секция 4) дойдёт до критиков и сожжёт их вызовы. Добавить в список удаления.
   - Ключевые факты из next.md (MI-потолок, календарная доминантность, regime drift) в промптах
   отсутствуют. Критики читают ретроспективу целиком, но короткая вставка 6 фактов в промпт критика
   заметно усилила бы проверку новизны — особенно фильтр «идея обязана объяснять, откуда берётся
   информация, которой по MI-аудиту нет».
 
   Сильные места: связка результат↔вектор по индексу, детерминированное слияние вердиктов кодом без
   лишнего агента, утилиты parseJson/normalizeResult.
