# Architecture Decision Record: Выбор подхода к прогнозированию

**Status**: Draft (требует обсуждения)  
**Date**: 2026-03-09  
**Decision**: Отказ от прямой 3-классовой классификации в пользу двухэтапного гибридного подхода

---

## 1. Резюме

После завершения этапа 3.2 (сравнение архитектур нейросетей) выявлено, что **все 4 архитектуры упираются в один потолок качества** (~0.57 macro F1, ~0.35 F1_minority). Проблема не в архитектуре, а в фундаментальном ограничении данных: дисбаланс классов 95%/2.5%/2.5% и недостаточное количество сигнальных примеров (~1000 на класс).

**Принятое решение**: Перейти от прямой классификации signal ∈ {-1, 0, 1} к **двухэтапному гибридному подходу**:
- Этап 1: Бинарная классификация Signal (|-1|+|1|) vs NoSignal (0)
- Этап 2: Регрессия predict + определение направления по знаку

---

## 2. Контекст

### 2.1 Текущие результаты

**Классификация (4 архитектуры)**:
| Модель | Val Macro F1 | F1(-1) | F1(1) | Signal Precision | Параметры |
|--------|--------------|--------|-------|------------------|-----------|
| hybrid | 0.568 | 0.417 | 0.353 | ~0.28 | 83K |
| transformer | 0.567 | 0.392 | 0.359 | ~0.29 | 70K |
| bilstm | 0.553 | 0.370 | 0.340 | ~0.27 | 147K |
| cnn1d | 0.346* | 0.368 | 0.325 | 0.236 | 42K |

*F1_minority, не macro F1

**Регрессия**:
| Модель | Pearson r | Параметры |
|--------|-----------|-----------|
| transformer | 0.563 | 70K |
| bilstm | 0.555 | 147K |
| hybrid | 0.546 | 83K |
| cnn1d | 0.519 | 42K |

### 2.2 Проблемы текущего подхода

1. **Ловушка дисбаланса**: Macro F1 = 0.57 обманчива — достигается за счёт F1(0)=0.95 (neutral, 95% данных)
2. **Катастрофическое качество сигналов**: F1(-1) и F1(1) ≈ 0.35–0.42
3. **70-75% ложных сигналов**: Signal precision = 0.25–0.30
4. **Overfitting**: Train loss ↓, Val loss ↑ — недостаточно данных для сложных моделей
5. **Потолок архитектур**: Разброс между лучшей и худшей моделью всего 0.017 macro F1

### 2.3 Почему это не работает

Для обучения нейросети с 147K параметров (Bi-LSTM) нужно минимум 147K–1.47M примеров. У нас всего ~2,200 сигнальных примеров — **дефицит 66x–668x**.

При таком дисбалансе модель выучивает оптимальную стратегию: "всегда предсказывать 0" — это даёт 95% accuracy и высокий F1(0), но нулевую торговую ценность.

## 3. Рассмотренные альтернативы

### 3.1 Альтернатива A: Продолжить улучшать классификацию

**Подход**: HPO для всех моделей, усиленный Focal Loss, WeightedRandomSampler, downsample neutral

**Плюсы**:
- Прямое решение (Buy/Sell/Neutral)
- Не требует изменения архитектуры

**Минусы**:
- Потенциал ограничен данными (максимум ~0.50 F1_minority)
- Требует значительных вычислительных ресурсов
- Не решает фундаментальную проблему дисбаланса

**Вердикт**: ❌ Отклонено — недостаточный потенциал улучшения

### 3.2 Альтернатива B: Перейти полностью на регрессию

**Подход**: Только регрессия predict, порог |predict| > threshold для генерации сигналов

**Плюсы**:
- Нет проблемы дисбаланса классов
- Непрерывная оценка "силы" сигнала
- Pearson r = 0.56 — база для улучшения

**Минусы**:
- Требует подбора threshold
- Нет явного контроля precision/recall
- DirAcc=97.5% — артефакт (связь с fractal0_direction)

**Вердикт**: ⚠️ Частично принято — используется как Stage 2

### 3.3 Альтернатива C: Двухклассовая постановка (Signal vs NoSignal)

**Подход**: Объединить -1 и 1 в класс "Signal", 0 → "NoSignal"

**Плюсы**:
- Более сбалансированная задача (~5% vs ~95%)
- Можно использовать стандартные техники борьбы с дисбалансом

**Минусы**:
- Теряется информация о направлении (Buy vs Sell)
- Всё ещё сильный дисбаланс

**Вердикт**: ⚠️ Частично принято — используется как Stage 1

### 3.4 Альтернатива D: Двухэтапный гибридный подход ⭐

**Подход**: 
- Stage 1: Signal vs NoSignal (бинарная классификация)
- Stage 2: Регрессия predict + знак для направления
- Inference: порог на вероятность Signal + знак predict

**Плюсы**:
- Разделение задач: детекция и оценка
- Stage 1 работает с более сбалансированной задачей
- Stage 2 не страдает от дисбаланса
- Контроль precision/recall через порог Stage 1
- Можно использовать разные модели для разных задач

**Минусы**:
- Сложнее в реализации
- Два набора гиперпараметров
- Потенциальное накопление ошибок

**Вердикт**: ✅ Рекомендуется

## 4. Решение

### 4.1 Выбранный подход: Двухэтапный гибрид

```
┌─────────────────────────────────────────────────────────────┐
│  Вход: X ∈ R^{batch×100×10} (фракталы без fractal_time)     │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  ЭТАП 1: Детектор сигналов                                   │
│  ─────────────────────────                                   │
│  Модель: 1D-CNN (42K параметров, быстрая)                   │
│  Задача: Бинарная классификация                             │
│    - Класс 1: Signal (объединённые -1 и 1, ~5%)             │
│    - Класс 0: NoSignal (0, ~95%)                            │
│  Loss: BCE with pos_weight=19 (95/5)                        │
│  Метрика: F1 для класса Signal                              │
└─────────────────────────────────────────────────────────────┘
                            ↓
                    probability_signal
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  ЭТАП 2: Оценка движения (выполняется всегда)               │
│  ─────────────────────────                                  │
│  Модель: Bi-LSTM (147K параметров, лучшая для регрессии)   │
│  Задача: Регрессия predict ∈ [-1, 1]                        │
│  Loss: Huber Loss (delta=1.0)                               │
│  Метрика: Pearson r                                         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  ИНФЕРЕНС:                                                   │
│  if probability_signal > threshold (например, 0.6):         │
│      signal = sign(predict)  # -1 или 1                     │
│      confidence = probability_signal × |predict|            │
│  else:                                                      │
│      signal = 0                                             │
│      confidence = 0                                         │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Обоснование выбора моделей

**Stage 1 (1D-CNN)**:
- Самая быстрая (79 сек vs 641 сек Transformer)
- Меньше всего параметров (42K) — меньше overfitting
- Хорошо захватывает локальные паттерны
- Подходит для бинарной классификации

**Stage 2 (Bi-LSTM)**:
- Лучший Pearson r для регрессии (0.555)
- Учитывает временные зависимости
- Больше параметров приемлемо для регрессии (нет дисбаланса)

### 4.3 Пороги и метрики

**Stage 1 (Signal Detection)**:
- Целевой F1 для Signal: >0.60 (более достижимо, чем 0.40 для отдельных классов)
- Порог по умолчанию: 0.5 (настраиваемый)
- Для высокого precision: порог 0.7–0.8
- Для высокого recall: порог 0.3–0.4

**Stage 2 (Regression)**:
- Целевой Pearson r: >0.60
- Использовать magnitude |predict| как уверенность

**Комбинированная метрика**:
```
Final_Signal = I[prob_signal > threshold] × sign(predict)
Confidence = prob_signal × |predict|
```

## 6. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Накопление ошибок (Stage 1 → Stage 2) | Средняя | Среднее | Обучение Stage 2 на всех данных, не только Signal |
| Stage 1 всё ещё страдает от дисбаланса | Высокая | Высокое | Использовать pos_weight=19, focal loss, threshold tuning |
| Увеличение времени инференса | Низкая | Низкое | Модели маленькие (42K + 147K), latency не критична (>10 сек приемлемо) |
| Сложность в настройке двух моделей | Средняя | Среднее | Автоматизировать через pipeline, HPO |

## 8. Fallback стратегия

Если двухэтапный подход не достигает целевых метрик:

1. **Вернуться к улучшенной 3-классовой классификации** с агрессивным downsampling neutral класса до 20%
2. **Перейти к anomaly detection** (One-Class SVM, Isolation Forest) для детекции сигналов
3. **Собрать больше данных** (требует времени, 3–6 месяцев)
4. **Переформулировать задачу**: предсказание силы тренда вместо разворотов
