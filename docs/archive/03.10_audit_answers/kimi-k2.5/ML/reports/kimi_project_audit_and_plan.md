# Project Audit and Strategic Plan

**Project**: SoSimple — ML-бот для прогнозирования разворотов Forex (XAUUSD, H1)  
**Audit Date**: 2026-03-09  
**Auditor**: AI Agent (Architect Mode)  
**Status**: Завершение Этапа 3.2, требуется принятие стратегического решения

---

## Executive Summary

Проект находится в критической точке: 4 архитектуры нейросетей обучены, но все упираются в один и тот же потолок качества. Классификация даёт F1_macro ≈ 0.57, но **торгово-значимые классы имеют F1 ≈ 0.35–0.42** — катастрофически низкое качество для практического применения. Регрессия показывает Pearson r ≈ 0.55–0.56, но метрика DirAcc=97.5% является артефактом data leakage.

**Ключевой вывод**: Проблема не в архитектуре, а в **фундаментальных ограничениях данных** (дисбаланс 95%/2.5%/2.5% и недостаточное количество сигнальных примеров ~1000 на класс).

**Рекомендация**: Перейти от прямой классификации {-1, 0, 1} к **двухэтапному подходу** (Signal vs NoSignal → направление) с фокусом на регрессию для оценки величины движения.

## Phase 1: Comprehensive Audit

### 1.1 Audit Данных

#### 1.1.1 Объём и дисбаланс

| Параметр | Train | Validation | Критичность |
|----------|-------|------------|-------------|
| Всего строк | 43,593 | 9,341 | ✅ Достаточно |
| Класс -1 (Sell) | 1,084 (2.5%) | 232 (2.5%) | ⚠️ Критично |
| Класс 0 (Neutral) | 41,390 (94.9%) | 8,865 (94.9%) | ⚠️ Доминирует |
| Класс 1 (Buy) | 1,119 (2.6%) | 244 (2.6%) | ⚠️ Критично |

**Оценка**: Общий объём данных достаточен для обучения, но **дисбаланс классов является критическим**:
- Всего ~2,200 сигнальных примеров на весь train set
- При разбиении на train/val/test — остаётся ~1,000 примеров на класс для обучения
- Для сложных архитектур (Bi-LSTM: 147K параметров) — недостаточно сигнальных данных

#### 1.1.2 Достаточно ли данных для глубокого обучения?

**Правило большого пальца**: Для каждого параметра модели нужно минимум 1–10 примеров.

| Модель | Параметры | Нужно примеров | Есть сигнальных | Дефицит |
|--------|-----------|----------------|-----------------|---------|
| Bi-LSTM | 147K | 147K–1.47M | ~2,200 | 🔴 66x–668x |
| Hybrid CNN+LSTM | 83K | 83K–830K | ~2,200 | 🔴 38x–377x |
| Transformer | 70K | 70K–700K | ~2,200 | 🔴 32x–318x |
| 1D-CNN | 42K | 42K–420K | ~2,200 | 🔴 19x–191x |

**Вывод**: Даже самая маленькая модель (CNN) имеет **дефицит данных 19–191x** для сигнальных классов. Это объясняет:
- Почему все модели застряли на одном потолке
- Почему наблюдается overfitting (train loss ↓, val loss ↑)
- Почему F1 для сигнальных классов остаётся низким (~0.35)

#### 1.1.3 Признаки Data Leakage

Проведён анализ pipeline ([`docs/DATA_FLOW.md`](docs/DATA_FLOW.md)):

| Этап | Риск утечки | Статус | Примечание |
|------|-------------|--------|------------|
| Сортировка фракталов | Низкий | ✅ Чисто | Сортировка внутри строки, нет межстрочной зависимости |
| Маркировка (label_signals.py) | Низкий | ✅ Чисто | Использует только future strong/break — legit для supervised learning |
| Нормализация | Средний | ⚠️ Проверить | StandardScaler fit на train, transform на val — корректно |
| ATR нормализация | Низкий | ✅ Чисто | ATR вычисляется на момент времени строки |

**Выявленная утечка в регрессии**: В [`discussion.md`](docs/plans/discussion.md) зафиксирована критическая утечка через признак `fractal0_direction`:
- `predict = -back * direction` — знак predict жёстко связан с direction
- Нейросеть достигает DirAcc=97.5%, "видя" direction текущего фрактала
- **Это НЕ legit утечка, а математическая связь** — но делает метрику DirAcc бессмысленной

**Рекомендация**: Исключить `fractal0_direction` из признаков для регрессии или изменить формулировку задачи.

#### 1.2.3 Классификация vs Регрессия: что выбрать?

| Критерий | Классификация | Регрессия |
|----------|---------------|-----------|
| **Текущее качество** | F1_minority ~0.35 (плохо) | Pearson r ~0.56 (слабое) |
| **Торговая ценность** | Прямое решение (Buy/Sell/Neutral) | Требует порогов для конвертации в сигналы |
| **Борьба с дисбалансом** | Сложно (95% neutral) | Нет дисбаланса (непрерывная переменная) |
| **Интерпретируемость** | Высокая | Низкая (нужен threshold) |
| **Потенциал улучшения** | Ограничен (нужно больше данных) | Есть (можно улучшить корреляцию) |

**Критический анализ классификации**:
- Macro F1 = 0.57 — обманчивая метрика (высокая за счёт F1(0)=0.95)
- Signal precision = 0.25–0.30 → **70-75% ложных сигналов**
- F1(-1) = 0.37–0.42, F1(1) = 0.34–0.38 — катастрофически низкие
- При таком качестве торговая система будет генерировать убытки

**Критический анализ регрессии**:
- Pearson r = 0.56 — умеренная положительная корреляция
- Можно использовать порог |predict| > threshold для генерации сигналов
- Нет проблемы дисбаланса классов
- Можно комбинировать с классификацией (гибридный подход)

**Рекомендация**: Отказаться от прямой 3-классовой классификации в пользу **двухэтапного подхода**:
1. Этап 1: Бинарная классификация Signal (|-1|+|1|) vs Neutral (0)
2. Этап 2: Регрессия predict + определение направления по знаку

#### 1.2.4 Анализ DirAcc=97.5% в регрессии

**Наблюдение**: Все модели регрессии показывают directional_accuracy ≈ 97.5%.

**Объяснение** (из [`discussion.md`](docs/plans/discussion.md)):
```
predict = -back * direction
```
Знак predict жёстко связан с direction фрактала. Признак `fractal0_direction` доступен на входе модели, и нейросеть легко восстанавливает эту связь.

**Это data leakage?** Нет, это **математическая тавтология**:
- В реальном времени direction fractal[0] известен
- Predict вычисляется ретроспективно на основе того же direction
- Модель "подсматривает" легальную информацию

**Проблема**: Метрика DirAcc становится бесполезной для оценки качества. Нужны альтернативные метрики:
- Корреляция по модулю |predict| (без учёта знака)
- MAE/RMSE безотносительно к направлению
- Бэктест с реальными торговыми правилами

#### 1.3.3 Адекватность loss functions

**Focal Loss** ([`ML/losses.py`](ML/losses.py)):
```python
FocalLoss(alpha=[0.45, 0.10, 0.45], gamma=2.0)
```
- Веса minority:majority = 4.5:1 — **недостаточно агрессивны** для 95%/2.5%/2.5% дисбаланса
- Gamma=2.0 — стандартное значение, можно увеличить до 3–5
- Частично решает проблему, но не устраняет её полностью

**Huber Loss**:
- Подходит для регрессии с выбросами
- Delta=1.0 — разумное значение для нормализованного predict ∈ [-1, 1]

**Рекомендация**: Для классификации попробовать alpha=[0.495, 0.01, 0.495] (вес minority в 50x выше neutral).

#### 1.3.4 Подход к нормализации

**Текущая схема** ([`docs/DATA_FLOW.md`](docs/DATA_FLOW.md)):
1. Построчная нормализация (цена → % относительно первого фрактала)
2. StandardScaler по каждому признаку
3. ATR нормализация для predict

**Оценка**: Схема корректна, предотвращает утечку данных через масштаб цены.

**Потенциальное улучшение**: Добавить признаки относительной волатильности (ATR/price) для каждого фрактала.

## Phase 2: Strategic Plan

### 2.1 Стратегическое направление

#### 2.1.1 Рекомендуемый подход: Двухэтапная гибридная модель

**Отказ от прямой 3-классовой классификации** — она не работает при текущем дисбалансе.

**Новая архитектура**:

```
Вход: X ∈ R^{batch×100×10}
         ↓
    ┌─────────────────────────────────────┐
    │  ЭТАП 1: Детектор сигналов          │
    │  Бинарная классификация:            │
    │  Signal (|-1|+|1|) vs NoSignal (0)  │
    │  Модель: 1D-CNN (быстрая, 42K)      │
    │  Loss: BCE with heavy class weights │
    └─────────────────────────────────────┘
         ↓
    ┌─────────────────────────────────────┐
    │  ЭТАП 2: Оценка движения            │
    │  Регрессия: predict ∈ [-1, 1]       │
    │  Модель: Bi-LSTM (лучшая для регр.) │
    │  Loss: Huber                        │
    └─────────────────────────────────────┘
         ↓
    ┌─────────────────────────────────────┐
    │  ИНФЕРЕНС:                          │
    │  if Stage1_Prob > threshold:        │
    │     direction = sign(Stage2_Predict)│
    │     signal = direction              │
    │  else:                              │
    │     signal = 0                      │
    └─────────────────────────────────────┘
```

**Обоснование**:
1. Детектор сигналов работает с более сбалансированной задачей (~5% Signal vs ~95% NoSignal)
2. Регрессия не страдает от дисбаланса классов
3. Можно настраивать пороги отдельно для precision/recall trade-off
4. Комбинация двух моделей даёт больше гибкости

### 2.4 Реалистичность целей MVP

| Цель MVP | Текущее | Требуемое | Достижимо? | Что нужно |
|----------|---------|-----------|------------|-----------|
| Accuracy >65% | ~87% (но biased) | 65% | ✅ Да | Использовать balanced accuracy или F1 |
| Sharpe Ratio >1.5 | Н/Д | 1.5 | ⚠️ Неизвестно | Бэктест на test set |
| Max Drawdown <25% | Н/Д | 25% | ⚠️ Неизвестно | Бэктест с учётом спредов |

**Критический анализ**:

1. **Accuracy >65%**: Метрика некорректна для дисбаланса. Тривиальный классификатор "всегда 0" даёт 95% accuracy.
   - Рекомендуемая метрика: **F1_minority > 0.50** или **Signal Precision > 0.50**

2. **Sharpe Ratio >1.5**: Невозможно оценить без бэктеста.
   - Для оценки нужна интеграция с MT4 и исторические котировки
   - При F1_minority ~0.40 и precision ~0.30 Sharpe >1.5 маловероятен

3. **Реалистичные цели при текущих данных**:
   - F1_minority: 0.45–0.50 (потенциальный потолок ~0.55)
   - Signal Precision: 0.40–0.45
   - Signal Recall: 0.50–0.60
   - Pearson r (регрессия): 0.60–0.65

## Рекомендации по торговым метрикам

Для реальной торговой системы важны не ML-метрики, а торговые:

| Метрика | Целевое значение | Как измерить |
|---------|------------------|--------------|
| **Win Rate** | >40% | Бэктест на test set |
| **Profit Factor** | >1.5 | Gross profit / Gross loss |
| **Sharpe Ratio** | >1.0 | (Return - Risk-free) / StdDev |
| **Max Drawdown** | <30% | Пик-просадка эквити |
| **Expectancy** | >0 | (Win% × AvgWin) - (Loss% × AvgLoss) |
| **Signal Precision** | >0.50 | TP / (TP + FP) для сигнальных классов |

**Рекомендация**: После достижения F1_minority > 0.45 переключить фокус на бэктест и торговые метрики.

## Заключение

### Главный вывод

Текущий подход (прямая 3-классовая классификация) **не работает** при дисбалансе 95%/2.5%/2.5% и ~1000 сигнальных примеров. Все архитектуры упираются в один потолок (~0.57 macro F1, ~0.35 F1_minority), что указывает на **фундаментальное ограничение данных**, а не архитектуры.

### Рекомендуемый путь

1. **Быстрые победы** (1–2 дня): Усилить Focal Loss + WeightedSampler → потенциал до 0.42–0.45 F1_minority
2. **Двухэтапный подход** (3–5 дней): Разделить детекцию сигнала и оценку направления
3. **Если не работает**: Перейти к feature engineering или собрать больше данных

### Честная оценка потолка

При текущем объёме и качестве данных:
- **Реалистичный потолок F1_minority**: 0.50–0.55
- **Реалистичный потолок Signal Precision**: 0.45–0.50
- **Sharpe Ratio**: Скорее всего <1.0 при текущем качестве

Для достижения MVP-целей (Sharpe >1.5) потребуется либо значительное улучшение признаков, либо 3–5x больше сигнальных данных.
