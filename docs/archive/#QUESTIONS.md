## описание проекта
я работаю над большим проектом SoSimple
Ознакомься: AGENTS.md
[Тут](docs/reports) находятся отчеты по проведенным исследованиям/разработкам ,  хотя начал вести его совсем недавно, по сути это воркфлоу проекта.
Файл CHANGELOG.md содержит короткие выжимки отчетов со ссылками на отчеты.
файл MODULE_INDEX.md описывает все основные файлы проекта.
Проект включает py код, md отчеты, планы, csv таблицы (нет в гите), mql библиотеки, и т.д.
Сейчас я (единственный разработчик) работаю над проектом с двух компьютеров на VSC (расширения codex,claude code), синхронизируя через github.

## проблема и предполагаемое решение
основная проблема ии агентов в малой памяти контекста. Для компенсации этого недостатка нужно для каждого проекта делать свою википедию с индексом. К этой википедии ии агент будет обращаться при ответе и пополнять ее. Так называемый 'second brain'.
Эту проблему решает [метод LLM Wiki](wiki/LLM Wiki_method.md)
Таким образом, создание вики позволит не заблудиться в разросшемся проекте мне самому, и облегчить агентам работу с проектом.

## мои предостережения и домыслы
Насколько я понимаю описание метода, кактлог raw/ должен содержать всю информацию о проекте, но это и есть весь проект SoSimple.
Проект уже имеет отличную базу :
docs/reports/ — готовые канонические отчёты (это почти готовый ingest-материал).
CHANGELOG.md — хронологический лог.
MODULE_INDEX.md — живой index модулей.
AGENTS.md + CLAUDE.md + CONTEXT_HANDOFF.md + .claude/memory/ — уже существующая схема (schema) для агентов.
Поэтому не хотелось бы ломать текущую структуру и не дублировать файлы (а это огромная база кода и  документации) в отдельный каталог 'raw/' в составе того же проекта.
Единсвтенное замечание: В LLM Wiki методе  'raw/' — это immutable источники, а в моем проекте как py файлы, так и md документация подвержены изменениям.
Поэтому я предлагаю дополнить LLM Wiki метод индексацией, описанной тут: wiki/wiki_index_method.md
