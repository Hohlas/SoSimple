фиксируется по привязке времени закрытия баров к UTC-эталону и замораживается до
анализа. Сравнение цен разных источников без конвенции запрещено.

## Карточки направлений

### Н1. Фандинг-кэрри на perp-DEX (шорт-перп + спот-хедж)

1. **Механизм**: плечевые лонги платят за синтетический долг; базовая ставка
   фандинга — аналог ставки денежного рынка в крипто. Кто платит: спрос на
   левередж (лонгисты с плечом). Почему арбитражный капитал не убивает премию:
   спот-нога требует ончейн-кастоди и стейблкоинов, банковские рельсы ⇄ USDC
   медленные, риск контрагента/смарт-контрактов; институциональный капитал не
   может держать ончейн-спот без операционной перестройки. Метрика тесноты:
   спред фандинга между площадками; предсказание — рост капитала basis-трейдеров
   сжимает премию к базе 0.01%/8 ч.
2. **Тип**: кэрри. Ноги разной природы (перп + спот); схождение обеспечивает сам
   фандинг (ежечасно). Истинным арбитражем не является.
3. **Масштаб**: начисление непрерывное (ежечасное), удержание дни–недели — в окно
   проекта попадает с запасом.
4. **Издержки**: RT хеджированной позиции: перп 0.09% + спот 0.14% (HL) или
   ~0.2% (CEX) + ввод/вывод → ~0.2–0.3% **[Ф: тарифы HL; Г: итог]**. База
   фандинга 0.03%/день: безпремиальный сценарий окупается ~7–10 суток;
   premium-эпизоды быстрее. **Гейт**: медианный дневной фандинг за окно ≥ RT/10
   при стрессе 2x.
5. **Фальсификация**: H0 — медиана (фандинг − издержки переноса) ≤ 0. Данные:
   публичные истории фандинга HL и CEX (BTC/ETH, 2–3 года). Статистика: медиана,
   доля отрицательных дней, стационарный бутстрэп по дням. Убивает: медиана
   нетто ≤ 0 или нижняя CI годового кэрри ≤ 0. Стоимость: 0.5–1 день, только
   публичные API (доступность эндпоинтов — первая задача).
6. **Мощность/переносимость**: N по дням ≥ 1000 — мощность достаточна **[Г]**;
   покрытие: HL с 2023 — ≥ 1 года с разными режимами волатильности есть, но один
   рынок-цикл; разрез по режимам обязателен. Смещение выживших: делистингнутые
   перпы из API исчезают — фиксировать списком.
7. **Новизна**: относительно индустрии отсутствует (basis-трейд в масштабе
   Ethena); для проекта — первый кандидат с доходом без предсказания знака.
   Проверка «почему не реализуют»: реализуют массово, премия сжимается — честно
   фиксируется как риск устойчивости эджа **[Г]**.
8. **Реализуемость**: USDC-капитал, аккаунт HL, спот-нога (HL spot / CEX / AMM);
   ёмкость ограничена глубиной спот-книги **[Г]**. Риск-оф-руин: депег USDC
   (прецедент 2023-03 **[Ф]**), ликвидация перп-ноги при скачке — маржинальный
   запас на обеих ногах; сессий/гэпов нет (24/7). ToS HL: фандинг peer-to-peer,
   запрета арбитража нет **[Ф, HL docs]**.
9. **Метки**: механизм и тарифы **[Ф: HL docs]**; сжатие премии, ёмкость **[Г/С]**.

### Н2. Кросс-площадочный базис крипто: CFD-брокер vs биржа/DEX

1. **Механизм**: один актив, изолированные пулы капитала (фиат-брокер vs
   USDC-контур). Кто платит: поток, которому нужна немедленность на «своей»
   площадке при расхождении цен. Почему капитал не приходит: перенос капитала
   между контурами — часы/дни; розничный CFD закрывается только против брокера;
   ToS брокеров дискриминируют арбитражных клиентов.
2. **Тип**: межплощадочный базис; **обе ноги — деривативы (CFD и перп) →
   торгуется схождение базиса/перенос, не истинный арбитраж**.
3. **Масштаб**: базис-эпизоды минуты–часы в волатильные окна **[Г]**; окно M5
   подходит.
4. **Издержки**: CFD-крипто спред у брокера **не зафиксирован — нужен снимок**;
   биржевая нога ~0.1–0.2% RT. Гейт не резолвится без снимка; априорный риск:
   розничные крипто-CFD спреды обычно широки → смерть по cost-гейту
   **[С → проверять первым шагом]**.
5. **Фальсификация**: H0 — медианный |базис| ≤ RT. Данные: параллельная запись
   котировок CFD (MT5) и биржи (API) ≥ 1–2 мес. с конвенцией таймстемпов §0.
   Убивает: медиана ≤ RT или N эпизодов с превышением < 100. Стоимость: снимок
   спецификаций + запись 1–2 мес.
6. **Мощность/переносимость**: N эпизодов за 1–2 мес., вероятно, < 100 →
   вердикт не выше DIAGNOSTIC_ONLY без более длинной записи **[честно: слабое
   место]**; режимное покрытие одной записи узко.
7. **Новизна**: низкая (классический cross-venue); для проекта новая. Проверка
   «почему не практикуют»: именно издержки и ToS — если гейт не проходит,
   «новизна» объясняется экономикой, а не незамеченностью.
8. **Реализуемость**: предразмещённый капитал на обеих площадках; риск-оф-руин:
   односторонний гэп CFD (остановка котирования), расширение спреда в
   волатильность, ликвидация биржевой ноги; **ToS брокера: возможный запрет
   арбитражных стратегий — снять текст до работы [флаг]**.
9. **Метки**: механизм **[Ф теоретический; Г для конкретных площадок]**;
   CFD-издержки **[неизвестно — требуется снимок]**.

### Н3. Фандинг-спред между площадками (HL vs CEX, один актив)

1. **Механизм**: одна и та же ставка переноса начисляется по разным книгам с
   разным составом клиентов. Кто платит: сторона с локальным перекосом плеча на
   площадке с более дорогим фандингом. Почему капитал не приходит: капитал нужно
   держать на обеих площадках одновременно (двойная маржа и кастоди), переводы
   медленные. Метрика тесноты: спред фандингов между площадками; предсказание —
   при упрощении переводов спред сжимается.
2. **Тип**: кэрри/перенос; **обе ноги деривативы → торгуется разница фандингов
   ± схождение баз, не истинный арбитраж**.
3. **Масштаб**: ставки обновляются ежечасно (HL) / каждые 8 ч (CEX); удержание
   дни — окно проекта подходит.
4. **Издержки**: 4 комиссии ≈ 0.18% RT суммарно **[Ф: HL; CEX — снимок при
   декомпозиции]**; нормальный фандинг-спред ~0–2 бп/8 ч → pass возможен только
   на хвостах **[Г]**.
5. **Фальсификация**: H0 — медиана часового спреда фандингов ≤ издержки на
   горизонт удержания. Данные: публичные API обеих площадок, ≥ 2 года, BTC/ETH.
   Убивает: медиана нетто ≤ 0; N дней с превышением < 100. Стоимость: 0.5–1 день.
6. **Мощность/переносимость**: N по дням ≥ 700; покрытие ≥ 2 лет с разными
   режимами; конвенция фандинг-меток HL (UTC-час) vs CEX — обязательна. Делистинг
   — смещение выживших, фиксировать списком.
7. **Новизна**: низкая (мониторится basis-десками); для проекта новая.
8. **Реализуемость**: капитал на двух площадках; риск-оф-руин: ликвидация одной
   ноги при волатильности → маржинальный запас на обеих; таймстемпы — по
   конвенции §0.
9. **Метки**: тарифы HL **[Ф]**, CEX **[Г до снимка]**, величина спреда **[Г]**.

### Н4. Ликвидационные каскады на perp-DEX: возврат после перелёта

1. **Механизм**: маржинальные ликвидации — механические продавцы без свободы
   выбора цены; перелёт ниже «справедливого» уровня покупается поставщиками
   ликвидности. Кто платит: ликвидируемый (PnL списан по худшей цене) и
   опоздавший тейкер. Почему капитал не приходит: вкладываться в «поимку ножа»
   можно только с робастным риск-менеджментом (stop-hunt выносит и арбитражёра);
   ёмкость эпизода мала для фондов — метрика тесноты: глубина книги в каскаде;
   предсказание: при росте глубины перелёт сжимается.
2. **Тип**: структурные события (ликвидации/ADL).
3. **Масштаб**: эпизоды минуты–часы; крупные кластеры — десятки/год на актив
   **[Г]**; окно M5 подходит, удержание часы–сутки.
4. **Издержки**: RT 0.09% **[Ф: HL]** + проскальзывание в каскаде (неизвестно —
   мерить по книге/сделкам); амплитуда перелётов **[С до измерения]**.
5. **Фальсификация**: H0 — медианный возврат после кластера ≤ RT. Данные:
   публичные данные ликвидаций HL API (2023–2026), предварегистрированное
   правило кластера. Статистика: event-study с кластеризацией по эпизодам,
   стационарный бутстрэп. Убивает: медиана ≤ RT; N < 100; развал по годам.
   Стоимость: 1–2 дня.
6. **Мощность/переносимость**: N крупных каскадов за 3 года — вероятно,
   100–300 **[Г]**; покрытие один рынок-цикл; разрез по годам обязателен.
7. **Новизна**: эффект ликвидационных каскадов известен в литературе и практике
   (источники — списком на декомпозиции **[флаг]**); для проекта нов.
   «Почему не практикуют»: практикуют (мейкинг в каскадах) — конкуренция за
   проскальзывание; ёмкость ограничена.
8. **Реализуемость**: аккаунт HL + USDC; риск-оф-руин: продолжение каскада →
   стоп-дисциплина и маржинальный запас; ADL принудительно закрывает выигрышную
   ногу против каскада — учитывать в риске. Таймстемпы — биржевой UTC.
9. **Метки**: механизм **[Ф теорет.; Г на данных HL]**; амплитуды **[С]**.

### Н5. Уикенд-базис золота: 24/7 обёртки vs CFD 5/8

1. **Механизм**: XAU-CFD торгуется 5/8-сессию; обёртки (PAXG и подобные) — 24/7.
   В выходные рынок один и тонкий. Кто платит: срочный уикенд-продавец (маржин-колл,
   новостной сброс) — покупатель забирает премию немедленности. Почему капитал
   не приходит: ончейн-нога (газ, кастоди), оракул-риск тонких инструментов,
   ёмкость выходного окна мала. Метрика тесноты: глубина уикенд-книги;
   предсказание: при росте глубины премия сжимается.
2. **Тип**: сессионные разрывы; при CFD vs gold-перпе **обе ноги деривативы →
   торгуется перенос базиса через выходные, не истинный арбитраж**.
3. **Масштаб**: 52 эпизода/год (уикенды) + праздники; удержание через окно
   2–3 суток — в пределах окна проекта.
4. **Издержки**: CFD XAUUSD 0.23 USD **[Ф: снимок]**; ончейн RT (спред + газ)
   ~0.3–1% **[С — зависит от площадки]**; суммарный RT ~0.4–1.2% **[Г]**.
   Амплитуда уикенд-движений золота: спокойные окна 0–0.3%, стресс > 1% **[Г]**.
5. **Фальсификация**: H0 — медианный уикенд-базис ≤ RT. Данные: публичная
   история обёрток (≥ 2 лет **[Ф: CoinGecko/биржи]**) vs пятница-закрытие /
   понедельник-открытие CFD (наш MT5); конвенция таймстемпов §0. Убивает: медиана
   ≤ RT; N < 100; стресс 2x. Стоимость: 1–2 дня.
6. **Мощность/переносимость**: N ≈ 104 уикенда за 2 года — впритык к гейту
   N ≥ 100 **[Г]**; покрытие: один режим-цикл золота; разрез по режимам
   (спокойные/стрессовые уикенды) обязателен.
7. **Новизна**: средняя; уикенд-эффекты крипты документированы **[флаг:
   источники на декомпозиции]**; для золота через обёртки малоисследовано
   **[С]**. «Почему не практикуют»: теснота уикенд-книги — метрика определена,
   проверяется напрямую.
8. **Реализуемость**: ончейн-капитал/кастоди; наличие gold-перпа на HL и
   мостовых вариантах PAXG — проверить API первым шагом **[флаг]**. Риск-оф-руин:
   понедельник-гэп CFD против ноги, оракул-девиация тонкого перпа; маржинальный
   запас на обеих ногах.
9. **Метки**: тариф CFD **[Ф: снимок]**; ончейн издержки, амплитуды **[Г/С]**.

### Н6. Фиксинг-дрейф FX (оконные метки концентрированного потока)

1. **Механизм**: институциональные клиенты исполняют большие объёмы по
   бенчмаркам (Лондон 16:00, Токио 09:55); перед меткой поток однонаправлен,
   после метки — частичный возврат. Кто платит: клиент, обязанный исполниться по
   метке (регуляторные/операционные ограничения). Почему арбитражный капитал не
   убивает: last look, банковские лимиты, мелкий масштаб дрейфа против
   издержек.
2. **Тип**: сессионные разрывы (поток-эффект, не арбитраж в строгом смысле).
3. **Масштаб**: метки ежедневны; дрейф в окне ±30 мин вокруг метки; удержание
   минуты–часы — идеально для окна M5.
4. **Издержки**: RT 0.2–0.4 пипса (спред 0.1–0.2 пипса на ногу **[Ф: снимок]**)
   + проскальзывание; величина дрейфа на наших данных **[Г — измеряется]**.
   **Гейт**: медианный нетто-дрейф > RT.
5. **Фальсификация**: H0 — медианный дрейф после издержек ≤ 0. Данные: **уже в
   репо** — M5 EURUSD/GBPUSD/USDCHF/USDJPY-класс 2005–2026 (~5 000 окон/год).
   Статистика: знаковый тест по дням + стационарный бутстрэп; конвенция
   DST/серверного времени фиксируется до расчёта. Убивает: медиана нетто ≤ 0;
   PF < 1.3 / BS_p05 ≤ 1.0; N < 100. Стоимость: 0.5–1 день, без новых данных.
6. **Мощность/переносимость**: лучшая в наборе — N огромно, покрытие ~20 лет и
   несколько режимов (2008, 2011–2015 SNB, 2022–2023 перелом) **[Ф: окна из
   наших данных]**; разрез по режимам — прямой. Смещения выживших нет.
7. **Новизна**: эффект документирован (BIS FXWG, обзоры бенчмарков 2018
   **[Ф: BIS]**; академические источники — списком на декомпозиции); в проекте
   никогда не проверялся **[Ф: best_ideas/роэдмап]**. «Почему не практикуют»:
   практикуют банки; вопрос — остаётся ли дрейф после розничных издержек. Это и
   есть H0.
8. **Реализуемость**: контур уже существует (те же символы, MT5); риск-оф-руин
   минимальный (одна нога, стопы, удержание внутри дня); ToS-риск низкий
   (календарные стратегии обычно не преследуются) **[С]**.
9. **Метки**: издержки и документированность **[Ф]**; величина дрейфа на наших
   данных **[Г до замера]**.

### Н7. Своп-ножницы розничного брокера (миспрайсинг своп-пойнтов)

1. **Механизм**: своп-пойнты брокера должны отражать покрытый процентный паритет
   (ПКП); при ошибках/задержках обновления возникает положительный кэрри против
   брокера. Кто платит: брокер (его прайсинговая ошибка). Почему капитал не
   приходит: прибыль изымают (клоубэк), аккаунты банят — премия существует из-за
   ToS-риска, а не «незамеченности».
2. **Тип**: кэрри (одна нога — против брокера; хедж второй площадкой = перенос).
3. **Масштаб**: ошибки — редкие эпизоды, живут дни **[Г]**; удержание
   ночи–недели.
4. **Издержки**: RT 0.2–0.4 пипса **[Ф: снимок]**; гейт: своп-дельта ≥ RT за
   типичное удержание.
5. **Фальсификация**: H0 — текущие свопы всех символов MT5 отклоняются от ПКП не
   больше, чем на издержки. Данные: снимок свопов (ExportSymbolSpecs-класс) +
   ставки центробанков (публично). Убивает: положительных расхождений нет;
   N эпизодов/год < 30 → навсегда DIAGNOSTIC_ONLY **[Г]**.
6. **Мощность/переносимость**: N мала — слабое место; истории свопов брокера за
   20 лет нет → переносимость непроверяема.
7. **Новизна**: низкая; известная розничная практика, брокеры её чинят. Случай,
   когда «новизна» объясняется правовыми причинами — вскрывается явно.
8. **Реализуемость**: дёшево (снимок + сравнение), но торговля — риск
   клоубэка/бана аккаунта **[С]**; ёмкость мала; двухногие конструкции упираются
   в single-position policy **[Ф]**.
9. **Метки**: механизм ПКП **[Ф]**; частота ошибок **[С]**.

### Н8. Оракул-лаг тонких перпов (возврат перп → оракул)

1. **Механизм**: маркировка, ликвидации и фандинг считаются по оракулу
   (медиана CEX-спота, обновление частое), а последняя цена перпа уходит при
   тонкой книге; возврат к оракулу механический. Кто платит: импульсный поток,
   переплачивающий за немедленность в тонкой книге. Почему капитал не приходит:
   возврат живёт секунды–минуты — нужна низколатентная инфраструктура;
   достаётся ботам на самой площадке.
2. **Тип**: оракул-лаг / латентностный.
3. **Масштаб**: half-life секунды–минуты **[Г]**; риск непопадания в окно M5 —
   измерить первым шагом; если медианный возврат < 5 мин — карточка мертва по
   окну проекта.
4. **Издержки**: RT 0.09% **[Ф: HL]** + проскальзывание тонкой книги;
   амплитуда девиаций **[С до измерения]**.
5. **Фальсификация**: H0 — медианный |perp − oracle| ≤ RT ИЛИ half-life
   возврата < окна решения M5 (двойной kill). Данные: публичные HL API
   (оракул-миды и сделки), ≥ 6 мес. Убивает: любой из двух исходов.
   Стоимость: 1–2 дня.
6. **Мощность/переносимость**: N девиаций велико; история короткая, режимов
   скудно — переносимость слабая.
7. **Новизна**: низкая (известная механика DEX-мейкинга); для проекта нов.
   «Почему не реализуют»: реализуют инсайдеры площадки с низкой латентностью —
   честно: наш ~5-секундный MT5-контур здесь бесполезен **[Г: латентность §0]**.
8. **Реализуемость**: kill-test дёшев; торговля требует API-исполнения на самой
   площадке (не MT5) — приобретение инфраструктуры; риск-оф-руин: продолжение
   девиации против позиции, ADL.
9. **Метки**: механика оракула **[Ф: HL docs]**; частоты **[Г]**.
