## 3b. Feature Selection Gate

### Цель

Минимизировать набор признаков до информативных, исключив шумовые, коррелированные и производные. Применяется после Leakage Gate (п.3) — только к live-safe признакам.

### Когда применять

- Перед обучением любой модели (baseline и выше).
- При добавлении новой группы признаков.
- После feature engineering (агрегаты, окна, производные).
- Если число признаков > 50 — обязательная проверка на переобучение.

### Пошаговые действия

1. **Корреляционный фильтр (до обучения).**
   - Построить матрицу корреляций (Pearson) на train-выборке.
   - Для каждой пары с |r| > 0.95: удалить один признак (менее информативный или производный).
   - Повторять пока есть пары с |r| > 0.95.
   - Результат: список удалённых признаков и причина (с каким скоррелирован).

2. **Фильтр важности (после RF).**
   - Обучить RF (`n_estimators=100, max_depth=10, random_state=42`) на train.
   - Извлечь `feature_importances_`.
   - Признаки с вкладом < 0.5% от суммарной важности — кандидаты на удаление.
   - Переобучить без них, сравнить validation PF.
   - Если PF не упал более чем на 0.03 — удалить. Если упал — оставить.

3. **Обязательная абляция групп.**
   - Для каждой группы признаков (>5 шт. в группе):
     - Обучить модель без группы.
     - Сравнить validation PF с baseline (модель на полном наборе).
   - Без улучшения (> +0.03 PF) группа не принимается — удалить.
   - Абляционный протокол: см. `08-model-development.md:59-88`.

4. **Правило производных признаков.**
   - Если признак B полностью вычисляется через признак(и) A: B = f(A), то A и B не должны использоваться вместе.
   - Примеры:
     - `Pwr = min(Frnt, Back)` → оставить `Frnt` и `Back`, удалить `Pwr`.
     - `Strong = f(back, front, break)` → оставить исходные, удалить `Strong` (кроме случаев, когда Strong доказанно добавляет сигнал через абляцию).
     - Признаки-ratio: если A/B уже во входе, не добавлять отдельно A и B если они не несут независимого сигнала.

5. **Принцип минимальности.**
   - Новый признак принимается только если его удаление ухудшает validation-метрику (PF, directional accuracy) статистически значимо.
   - Группа признаков принимается только если её добавление улучшает validation PF ≥ 0.03 относительно baseline без группы.
   - Исключение: engineered-признаки, не прошедшие абляцию → удалить, даже если полный набор проходит gate (шум маскирует сигнал).

### Обязательные проверки

- Корреляционная матрица вычислена на train, а не на всём датасете.
- Абляция выполнена на validation, выводы не подогнаны под test.
- Если удаление группы не меняет PF — группа шумовая, удалить.
- Если engineered-признаки как целое не улучшают baseline, но отдельная группа улучшает — оставить только группу, удалить остальные.
- Производные признаки исключены из входа (или доказана их независимая полезность через абляцию).

### Критерии успешного завершения

- Нет пар признаков с |r| > 0.95.
- Все признаки имеют важность ≥ 0.5% (или доказано исключение).
- Каждая группа признаков прошла абляцию или удалена.
- Производные признаки либо удалены, либо имеют documented justification.
- Итоговый набор признаков минимален: удаление любого признака ухудшает validation-метрику.

### Типовые ошибки

- Пропустить корреляционный фильтр и обучить модель на дублирующих признаках.
- Использовать feature importance из модели, обученной на всех данных включая test.
- Принять группу признаков без абляции потому что «полный набор прошёл gate».
- Оставить производный признак вместе с исходным без проверки.
- Утвердить engineered-признаки без сравнения с flat baseline.
- Использовать `ret_dir_atr_lag1` как признак (смотрит в будущее, см. leakage gate).

### Ветвления

- Если после всех фильтров осталось < 5 признаков: данных недостаточно для ML, пересмотреть feature engineering.
- Если корреляционный фильтр удалил > 50% признаков: проблема мультиколлинеарности, пересмотреть способ построения признаков.
- Если абляция показывает что все engineered-группы бесполезны: использовать только flat features + возможно пересмотреть способ агрегации.
