## 7b. Predictability Gate — проверка предсказуемости до обучения

### Цель

До дорогого обучения проверить, несёт ли набор признаков предсказательную силу
для данного target. Если не несёт — набор отклоняется, обучение не проводится.
Экономит вычисления и защищает от интерпретации шума как сигнала.

Решение об отклонении принимает **только совместный RF-гейт**. MI-скрининг —
опциональная диагностика: он не вправе отклонять набор, потому что меряет
фичи по отдельности и пропускает взаимодействия.

### Входы

- данные гейта: **train** (по умолчанию) либо **train + validation** —
  когда нужна большая выборка для слабых сигналов; см. «Данные гейта»;
- `locked_test`/test в гейте не участвуют **никогда**;
- target contract и `decision_time` (зафиксированы в Leakage Gate п.3,
  см. `00-research-management.md`);
- проверяемый набор признаков (live-safe относительно `decision_time`,
  после Leakage Gate п.3). Если `03b-feature-selection.md` уже выполнен —
  проверяется итоговый (минимальный) набор; если нет — полный live-safe
  набор. В отчёте раскрыть, какой именно набор проверялся.

### Данные гейта

- По умолчанию гейт считается на train: вердикт относится к распределению,
  на котором модель будет обучаться.
- Допускается train + validation: validation в проекте — рабочий выборочный
  датасет (`val-select`/`val-stop`, см. `06-temporal-split.md`,
  `09-validation-freeze.md`), а защищённый «один выстрел» — `locked_test`.
  Плюс: рост выборки (мощность против ошибки второго рода) и вердикт сразу
  про оба режима. Оговорки: вердикт относится к смешанному распределению;
  многократное переиспользование validation накапливает адаптивное смещение
  (Dwork et al., 2015), которое гасится нетронутым `locked_test`.
- В отчёте фиксировать, на каких данных посчитан гейт.

### Пошаговые действия

1. **Совместный RF-гейт (обязательная проверка набора целиком).**
   - Random Forest: значения по умолчанию проекта `n_estimators=100,
     max_depth=10, random_state=42`; при дисбалансе классов target добавить
     `class_weight='balanced'`. Менять значения по умолчанию допускается при
     обосновании; фактический полный список параметров фиксируется в отчёте
     и JSON-артефакте. Данные гейта — **walk-forward CV по времени**,
     расширяющееся окно (`TimeSeriesSplit`; число фолдов подобрать по объёму
     выборки, чтобы размер фолда проходил sample size gate из
     `06-temporal-split.md`; перемешивание строк запрещено). Вердикт — по
     агрегированному скору всех фолдов против перестановочного фона, а не по
     одному окну.
   - Статус реализации: отдельного модуля пока нет; прогон выполняется
     скриптом по этой спецификации, путь к скрипту указывается в отчёте.
   - Связь с `03b-feature-selection.md` шаг 2: конфигурация RF та же, но
     задача другая (фильтр важности отдельных фич vs предсказуемость набора
     целиком). Переиспользовать один прогон допустимо только при совпадающей
     схеме CV; иначе прогон отдельный.
   - Нормализация признаков для RF не нужна (деревья инвариантны к
     масштабу); для MI непрерывные фичи получают z-score, посчитанный по
     данным гейта (аффинное преобразование MI не меняет, но стабилизирует
     kNN-метрику), а дискретные (например, час, день недели) идут без
     нормализации, с discrete-маской.
   - Перестановочный тест: тот же RF на target со случайно перемешанными
     значениями (временной порядок сохранён), сравнение скор.
   - Метод ловит взаимодействия признаков и отвечает на вопрос
     «предсказуемо ли это вообще».

   **Нестандартный вход (последовательности, окна и т.п.).** Гейт проверяет
   сигнал в данных, а не архитектуру, поэтому любой вход приводится к
   табличному виду: плоский вектор, окно из W шагов по F признаков,
   сплющенное в вектор длиной W×F, либо агрегированные статистики окна
   (принцип «честного сравнения», см. `07-baseline-first.md`). Пример —
   вход Transformer/LSTM. Оговорки:
   - плоский RF консервативен: глубинные временны́е паттерны (порядок,
     фаза), которые извлекает внимание, деревья могут недооценить;
     FAIL при сильной гипотезе «сигнал именно в порядке шагов» — не
     автоматический reject, а зафиксированное в отчёте исключение;
   - при больших W дешевле агрегировать окно до статистик (mean/std/
     последнее значение по каждой фиче) и прогнать RF на коротком векторе;
     это ослабленная версия проверки, помечать её как таковую;

2. **MI-скрининг (опционально, диагностика).**
   Когда полезен: кандидатов много и хочется дешёвый предпросмотр; нужно
   понять, какая фича несёт сигнал; нужен ориентировочный R²-потолок.
   - Запустить `statistics/mi_upper_bound.py` на train: маргинальное MI
     каждой фичи с target + среднее и максимум по набору, перестановочный
     p-value (минимум 200 перестановок — как в spec и коде;
     p_min = 1/(n_perm+1): при 200 перестановках 1/201 ≈ 0.005).
   - Ограничения (фиксировать в отчёте):
     - маргинальное MI не видит взаимодействий (пример XOR: каждая фича
       по отдельности без сигнала, но target восстанавливается только их
       комбинацией): FAIL скрининга не означает отсутствие сигнала в наборе;
     - среднее маргинальное MI — диагностическая величина, не строгая
       граница совместной информации;
     - прямое joint-MI ненадёжно, когда размерность велика относительно
       объёма выборки (пример проекта: 42 признака при ~41K строк train,
       см. `docs/superpowers/specs/2026-08-11-mi-upper-bound-design.md`).
       Если всё же нужен joint-MI: редуцировать размерность — топ-k фич
       (k ≤ 5 по маргинальному MI), PCA-компоненты, групповое MI по
       семействам — и подтверждать перестановочным тестом.
   - Результат MI-скрининга не является основанием для reject. В отчёте его
     вердикты помечать префиксом `mi_screening` (например,
     `mi_screening: PASS`), чтобы не путать с вердиктом RF-гейта.

3. **Фиксация результата.**
   - RF-гейт сохраняется как structured artifact (JSON): состав набора,
     параметры RF и CV, скоры оригинала, перестановочный фон, p-value,
     n_permutations, вердикт. Числа в отчёте сверяются с JSON
     (см. `16-reporting-audit.md`).
   - Вердикт RF-гейта, p-value, параметры RF и CV, число проверенных наборов
     — в отчёт эксперимента (формат: `16-reporting-audit.md`).
     Если MI-скрининг запускался — его JSON и per-feature рейтинг тоже.

### Критерии прохождения

- **Отклонить набор без обучения** — только если совместный RF-гейт:
  p ≥ 0.05 против перестановочного фона.
- RF-гейт PASS → набор проходит, далее обычное обучение.
- Если RF-гейт FAIL на малой выборке, это может быть ошибка второго рода:
  до окончательного reject проверить стабильность — минимум 5 seeds и
  чувствительность к размеру train. Правило: результат устойчив, если
  большинство seeds дают одинаковый вердикт; при смешанной картине —
  расширить данные гейта или понизить статус до `DIAGNOSTIC_ONLY`.
- Диагностический R²-потолок из MI ниже лучшего исторического R² target —
  не reject, а предупреждение: прошлые результаты target под вопросом,
  поднять аудит их источников.

### Обязательные проверки

- Гейт посчитан на train либо train + validation; `locked_test`/test не
  использованы; данные гейта раскрыты в отчёте.
- Walk-forward CV, не случайное перемешивание (временные ряды).
- Число перестановок зафиксировано и отражено в минимально достижимом p.
- Если проверялось несколько наборов (N штук) — раскрыть их число и применить
  поправку: PASS засчитывается только при p < 0.05/N (Бонферрони); без
  поправки статус результата не выше `DIAGNOSTIC_ONLY`
  (multiple testing, см. `16-reporting-audit.md`, `09-validation-freeze.md`).
- Артефакты приложены к отчёту.

### Типовые ошибки

- Прогонять гейт на `locked_test`/test — утечка в финальную оценку.
- Отклонять набор по MI-скринингу: он не видит взаимодействия и может
  «выплеснуть ребёнка с водой».
- Читать маргинальное MI как верхнюю границу возможностей набора.
- Считать joint-MI при размерности, большой относительно выборки
  (пример: 42 признака при ~41K строк), и доверять ему.
- Отклонять набор по p ≈ 0.1 на малой выборке без проверки мощности.
- Не сохранять результаты: следующий цикл не узнает о reject.

### Ветвления

- RF-гейт FAIL (подтверждён по seeds/выборке) → набор отклонён, обучение
  запрещено; сформулировать гипотезу нового набора
  (post-mortem: `A5-post-mortem-diagnostics.md`).
- RF-гейт PASS → далее `07-baseline-first.md` и обычное обучение.
- RF-гейт PASS, но R²-потолок MI ниже исторического R² target → пройти
  дальше с аудитом источников прошлых метрик.
