# A6. Fractal Feature Profile Catalog

## Цель

Сохранить каталог вариантов представления фракталов, которые уже встречались в исследованиях SoSimple или прямо поддержаны кодом. Этот файл не является разрешением запускать все варианты сразу. Он нужен, чтобы при планировании нового этапа не забывать доступные варианты и заранее ограничивать матрицу экспериментов.

Главное правило: каждый профиль признаков должен пройти обычные проверки из `03-feature-contract-leakage.md`, `03b-feature-selection.md`, `08-model-development.md` и `09-validation-freeze.md`. Каталог описывает идеи, а не доказывает их качество.

## Как применять

1. До обучения выбрать небольшую матрицу профилей: обычно 3-6 вариантов.
2. Для каждого профиля заранее описать:
   - какие фракталы попадают во вход;
   - какие поля используются;
   - как обрабатывается переменная длина: padding, mask или агрегаты;
   - какие признаки являются контрольными, а какие проверяют основную гипотезу.
3. Зафиксировать search budget: число профилей, таргетов, seed, порогов и торговых правил.
4. Не добавлять новый профиль после просмотра validation/test результата без отдельного статуса `DIAGNOSTIC_ONLY`.

## Варианты отбора фракталов

| Профиль | Смысл | Где встречался | Методический статус |
|---|---|---|---|
| `all100` | Все `fractal0..fractal99` в исходном порядке строки | Stage 1-4 Fractal Stop, `ML/data_loader.py` | Базовый профиль для сравнения |
| `newest_N` | Только N свежих фракталов: например 10, 20, 50, 100 | Старые `seq_len` эксперименты, `data_loader.py`, take/skip matrices | Полезен для проверки, нужен ли дальний хвост |
| `nearest_k` | K фракталов, ближайших по цене к `fractal0`, кроме самого `fractal0` | `ML/fractal_level_feature_builder.py`, entry-path исследования | Хороший компактный кандидат, особенно `k=4/6/8/16` |
| `corridor_Xatr` | Все фракталы внутри ценового коридора `±X*ATR` от `fractal0.price` | Идея для Stage 5.0 и последующих Transformer-этапов | Основной кандидат для проверки рыночной картины вокруг уровня |
| `zones_atr` | Агрегаты по ATR-зонам выше/ниже `fractal0` | `build_zone_features()` | Контрольный агрегированный профиль |
| `zones_plus_nearest_k` | ATR-зоны плюс ближайшие K фракталов | `build_fractal_level_features(input_family="zones_plus_nearest_k")` | Контроль: сочетает локальную плотность и конкретные уровни |

## Рекомендуемые коридоры ATR

Для профиля `corridor_Xatr` не использовать слишком узкий основной диапазон `1-3 ATR`, если цель - увидеть рыночную структуру, а не только ближайший стоповый кластер. Такой коридор может оставить мало фракталов и превратить Transformer в модель почти без контекста.

Базовая сетка для новых исследований:

| Коридор | Назначение |
|---|---|
| `corridor_5atr` | Локальная структура вокруг `fractal0`, но шире, чем микрозона стопа |
| `corridor_10atr` | Основной рабочий вариант: баланс между локальностью и рыночным контекстом |
| `corridor_15atr` | Широкая картина рынка вокруг уровня |

Меньшие зоны `0.25/0.5/1/2/4 ATR` можно использовать как агрегаты `zones_atr`, но не как единственный sequence-вход, пока не доказано, что заполненность достаточна.

Обязательные проверки для `corridor_Xatr`:

- распределение числа фракталов на строку: p5, p25, median, p75, p95;
- доля строк с 0, 1, 2, 3+ фракталами после отбора;
- отдельно BUY/SELL и H6/H12, если профиль используется в Fractal Stop;
- padding/mask не должен превращаться в главный сигнал модели;
- порядок токенов должен быть зафиксирован: по расстоянию к `fractal0`, по свежести или отдельные группы выше/ниже.

## Варианты состава полей

| Профиль | Состав | Смысл | Ограничения |
|---|---|---|---|
| `base10` | `price`, `direction`, `front`, `back`, `strong`, `break`, `reverse`, `power`, `count`, `impulse` | Минимальная база Stage 1-4 | `price` желательно проверять в raw и relative вариантах |
| `full29` | Полный tensor из `ML/data_loader.py`: базовые поля плюс `ATR_ratio`, time-поля, `shift`, distance-in-ATR | Расширенный sequence-вход | Требует строгого feature contract |
| `geometry_only` | Геометрия без `up_*`/`dn_*` | Проверяет, есть ли сигнал в структуре уровней без исторической реакции цены | Старые direct-direction тесты не дали устойчивого преимущества |
| `relative_price` | Цена как `(price_i - price_0) / ATR` | Убирает абсолютный ценовой режим | В Stage 3.1 сам по себе ухудшил RF, но для Transformer остаётся разумным контролем |
| `distance_atr` | Signed/absolute/direction-weighted distance от `fractal0` | Явно кодирует расположение уровня относительно текущего | Не дублировать без абляции с `relative_price` |
| `shift_age` | Возраст фрактала в барах: `shift`, `log_shift`, `delta_shift` | Старые и свежие уровни могут пробиваться по-разному | Проверять отдельно, не смешивать вслепую с десятками path-полей |
| `atr_ratio` | `fractal_atr / current_ATR` или `log(fractal_atr / current_ATR)` | Учитывает смену волатильности с момента формирования уровня | В Stage 3 проверялся в смеси, отдельный эффект не доказан |
| `mov_h` | Свернутое движение: для пика использовать движение вниз, для впадины вверх | Убирает шумовые нули из пары `up_h/dn_h` | В составе `base_plus_path` ухудшил RF, но не проверен как компактный отдельный блок |
| `path_reaction` | Агрегаты реакции цены по окнам 5/10/20/50/100 и горизонтам 3/6/12/24/48 | Описывает историческую реакцию после старых уровней | Не подавать массово без абляции, риск шумовой размерности |
| `density` | Счётчики фракталов выше/ниже или внутри ATR-зон | Описывает скученность уровней вокруг `fractal0` | Stage 3.1 не показал самостоятельной пользы для RF |
| `time_control` | Час и день недели | Контроль календарного риска, а не фрактальный профиль | Если доминирует, модель может быть календарным фильтром |

## Варианты формы входа

| Форма | Описание | Когда применять |
|---|---|---|
| `flat_table` | Все признаки развёрнуты в один вектор | RF/XGBoost и быстрые baseline |
| `sequence_tokens` | Каждый фрактал - отдельный токен | Transformer, если важен порядок и взаимодействия уровней |
| `zone_tokens` | Каждый ATR-коридор или зона - отдельный токен с агрегатами | Когда нужно сохранить структуру выше/ниже уровня без 100 сырых фракталов |
| `hybrid_sequence_plus_row` | Sequence фракталов плюс row-level признаки | Transformer с ATR/time/density как отдельным контекстом |
| `multi_scale_summary` | Сводки по окнам 20/50/100 или 5/10/20/50/100 | Контроль, видит ли модель масштаб без полного sequence |

## Рекомендуемая стартовая матрица для Transformer

Не запускать всё сразу. Для Stage 5.0 или похожего этапа разумная стартовая матрица:

| Профиль | Что проверяет |
|---|---|
| `all100_base10` | Базовая последовательность всех фракталов |
| `all100_full29` | Даёт ли пользу расширенный контракт `data_loader.py` |
| `newest20_full29` | Достаточны ли только свежие фракталы |
| `nearest16_full` | Лучше ли ценовая близость, чем порядок свежести |
| `corridor_10atr_full` | Даёт ли широкий ATR-коридор вокруг `fractal0` лучший рыночный контекст |
| `corridor_5_10_15atr_ablation` | Ограниченная проверка ширины коридора: 5 против 10 против 15 ATR |
| `zones_plus_nearest16` | Контроль агрегатов зон плюс конкретные ближайшие уровни |

Если бюджет ограничен, сначала запускать:

1. `all100_base10`;
2. `all100_full29`;
3. `nearest16_full`;
4. `corridor_10atr_full`;
5. `corridor_5_10_15atr_ablation`.

## Интерпретация результатов

- Если `newest_N` лучше `all100`, дальний хвост вносит шум или модель не умеет его игнорировать.
- Если `nearest_k` лучше `newest_N`, ценовая близость важнее свежести.
- Если `corridor_10atr` лучше `nearest_k`, модели нужна широкая рыночная картина, а не только несколько ближайших уровней.
- Если `corridor_15atr` лучше `corridor_5atr`, локальный контекст слишком узкий.
- Если `zones_atr` лучше sequence-профилей, конкретный порядок фракталов не нужен, достаточно плотности и агрегатов.
- Если `time_control` близок к фрактальным профилям, нужен отдельный аудит календарного риска.

## Типовые ошибки

- Сравнивать `all100` и `corridor_Xatr` без отчёта о заполненности коридора.
- Использовать `1-3 ATR` как единственный коридор и сделать вывод, что “коридор не работает”, хотя туда попало слишком мало фракталов.
- Добавлять `path_reaction`, `shift`, `atr_ratio`, `density` одним большим блоком и потом считать, что каждый компонент вреден.
- Подбирать ширину коридора по test.
- Менять порядок токенов между train и live.
- Считать календарные признаки полноценной заменой фрактальной структуры.
