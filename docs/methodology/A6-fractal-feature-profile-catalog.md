# A6. Каталог вариантов представления фракталов

## Цель

Сохранить каталог вариантов представления фракталов, которые уже встречались в исследованиях SoSimple или прямо поддержаны кодом. Этот файл не является разрешением запускать все варианты сразу. Он нужен, чтобы при планировании нового этапа не забывать доступные варианты и заранее ограничивать матрицу экспериментов.

Главное правило: каждый профиль признаков должен пройти обычные проверки из `03-feature-contract-leakage.md`, `03b-feature-selection.md`, `08-model-development.md`, [A7 Feature Distribution Audit](A7-feature-distribution-audit.md) и `09-validation-freeze.md`. Каталог описывает идеи, а не доказывает их качество.

Для канонических определений feature-family, target-family и различия между "полем признака", "семейством признаков" и "представлением входа" использовать [A8-feature-target-catalog.md](A8-feature-target-catalog.md). Этот файл нужен прежде всего для планирования profile-матриц, а не как словарь всех терминов проекта.

## Как применять

1. До обучения выбрать небольшую матрицу профилей: обычно 3-6 вариантов.
2. Для каждого профиля заранее описать:
   - какие фракталы попадают во вход;
   - какие поля используются;
   - как обрабатывается переменное число фракталов;
   - какие признаки являются контрольными, а какие проверяют основную гипотезу.
3. Зафиксировать бюджет перебора: число профилей, таргетов, seed, порогов и торговых правил.
4. Не добавлять новый профиль после просмотра validation/locked_test результата без отдельного статуса `DIAGNOSTIC_ONLY`.
5. До обучения выполнить [A7 Feature Distribution Audit](A7-feature-distribution-audit.md), особенно для `corridor_Xatr`, `nearest_k`, `relative_price`, `no_price` и `time_control`.

## Варианты отбора фракталов

| Профиль | Смысл | Где встречался | Методический статус |
|---|---|---|---|
| `all100` | Все `fractal0..fractal99` в исходном порядке строки | Stage 1-4 Fractal Stop, `ML/data_loader.py` | Базовый профиль для сравнения |
| `newest_N` | Только N свежих фракталов: например 10, 20, 50, 100 | Старые `seq_len` эксперименты, `data_loader.py`, take/skip matrices | Полезен для проверки, нужен ли дальний хвост |
| `nearest_k` | См. определение в [A8](A8-feature-target-catalog.md) | `ML/fractal_level_feature_builder.py`, entry-path исследования | Хороший кандидат для проверки ценовой близости; для новых исследований проверять `k=20/40/60/80` |
| `corridor_Xatr` | См. определение в [A8](A8-feature-target-catalog.md) | Идея для Stage 5.0 и последующих Transformer-этапов | Основной кандидат для проверки рыночной картины вокруг уровня |
| `zones_atr` | См. определение в [A8](A8-feature-target-catalog.md) | `build_zone_features()` | Контрольный агрегированный профиль |
| `zones_plus_nearest_k` | См. определение в [A8](A8-feature-target-catalog.md) | `build_fractal_level_features(input_family="zones_plus_nearest_k")` | Контроль: сочетает локальную плотность и конкретные уровни |

## Рекомендуемые коридоры ATR

Для профиля `corridor_Xatr` не использовать слишком узкий основной диапазон `1-3 ATR`, если цель - увидеть рыночную структуру, а не только ближайший стоповый кластер. Такой коридор может оставить мало фракталов и превратить Transformer в модель почти без контекста.

Базовая сетка для новых исследований:

| Коридор | Назначение |
|---|---|
| `corridor_5atr` | Локальная структура вокруг `fractal0`, но шире, чем микрозона стопа |
| `corridor_10atr` | Основной рабочий вариант: баланс между локальностью и рыночным контекстом |
| `corridor_15atr` | Широкая картина рынка вокруг уровня |

Меньшие зоны `0.25/0.5/1/2/4 ATR` можно использовать как агрегаты `zones_atr`, но не как единственный вход из отдельных фракталов, пока не доказано, что заполненность достаточна.

Обязательные проверки для `corridor_Xatr`:

- распределение числа фракталов на строку: p5, p25, median, p75, p95;
- доля строк с 0, 1, 2, 3+ фракталами после отбора;
- отдельно BUY/SELL и H6/H12, если профиль используется в Fractal Stop;
- технические признаки заполнения не должны превращаться в главный сигнал модели;
- порядок фракталов во входе должен быть зафиксирован: по расстоянию к `fractal0`, по свежести или отдельные группы выше/ниже.

Если модель требует одинаковую длину входа, а в коридоре у разных строк разное число фракталов, нужно выбрать правило:

- если фракталов меньше нужного числа — недостающие места заполняются нулями или другим нейтральным значением;
- рядом передаётся служебный признак, какие места настоящие, а какие заполнены технически;
- если фракталов больше нужного числа — заранее фиксируется правило отсечения, например ближайшие по цене или самые свежие.

## Варианты состава полей

| Профиль | Состав | Смысл | Ограничения |
|---|---|---|---|
| `base10` | `price`, `direction`, `front`, `back`, `strong`, `break`, `reverse`, `power`, `count`, `impulse` | Минимальная база Stage 1-4 | `price` желательно проверять в raw и relative вариантах |
| `full29` | Полный набор из `ML/data_loader.py`: базовые поля плюс `ATR_ratio`, поля времени, `shift`, расстояние в ATR | Расширенный вход для модели | Требует строгого feature contract |
| `geometry_only` | Геометрия без `up_*`/`dn_*` | Проверяет, есть ли сигнал в структуре уровней без исторической реакции цены | Старые direct-direction тесты не дали устойчивого преимущества |
| `relative_price` | См. определение в [A8](A8-feature-target-catalog.md) | Убирает абсолютный ценовой режим | В Stage 3.1 сам по себе ухудшил RF, но для Transformer остаётся разумным контролем |
| `price_atr_scaled` | См. определение в [A8](A8-feature-target-catalog.md) | Диагностический контроль по масштабу цены | Не основной профиль по умолчанию; проверять вместе с `no_price` и `relative_price` |
| `distance_atr` | См. определение в [A8](A8-feature-target-catalog.md) | Явно кодирует расположение уровня относительно текущего | Базовое расстояние со знаком совпадает с `relative_price`; не дублировать без абляции |
| `shift_age` | См. определение в [A8](A8-feature-target-catalog.md) | Старые и свежие уровни могут пробиваться по-разному | Проверять отдельно, не смешивать вслепую с десятками признаков реакции цены |
| `atr_ratio` | См. определение в [A8](A8-feature-target-catalog.md) | Учитывает смену волатильности с момента формирования уровня | В Stage 3 проверялся в смеси, отдельный эффект не доказан |
| `mov_h` | Свернутое движение favorable/adverse по стороне уровня | Убирает шумовые нули из пары `up_h/dn_h` | В составе `base_plus_path` ухудшил RF, но не проверен как компактный отдельный блок |
| `path_reaction` | См. определение в [A8](A8-feature-target-catalog.md) | Историческая реакция после старых уровней | Не подавать массово без абляции, риск шумовой размерности |
| `density` | См. определение в [A8](A8-feature-target-catalog.md) | Описывает скученность уровней вокруг `fractal0` | Stage 3.1 не показал самостоятельной пользы для RF |
| `time_control` | См. определение в [A8](A8-feature-target-catalog.md) | Контроль календарного риска, а не фрактальный профиль | Если доминирует, модель может быть календарным фильтром |

## Варианты формы входа

Форма входа — это способ превратить строку CSV с `fractal0..fractal99` в числовой вход модели. Один и тот же набор фракталов можно подать по-разному.

| Форма | Описание | Когда применять |
|---|---|---|
| `flat_table` | Все признаки развёрнуты в одну длинную строку чисел: `fractal0_price`, `fractal0_direction`, ..., `fractal99_impulse` | RF/XGBoost и быстрые baseline |
| `fractal_rows` | Каждый фрактал остаётся отдельной строкой признаков внутри одного примера: например 100 фракталов × 10 полей | Transformer и другие модели, которым важны порядок и взаимодействие уровней |
| `zone_rows` | Каждая ATR-зона становится отдельной строкой агрегатов: зона выше 0-5 ATR, ниже 0-5 ATR и т.д. | Когда нужно сохранить структуру выше/ниже уровня без 100 сырых фракталов |
| `fractal_rows_plus_context` | Отдельные строки фракталов плюс общие признаки всей строки: ATR, час, день недели, плотность уровней | Когда нужен и список уровней, и общий рыночный контекст |
| `multi_scale_summary` | Сводки по нескольким окнам: например первые 20, 50, 100 фракталов или окна 5/10/20/50/100 | Контроль, видит ли модель масштаб без полного списка фракталов |

## Рекомендуемая стартовая матрица для Transformer

Не запускать всё сразу. Для Stage 5.0 или похожего этапа разумная стартовая матрица:

| Профиль | Что проверяет |
|---|---|
| `all100_base10` | Базовый упорядоченный список всех фракталов |
| `all100_full29` | Даёт ли пользу расширенный контракт `data_loader.py` |
| `newest20_full29` | Достаточны ли только свежие фракталы |
| `nearest40_full` | Лучше ли ценовая близость, чем порядок свежести |
| `corridor_10atr_full` | Даёт ли широкий ATR-коридор вокруг `fractal0` лучший рыночный контекст |
| `corridor_5_10_15atr_ablation` | Ограниченная проверка ширины коридора: 5 против 10 против 15 ATR |
| `zones_plus_nearest40` | Контроль агрегатов зон плюс конкретные ближайшие уровни |

Для `nearest_k` в новых исследованиях использовать сетку `k=20/40/60/80`. Старые `k=4/6/8/16` считать историческими диагностическими вариантами: они полезны для проверки минимального локального сигнала, но слишком малы для оценки рыночной картины.

## Интерпретация результатов

- Если `newest_N` лучше `all100`, дальний хвост вносит шум или модель не умеет его игнорировать.
- Если `nearest_k` лучше `newest_N`, ценовая близость важнее свежести.
- Если `corridor_10atr` лучше `nearest_k`, модели нужна широкая рыночная картина, а не только несколько ближайших уровней.
- Если `corridor_15atr` лучше `corridor_5atr`, локальный контекст слишком узкий.
- Если `zones_atr` лучше профилей с отдельными фракталами, конкретный порядок фракталов не нужен, достаточно плотности и агрегатов.
- Если `time_control` близок к фрактальным профилям, нужен отдельный аудит календарного риска.

## Типовые ошибки

- Сравнивать `all100` и `corridor_Xatr` без отчёта о заполненности коридора.
- Использовать `1-3 ATR` как единственный коридор и сделать вывод, что “коридор не работает”, хотя туда попало слишком мало фракталов.
- Добавлять `path_reaction`, `shift`, `atr_ratio`, `density` одним большим блоком и потом считать, что каждый компонент вреден.
- Подбирать ширину коридора по `locked_test`.
- Менять порядок фракталов между train и live.
- Считать календарные признаки полноценной заменой фрактальной структуры.
