# План объединения скиллов: update-docs-on-code-change + generate-module-index

## Анализ текущего состояния

### generate-module-index
- **Размер**: ~44 строки (компактный)
- **Назначение**: Полная регенерация MODULE_INDEX.md из file headers
- **Триггер**: "rebuild module index", "refresh MODULE_INDEX.md"
- **Workflow**: 5 шагов (найти → извлечь → парсить → сгенерировать → показать diff)

### update-docs-on-code-change
- **Размер**: ~480 строк (большой скилл)
- **Назначение**: Комплексное управление документацией
- **Режимы**:
  1. Создание нового модуля (упоминает обновление MODULE_INDEX.md в шаге 4)
  2. Документирование существующего (упоминает MODULE_INDEX.md)
  3. Синхронизация (проверяет MODULE_INDEX.md)
  4. Валидация (проверяет MODULE_INDEX.md)
- **Секция MODULE_INDEX.md Format**: дублирует информацию

## Варианты объединения

### Вариант A: Sub-mode интеграция (Рекомендуется)
**Суть**: Добавить generate-module-index как "Режим 6" в update-docs-on-code-change

**Структура после объединения:**
```
update-docs-on-code-change/
├── SKILL.md (обновлённый)
│   ├── Режим 1: Создание нового модуля
│   ├── Режим 2: Документирование существующего
│   ├── Режим 3: Синхронизация документации
│   ├── Режим 4: Валидация документации
│   ├── Режим 5: Рефакторинг AGENTS.md (refactor agents.md)
│   └── Режим 6: Регенерация MODULE_INDEX.md ← НОВОЕ
└── templates/
    └── file-headers.md
```

**Преимущества:**
- ✅ Один скилл вместо двух — проще обнаружение
- ✅ Логичная группировка: всё про документацию в одном месте
- ✅ Режим 5 использует те же шаблоны и форматы
- ✅ Не нарушает существующие workflows

**Недостатки:**
- ⚠️ Скилл станет ещё больше (~520 строк)
- ⚠️ Нужно обновить триггеры

**Триггеры для Режима 6:**
- "rebuild module index"
- "refresh MODULE_INDEX.md"
- "regenerate index"
