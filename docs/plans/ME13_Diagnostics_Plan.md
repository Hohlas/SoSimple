# Контекст: Диагностика ML-интеграции (ME-13 - ME-15)

## 📌 Суть проблемы
В проекте **SoSimple** наблюдается сильное расхождение метрик между Python ML-бэктестами и результатами симуляции в MT4 Strategy Tester.
- **Python (OOS)**: Profit Factor = 4.50, Win Rate = 86% (на таргете `regression_updn` с агрессивным порогом θ=2.665).
- **MT4 (Strategy Tester)**: Profit Factor = 0.93 - 1.03, Win Rate = 34-54%.

## 🔍 Гипотезы расхождения
1. **MFE/MAE Иллюзия (Path Dependency / Look-ahead bias)**: Python оценивает максимальный пик цены (`up_12`) за 12 часов. При этом он игнорирует траекторию! Если цена сначала сильно упала (выбив MT4 Stop Loss = 1.6 ATR), а лишь потом выросла до `up_12`, Python запишет это в **профит**, а MT4 закроет в **убыток**.
2. **Блокировка позиций (Position Blocking)**: Python считает каждый сигнал независимо. MT4 отклоняет вторые и третьи сигналы подряд, если позиция уже открыта (по статистике ~51% сигналов блокируется). 
3. **Отставание входа (Lag bias)**: Фрактал Вильямса формируется с задержкой в 2 бара. Значит, ML обучается на цене начала тренда, а MT4 входит по цене на 2 часа позже.
4. **Влияние жесткого таймаута**: MT4 принудительно закрывает сделки по истечении времени (`HoldOverTime`), не давая цене шанса дойти до ML-профита.

## 🛠 Инструмент диагностики

`statistics/signal_tracer.py` — trade-level reconciliation, 3 режима:
- `--time "YYYY.MM.DD HH:MM"` — полное досье одного сигнала
- `--batch --top N --min-ratio X` — топ-N высокорейтинговых сигналов, сводная таблица + CSV
- `--from-log MT/tester/logs/YYYYMMDD.log` — разбор реальных сделок из MT4 лога

Для каждой сделки: ML предсказание → формула SL/TP (реплика `lib_ML_Signal.mqh`) → Ground Truth up_12/dn_12 (денормализованные пункты) → классификация TP_CLEAR / SL_CLEAR / BOTH_HIT / TIMEOUT.

Полная документация: [docs/data_analysis/signal_tracer.py.md](../data_analysis/signal_tracer.py.md)

# 🚀 План дальнейшего исследования

Для следующего агента/разработчика:

### Этап 1: Сбор данных из MT4 (Ручной этап пользователя)
1. Запустить торгового эксперта `$o$imple.mq4` в тестере стратегий MT4.
2. Открыть "Журнал" (или вкладку "Результаты").
3. Найти **3-5 конкретных сделок**, которые:
   - Были открыты по ML-сигналу (iSignal=3).
   - Закрылись в убыток (по Stop Loss) ИЛИ были принудительно перевернуты / закрыты по таймауту.
4. Выписать их точное время открытия ордера: `YYYY.MM.DD HH:MM`.

### Этап 2: Диагностика (Разбор полетов)
1. Прогнать выписанные времена через скрипт `signal_tracer.py`:
   ```bash
   python statistics/signal_tracer.py --time "YYYY.MM.DD HH:MM"
   ```
2. Сопоставить логи MT4 с выводом скрипта:
   - Совпадает ли цена входа `Price` фрактала с ценой `Open` в MT4? Если сдвиг сильный — дело в Lag Bias или спреде.
   - Превысил ли `dn_12` (для BUY) уровень теоретического SL до того, как цена коснулась TP? Если да — это 100% подтверждение MFE/MAE иллюзии.

### Этап 3: Системные решения (Зависит от результатов Этапа 2)
Если гипотеза **MFE/MAE иллюзии** подтверждается на большинстве сделок, необходимо менять таргет обучения ML-модели или логику ее оценки:
- **Переход на Triple Barrier Method (TBM)**: (Уже разрабатывается на параллельном треке). При маркировке датасета необходимо проверять **касание первого барьера** (что наступило раньше — SL или TP) по побарной или тиковой истории, а не просто брать максимум/минимум за 12 часов.
- **Внедрение жесткого ML Trailing Stop**: В MT4 добавить агрессивный трейлинг, фиксирующий прибыль на резких MFE-выбросах, пока цена не успела развернуться по HoldOverTime.
- **Фильтр "опасных" фракталов**: Обучить вспомогательную модель отказывать в торговле, если ожидаемая дисперсия (`pred_dn` для BUY-сигнала) приближается к размеру Stop Loss.
