## Дисбаланс классов (94.9% Neutral)
ИИ: Модели наловчились предсказывать 0 (Neutral), потому что так проще всего минимизировать общую ошибку. Что мы можем с этим сделать:
- Не учитывать 0 в оценке (Macro F1 только для -1 и 1): Мы уже частично это делаем, когда смотрим на Per-class F1 в матрицах классификации. Но мы можем заставить систему остановки обучения (Early Stopping) вообще игнорировать успехи модели на нулевом классе. Сигналом к сохранению модели будет только ее способность качественно предсказывать Sell и Buy.
- Повысить ценность классов (-1 и 1) в десятки раз: Сейчас мы используем функцию потерь Focal Loss с весами [0.45, 0.10, 0.45] (то есть классы 1 и -1 ценятся в 4.5 раза выше, чем 0). Мы можем сделать веса [0.495, 0.01, 0.495] — тогда угадывание сигнала будет в 50 раз важнее, чем угадывание флэта. Модель начнет чаще ошибаться, принимая нейтральные зоны за сигналы, но не пропустит настоящие импульсы.

## Ключевые наблюдения
1. Все модели застряли на одном потолке (~0.57–0.58)
Разброс Macro F1 между лучшей (BiLSTM, 0.580) и худшей (1D-CNN, 0.563) — всего 0.017. Это означает, что проблема не в архитектуре, а в чём-то фундаментальном: данных, фичах или разметке.

2. Критическая проблема: никто не предсказывает Buy и Sell достаточно хорошо
F1 для класса Neutral (0) ≈ 0.95 — модели научились игнорировать всё и говорить "нейтрально"
F1 для Sell (-1) ≈ 0.39–0.42 и Buy (+1) ≈ 0.35–0.38 — очень слабо
Матрицы ошибок подтверждают: ни одна модель не предсказала ни одного Buy как Sell (нули в углах матриц) — это нехороший признак
3. Overfitting во всех моделях
На всех 4 кривых обучения: Train Loss падает, Val Loss растёт или плато — классический оверфиттинг. BiLSTM начинает переобучаться примерно с эпохи 10–12, Hybrid ещё раньше.

4. Transformer — самый медленный и не самый лучший
641 секунд vs 332 у BiLSTM при схожем качестве. Для этого объёма данных transformer, скорее всего, избыточен.

5. BiLSTM — лидер, но с оговорками
Лучший Macro F1, но best_epoch=24 говорит, что модель медленно конвергирует. Вероятно, есть запас если добавить регуляризацию.

❗ Диагноз — что идёт не так
Судя по матрицам ошибок, основная проблема — дисбаланс классов. Class 0 (Neutral) явно сильно представлен (~8000 примеров vs ~230–250 для Sell/Buy). Focal Loss должна с этим бороться, но видимо это настроено недостаточно агрессивно (нужно проверить параметр gamma).

## [2026-02-27] — Критический анализ: ловушка дисбаланса классов
### Проблема
- **Macro F1 = 0.57 — обманчивая метрика**: высокое значение достигается за счёт F1(0)=0.95 (neutral, 95% данных)
- **Торгово-значимые классы (-1 и 1) имеют F1 ≈ 0.35** — катастрофически низкое качество
- **Precision сигнальных классов**: 0.25–0.30 → 70-75% ложных торговых сигналов
### Что делать (альтернативные подходы)
1. Изменить целевую метрику (срочно!)
В train.py строка 388:

metric_name = 'f1_macro'  # ← меняем на:
Варианты:

Вариант А: F1 только сигнальных классов
metric_name = 'f1_minority'  # (F1(-1) + F1(1)) / 2

Вариант Б: Weighted F1 с штрафом за neutral
Вариант В: Precision для сигнальных классов (минимизируем ложные сигналы)
2. Downsample neutral класса (жёстко, но честно)
В data_loader.py — брать только 10-20% neutral сэмплов
Баланс классов в батче: ~равное количество -1, 0, 1
Минус: теряем 80-90% данных

Плюс: модель реально учится на сигналах

3. WeightedRandomSampler (лучший компромисс)
from torch.utils.data import WeightedRandomSampler

Веса обратно пропорциональны частоте класса
weights = [1/0.025, 1/0.949, 1/0.026]  # ~[40, 1, 38]
sampler = WeightedRandomSampler(weights, num_samples=len(dataset), replacement=True)
В батче будет ~равное количество всех классов — модель вынуждена учиться на сигналах.
