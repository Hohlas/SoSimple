### Ключевые структуры данных

**PICS** (один фрактальный уровень):
| Поле | Тип | Описание |
|------|-----|----------|
| `P` | float | Цена уровня |
| `Dir` | char | Направление: +1 (вершина), -1 (впадина) |
| `T` | datetime | Время формирования |
| `Frnt` / `FrntVal` | float | Передний фронт (минимум перед пиком) и его амплитуда |
| `Back` / `BackVal` | float | Задний фронт (откат после пика) и его амплитуда |
| `Pwr` | float | Сила уровня = min(FrntVal, BackVal) |
| `PwrSum` | float | Суммарная сила совпадающих пиков на этом уровне |
| `Imp` | float | Импульс: 2*Peak - base1 - base2 (симметрия пика) |
| `Cnt` | char | Количество совпадений с другими пиками |
| `Brk` | char | Статус: CLEAR(0) → TOUCH(1) → MIRROR(2) → BROKEN(3) → 4..10 |
| `Strong` | char | Признак сильного уровня (Pwr > ATR*PicPwr и сильный импульс) |
| `Rev` | float | Сила разворотной вершины, превосходящей этот пик |
| `Flt` | FLT_LEV | Вложенная структура флэта (если пик стал частью диапазона) |
| `Fls` | FLS_BRK | Вложенная структура ложного пробоя (Phase, Base, P) |
| `Up[3]` / `Dn[3]` | float | Максимальные экскурсии цены вверх/вниз за 12/24/48 баров после формирования |
| `Atr` | float | Значение Atr.Fast на момент формирования фрактала |

**TREND_SIGNALS**:
| Поле | Тип | Описание |
|------|-----|----------|
| `Global` | char | Глобальный тренд: +1 (up), -1 (down), 0 (нет) |
| `Local` | char | Локальный тренд: сумма PicBrk + Flat |
| `PicBrk` | char | Счётчик пробоев пиков: >0 = бычий, <0 = медвежий |
| `Flat` | char | Направление выхода из флэта: +1 (вверх), -1 (вниз) |

**PRICE** (текущий ордер BUY/SEL):
| Поле | Описание |
|------|----------|
| `Val` | Цена входа |
| `Stp` | Стоп-лосс |
| `Prf` | Тейк-профит |
| `Typ` | Тип: NONE(0), MARKET(1), STOP(2), LIMIT(3), SET(4) |
| `T` | Время открытия |

## 3. Детекция фракталов — PIC()

**Файл**: [lib_PIC.mqh](../../MT/MQL4/Include/lib_PIC.mqh)

### 3.1 ATR_COUNT()

**Файл**: [lib_ATR.mqh](../../MT/MQL4/Include/lib_ATR.mqh)

Вычисляет два ATR:
- **Atr.Fast** = среднее (High-Low) за `FastAtrPer = a²` баров. Обновляется каждый бар.
- **Atr.Slow** = среднее (High-Low) за `SlowAtrPer = A²` баров. Обновляется раз в день.
- **ATR** = выбранный ATR (по параметру `Ak`): 0=Slow, 1=Fast, 2=Min, 3=Max.
- **Atr.Lim** = `ATR * PicVal / 100` — порог "касания" уровня.

### 3.2 Детекция фракталов (Williams)

На каждом баре проверяется:
- `High[bar + PicPer]` — максимум из `2*PicPer + 1` баров → новая вершина (Dir=+1).
- `Low[bar + PicPer]` — минимум из `2*PicPer + 1` баров → новая впадина (Dir=-1).

При обнаружении вызывается `NEW_LEVEL(Dir, Price)`.

### 3.3 NEW_LEVEL() — регистрация нового фрактала

Ключевая функция (180+ строк). Алгоритм:

1. **Обход всех слотов F[1..100]**:
   - Вычисляет **вес** каждого уровня: `Weight = Pwr * FltNum / Distance / (Brk+1)`.
   - Находит слот с минимальным весом (кандидат на вытеснение).
   - Для совпадающих уровней (в пределах `Atr.Lim`): накапливает `PwrSum`, `Cnt`.
   - Для пробитых уровней: если пробой глубокий (> `Atr.Max*2`), повышает до MIRROR.
   - Вызывает `FALSE_BREAK(f)` для каждого уровня.
   - Обновляет `Back`, `BackVal`, `Near`, `NearVal` для существующих уровней.

2. **Запись нового уровня** в слот с минимальным весом:
   - Все поля: P, T, Dir, Cnt, Brk=CLEAR, Up[0..2]=0, Dn[0..2]=0, Atr=Atr.Fast.
   - Для вершин: `Frnt = LOWEST(...)` (минимум между текущим и предыдущим пиком), `Tr = P - Atr.Fast`.
   - Для впадин: `Frnt = HIGHEST(...)`, `Tr = P + Atr.Fast`.
   - `Imp = 2*Peak - base1 - base2` (мера импульсности).
   - `StrongImp = (Imp/Atr > PicImp)`.

3. **Обнаружение флэтов**: вызов `FLAT_DETECT()`.
4. **Экспорт для ML**: вызов `NERO_CSV_CREATE(bar)`.

### 3.4 LEVELS_FIND_AROUND() — поиск ключевых уровней

Обходит все заполненные слоты F[] и определяет:

| Переменная | Описание | Критерий выбора |
|------------|----------|-----------------|
| **HI** | Первый уровень сопротивления | Сильный непробитый уровень выше цены (Days определяет ближний/дальний) |
| **LO** | Первый уровень поддержки | Сильный непробитый уровень ниже цены |
| **HI2** | Серединный уровень сопротивления | Самый сильный уровень между HI и HI.Back (MidTyp определяет критерий) |
| **LO2** | Серединный уровень поддержки | Самый сильный уровень между LO и LO.Back |
| **stpH** / **stpL** | Уровни для трейлинга | Ближайшие уровни над H / под L с достаточным BackVal |
| **TrgHi** / **TrgLo** | Целевые уровни | Ближайшие к расчётным TargetHi/TargetLo |

**Важно для ML**: В этой же функции **инкрементально накапливаются Up[]/Dn[]** — максимальные экскурсии цены после формирования каждого фрактала (H12, H24, H48 горизонты). Эти данные становятся таргетами ML-модели.

### 3.5 Жизненный цикл уровня (State Machine)

```
      NEW_LEVEL()
          │
          ▼
       CLEAR ──LEV_TOUCH()──► TOUCH ──LEV_BREAK()──► BROKEN ──LEV_CROSS()──► 4..10
          │                                              │
          └──────LEV_BREAK()─────────────────────────────┘
                                                         │
          SET_BROKEN() при пробое:                       │
          ├── Обновляет Trnd.Global (+1/-1)               │
          ├── Обнуляет HI/LO/HI2/LO2 если пробит         │
          └── Запускает FALSE_BREAK tracking              │
                                                         │
       MIRROR ◄── из NEW_LEVEL(), если глубокий пробой ──┘
```

### 3.6 LOCAL_TREND()

Определяет локальный тренд по двум компонентам:
- **PicBrk**: счётчик последовательных пробоев (>0 = бычий, <0 = медвежий). Инкрементируется в `SET_BROKEN()`, ограничен параметром `iLoc`.
- **Flat**: направление выхода из флэта. Если цена вошла в флэт снизу, ожидается выход вверх (+1).

`Trnd.Local = sign(PicBrk) + Flat` (если `iFlt > 0`).

### 3.7 GLOBAL_TREND()

Устанавливается inline в `SET_BROKEN()`:
- Пробит HI или HI2 → `Trnd.Global = +1` (бычий).
- Пробит LO или LO2 → `Trnd.Global = -1` (медвежий).
- Параметр `iGlb` контролирует, какой уровень (1=первый, 2=серединный) задаёт глобальный тренд.

## 4. Генерация входных сигналов — INPUT()

**Файл**: [INPUT.mqh](../../MT/MQL4/Include/INPUT.mqh)

### 4.1 Трендовый фильтр

Перед генерацией сигналов проверяется:
```
UP = (нет открытого BUY) AND (Trnd.Global >= 0) AND (Trnd.Local >= 0)
DN = (нет открытого SEL) AND (Trnd.Global <= 0) AND (Trnd.Local <= 0)
```
Если ни UP ни DN — выход без сигнала.

### 4.2 Стратегии входа (iSignal)

| iSignal | Функция | Стратегия |
|---------|---------|-----------|
| 0 | `SIG_NULL()` | Безусловный вход: всегда BUY+SELL по текущей цене ± ATR |
| 1 | `SIG_FIRST_LEVELS()` | **От первых уровней**: вход от HI/LO (или HI2/LO2 при MidTyp>0) |
| 2 | `SIG_FALSE_BREAK()` | **Ложный пробой**: вход после подтверждённого ложного пробоя уровня |
| 4 | `SIG_TURTLE()` | **Черепаший**: вход в направлении пробоя сильного уровня |

#### SIG_FIRST_LEVELS() (iSignal=1)

**Файл**: [iSIG_FIRST_LEVELS.mqh](../../MT/MQL4/Include/iSIG_FIRST_LEVELS.mqh)

Основная стратегия — торговля отскоков от ключевых уровней:
1. BUY: если `MidTyp==0`, используется LO (первый уровень поддержки), иначе LO2 (серединный).
2. Если PIC существует и отличается от предыдущего сигнала → `set.BUY.Sig = GOGO`, вызов `OPEN_BUY(PIC)`.
3. Аналогично для SELL: используется HI или HI2.

#### SIG_FALSE_BREAK() (iSignal=2)

**Файл**: [iSIG_FALSE_BREAK.mqh](../../MT/MQL4/Include/iSIG_FALSE_BREAK.mqh)

Торговля ложных пробоев:
1. Когда `F[FlsUp].Fls.Phase == GOGO` → sell-сигнал. Цена входа зависит от параметра D:
   - D > 2: лимитник от пробитой вершины (± ATR/2)
   - D >= 0: лимитник от базы ложняка (± ATR/2)
   - D < 0: стоп-ордер на обратный пробой
2. Стоп = пик ложняка + DELTA(Stp). Профит = Back уровня (величина предшествовавшего движения).
3. Отмена сигнала, если ложный пробой фаза вернулась в NONE.

#### SIG_TURTLE() (iSignal=4)

**Файл**: [iSIG_TURTLE.mqh](../../MT/MQL4/Include/iSIG_TURTLE.mqh)

Тренд-следящая стратегия по пробоям:
1. Фильтр: пробитый пик (`BrokenPic`) должен иметь: Back >= ATR*PicPwr, сформированный трендовый уровень, Per > FltLen*5.
2. Ждёт формирования нового пика после пробоя (`Phase = WAIT`).
3. По формировании нового пика → `GOGO`: стоп за новый пик, профит = Val + 5*ATR.

### 4.3 OPEN_BUY / OPEN_SELL — расчёт ордера

**Файл**: [INPUT.mqh](../../MT/MQL4/Include/INPUT.mqh)

```
OPEN_BUY(pic):
  Stop = ATR * D / 2
  set.BUY.Stp = F[pic].P - Atr.Lim * Stp       ← стоп ниже уровня
  set.BUY.Val = set.BUY.Stp + Stop              ← вход = стоп + стоповая зона

  if Prf > 0: set.BUY.Prf = F[pic].P + (Back - P) * Prf/4  ← профит = доля от Back
  else:       set.BUY.Prf = Val + DELTA(2-Prf)              ← профит = квадратичная ATR-функция

  if D <= 0:  Val = Stp + (Prf - Stp) * 2/(3-D)             ← вход пропорционален P/L ratio
  if ASK < Val: Val = ASK                                     ← рыночный вход, если цена прошла
```

### 4.4 Валидация и замена ордеров

После генерации сигнала INPUT() проверяет:
- Корректность Stp < Val < Prf (для BUY) / Stp > Val > Prf (для SEL).
- При `ExpirationBars == 0`: новый сигнал заменяет существующий отложенник, если разница > ATR/2.
- При `ExpirationBars > 0`: новый сигнал игнорируется, пока старый не истёк.

## 5. ML-сигналы — ML_TRADE()

**Файл**: [lib_ML_Signal.mqh](../../MT/MQL4/Include/lib_ML_Signal.mqh)

### 5.1 Архитектура

```
Python                                    MQL4
─────────                                 ────────
Nero_*_labeled.csv                        ml_signals.csv
  + Transformer model         ──CSV──►      │
  + θ = 2.665                               ▼
                                        ML_INIT()      ← lazy init, загрузка CSV в массивы
                                        ML_FindSignal() ← бинарный поиск по Time[bar]
                                        ML_TRADE()      ← вызов OPEN_BUY/OPEN_SELL
```

### 5.2 Формат CSV

```
time;signal;pred_up;pred_dn;ratio_up;ratio_dn
2023.01.03 04:00;1;0.477;0.045;10.71;0.09
```

- `signal`: 1 (BUY), -1 (SELL), 0 (FLAT)
- `pred_up` / `pred_dn`: предсказанные ML-моделью экскурсии вверх/вниз
- `ratio_up` = pred_up / pred_dn (используется для фильтрации по θ)

### 5.3 Торговая логика ML_TRADE()

```python
if signal == 1 AND нет открытого BUY:
    OPEN_BUY(Ask, 0)     # рыночный вход, target=0 → профит по умолчанию
elif signal == -1 AND нет открытого SEL:
    OPEN_SELL(Bid, 0)    # рыночный вход, target=0 → профит по умолчанию
```

**Текущие ограничения**:
- `target_price = 0` → OPEN_BUY/OPEN_SELL проверяют `input_price * target_price == 0` и возвращают "price=0" ошибку. **Это блокирует открытие ордеров**.
- ML_TRADE() не использует `pred_up`/`pred_dn` для расчёта стопов и профитов.
- ML_TRADE() не учитывает трендовый фильтр (Trnd.Global, Trnd.Local).
- ML_TRADE() работает параллельно с INPUT() — возможны конфликты ордеров.

### 5.4 Точки интеграции для ML-улучшений

| Что модифицировать | Где | Зачем |
|--------------------|-----|-------|
| **Вычисление стопа/профита** | `ML_TRADE()` → `OPEN_BUY/SELL` | Использовать pred_up/pred_dn для адаптивного SL/TP |
| **Трендовый фильтр** | `ML_TRADE()` | Согласовать ML-сигнал с Trnd.Global/Local |
| **Управление позицией** | `OUTPUT()` | ML-предсказание может корректировать условия выхода |
| **Замена INPUT()** | `MAIN.mqh:123` | Полная замена классических сигналов на ML |
| **Гибрид** | `INPUT()` + `ML_TRADE()` | ML как фильтр или усилитель классических сигналов |

## 6. Генерация выходных сигналов — OUTPUT()

**Файл**: [OUTPUT.mqh](../../MT/MQL4/Include/OUTPUT.mqh)

### 6.1 Условия закрытия BUY

| Условие | Параметр | Действие |
|---------|----------|----------|
| Импульс угас | `oImp < 0` | Закрытие по текущей цене, если (H - BUY.Val) / noise < oImp * 0.1 |
| Импульс угас (мягко) | `oImp > 0` | Передвижение тейка в безубыток |
| Глобальный тренд развернулся | `oGlb > 0` AND `Trnd.Global < 0` | Передвижение стопа/тейка по типу oGlb |
| Локальный тренд развернулся | `oLoc > 0` AND `Trnd.Local < 0` | Передвижение стопа/тейка по типу oLoc |
| Цель достигнута | `Target` AND `BUY.Val > TargetLo` | Закрытие по текущей цене |
| POC/пик рядом с ордером | `oFlt` | Если консолидация или новый пик рядом с ожидающим ордером — отмена |

### 6.2 CLOSE_BUY(price, comment)

Параметр `price` определяет действие:
- `price > 0`: подтягивание тейка (1=закрыть, 2=безубыток, 3=по максимуму, 4+=с припуском)
- `price < 0`: подтягивание стопа (-1=за последний пик, -2=в безубыток)
- `price == 0`: отмена ордера (удаление отложенника)

### 6.3 TRAILING_STOP()

Работает от уровней stpH / stpL (найденных в LEVELS_FIND_AROUND):
- BUY: если `stpL > 0` и `F[stpL].P - Atr.Lim > BUY.Stp` → подтягиваем стоп.
- SEL: зеркально для stpH.
- Параметр `Trl`: >0 = только в плюс, <0 = в любом случае.

## 7. Обнаружение ложных пробоев — FALSE_BREAK()

**Файл**: [lib_Flat.mqh](../../MT/MQL4/Include/lib_Flat.mqh)

State machine для каждого фрактального уровня:

```
WAIT ──► START ──► CONFIRM ──► GOGO ──► NONE
              │                          ▲
              └──── (отмена) ─────────────┘
```

1. **WAIT**: уровень пробит (Brk = BROKEN), ожидаем формирование нового пика за уровнем.
2. **START**: Новый пик вышел за уровень на `> Atr.Lim`. Фиксируем **Base** (откуда начался пробой).
3. **CONFIRM**: Цена вернулась внутрь уровня. Ложный пробой наметился.
4. **GOGO**: Цена прошла ниже Base. Ложный пробой подтверждён → сигнал на вход (FlsUp/FlsDn).
5. **NONE**: Сигнал отработан или отменён (цена ушла слишком далеко).

## 8. Обнаружение флэтов — POC_SIMPLE() и FLAT_DETECT()

### POC_SIMPLE()

**Файл**: [lib_PIC.mqh](../../MT/MQL4/Include/lib_PIC.mqh)

Простой Point-of-Control: считает количество последовательных баров с пересекающимися диапазонами:
```
HiZone = MIN(H, HiZone)    ← верхняя граница сужается
DnZone = MAX(L, DnZone)    ← нижняя граница расширяется
if HiZone > DnZone: PocCnt++, PocCenter = (HiZone + DnZone) / 2
else: reset → PocCnt = 1
```

### FLAT_DETECT()

**Файл**: [lib_Flat.mqh](../../MT/MQL4/Include/lib_Flat.mqh)

Обнаруживает боковой диапазон из нескольких совпадающих пиков:
1. Проверяет `F[n].Flt.Num >= PicCnt` (достаточно совпадающих пиков) и `len >= FltLen` (достаточная длина).
2. Вычисляет границы: `UpLev`, `DnLev`, `Range`, `Center`.
3. Определяет `Trnd.Flat` — предполагаемое направление выхода (если вошли снизу, ожидаем выход вверх).

## 9. Управление ордерами

### ORDER_CHECK()

**Файл**: [ORDERS.mqh](../../MT/MQL4/Include/ORDERS.mqh)

Сканирует все открытые ордера MT4 по MagicNumber:
- Заполняет `BUY.Val/Stp/Prf/Typ/T` и `SEL.Val/Stp/Prf/Typ/T`.
- Различает типы: OP_BUY, OP_BUYSTOP, OP_BUYLIMIT, OP_SELL, OP_SELLSTOP, OP_SELLLIMIT.

### ORDERS_SET()

Выставляет новые ордера через `OrderSend()`:
- Вычисляет `Lot` через Money Management (`MM()`) на основе стоп-лосса и `Risk`.
- Определяет тип ордера по соотношению цены входа и рыночной: BUYSTOP / BUYLIMIT / BUY(market).
- Проверяет `CHECK_RISK()` — не превышает ли MaxRisk.

### MODIFY()

Перебирает все ордера и:
- Закрывает рыночные ордера, если `BUY.Val == 0` / `SEL.Val == 0`.
- Удаляет отложенные ордера, если Val == 0.
- Модифицирует стоп/тейк, если значения изменились.

## 10. Временные фильтры

### FINE_TIME()

**Файл**: [COUNT.mqh](../../MT/MQL4/Include/COUNT.mqh)

Контролирует разрешённое время торговли:
- `Wknd=1`: запрет в пятницу после 22:00 (FOMC).
- `Wknd=2`: запрет в пятницу после 19:00 (Weekend).
- `tk > 0`: торговля разрешена только в окне `Tin..Tout` (в барах от начала дня).

При запрете: закрывает все позиции по `tp` типу цены.

### TIMER()

Закрывает позиции, удерживаемые дольше `Tper` баров:
```
if BUY открыт AND SHIFT(BUY.T) >= Tper → CLOSE_BUY(1, "HoldOverTime")
if SEL открыт AND SHIFT(SEL.T) >= Tper → CLOSE_SEL(1, "HoldOverTime")
```

## 11. Внешние параметры эксперта

Параметры загружаются из CSV-файла `#.csv` (одна строка на эксперта):

### Индикаторные (PIC)
| Параметр | Описание |

| Параметр | Описание |
|----------|----------|

### Трендовые
| Параметр | Описание |
|----------|----------|
| `iGlb` | Какой пробой задаёт глобальный тренд: 1=первый, 2=серединный |
| `iFlt` | Влияние флэта на локальный тренд (>0 = учитывать) |
| `iLoc` | Максимальный счётчик PicBrk для локального тренда |

### Входные (INPUT)
| Параметр | Описание |
|----------|----------|
| `iSignal` | Стратегия: 0=null, 1=first_levels, 2=false_break, 4=turtle |

### Выходные (OUTPUT)
| Параметр | Описание |
|----------|----------|
| `oImp` | Импульс-фильтр (<0 = закрытие, >0 = безубыток) |

| `oGlb` | Закрытие при смене глобального тренда (>0 = тип закрытия) |
| `oLoc` | Закрытие при смене локального тренда |

### Временные (TIME)
| Параметр | Описание |
|----------|----------|
| `tk` | Тип временного окна: 0=GTC, >0 = внутридневное окно |
| `T0` / `T1` | Начало/конец торгового окна (индексы из ряда Fibonacci: 1,2,3,5,8,13,21) |

## 12. Экспорт данных для ML — NERO_CSV_CREATE()

**Файл**: [lib_PIC.mqh](../../MT/MQL4/Include/lib_PIC.mqh)

### 12.1 Формат CSV (Nero.csv)

Вызывается при каждом формировании нового фрактала. Записывает строку:

```
time; signal; predict; ATR; fractal_0; fractal_1; ... fractal_99
```

Каждый `fractal_i` содержит **18 полей** (через `:`):

| # | Поле | Описание |
|---|------|----------|
| 1 | T | Время формирования фрактала |
| 2 | P | Цена уровня |
| 3 | Dir | Направление: +1 (вершина), -1 (впадина) |
| 4 | FrntVal | Амплитуда переднего фронта |
| 5 | BackVal | Амплитуда заднего фронта |
| 6 | Strong | Признак сильного уровня (0/1) |
| 7 | Brk | Статус пробоя (0..10) |
| 8 | Rev | Сила разворотной вершины |
| 9 | PwrSum | Суммарная сила совпадающих пиков |
| 10 | Cnt | Количество совпадений |
| 11 | Imp | Импульс |
| 12 | Up[H12] | max(High - P) за 12 баров |
| 13 | Dn[H12] | max(P - Low) за 12 баров |
| 14 | Up[H24] | max(High - P) за 24 бара |
| 15 | Dn[H24] | max(P - Low) за 24 бара |
| 16 | Up[H48] | max(High - P) за 48 баров |
| 17 | Dn[H48] | max(P - Low) за 48 баров |
| 18 | Atr | Значение Atr.Fast на момент формирования |

### 12.2 Связь с ML pipeline

```
NERO_CSV_CREATE() → Nero.csv → label_main.py → Nero_*_labeled.csv → ML/train.py
                                                                         ↓
                                              generate_signals.py ← transformer_updn_best.pt
                                                     ↓
                                              ml_signals.csv → ML_TRADE() → OPEN_BUY/SELL
```

## 13. Резюме для ML-интеграции

### Текущее состояние ML_TRADE()

ML_TRADE() вызывается на каждом баре после COUNT() и до INPUT(). При наличии сигнала в CSV вызывает `OPEN_BUY(Ask, 0)` / `OPEN_SELL(Bid, 0)`. Однако `target_price=0` приводит к блокировке ордера в OPEN_BUY/OPEN_SELL (проверка `input_price * target_price == 0`).

### Доступный контекст для ML-решений

На момент вызова ML_TRADE() уже вычислены:
- **ATR**: `Atr.Fast`, `Atr.Slow`, `ATR`, `Atr.Lim`
- **Фракталы**: массив `F[]` с 101 уровнем, включая все характеристики
- **Ключевые уровни**: `HI`, `LO`, `HI2`, `LO2`, `stpH`, `stpL`
- **Тренд**: `Trnd.Global`, `Trnd.Local`, `Trnd.PicBrk`, `Trnd.Flat`
- **POC**: `PocCnt`, `PocCenter`
- **Текущие ордера**: `BUY.Val/Typ/Stp/Prf`, `SEL.Val/Typ/Stp/Prf`
- **Цены**: `H`, `L`, `C`, `H1`, `L1`, `C1` (текущий и предыдущий бар)

### Рекомендуемые точки модификации

1. **ML_TRADE()** — основная точка: заменить `OPEN_BUY(Ask, 0)` на вызов с расчётными ценами на основе pred_up/pred_dn и ATR.
2. **INPUT() как фильтр** — добавить ML-фильтр перед классическими сигналами: блокировать UP/DN если ML предсказывает противоположное.
3. **OUTPUT()** — ML может корректировать уровни выхода (стоп/профит) динамически.
4. **TRAILING_STOP()** — адаптивный трейлинг на основе ML-предсказаний волатильности.
