# docs/audit/

Рабочие методики и аудит-планы для проверки ML-моделей торговых систем.

| Артефакт | Роль | Когда обновлять |
|---|---|---|
| [`ml_trading_methodology.md`](ml_trading_methodology.md) | Основной регламент разработки и аудита ML-моделей ТС в рамках проекта, включая обязательный Feature Contract / Leakage Gate | Меняются обязательные gates, leakage-инварианты, схема validation/test/forward или выводы по типовым ошибкам |
| [`old_plan_example.md`](old_plan_example.md) | Старый пример плана; использовать только для сравнения полноты структуры | Не обновлять как методику без отдельного пересмотра |

## Правила

- Методики должны быть применимы к нескольким исследовательским трекам, а не к одному конкретному checkpoint.
- `ml_trading_methodology.md` является source of truth для ML-quality gates; отдельные планы и `DATA_FLOW.md` не заменяют его.
- Примеры из проекта допустимы, но решения нельзя переносить без проверки по первичным файлам.
- Если методика ссылается на отчёты, выводы должны быть проверены по `docs/reports/`, а не только по wiki.
