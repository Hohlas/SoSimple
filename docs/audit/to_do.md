# Audit To Do

## После Stage 4.3 Diagnostic-Only

Stage 4.3 специально ограничен диагностикой текущего winner и не должен включать новые исследовательские ветки. Следующие темы вынесены из Stage 4.3 не потому, что они не нужны, а потому что для них нужны отдельные планы и отдельные критерии интерпретации.

- [ ] **Stage 5.0-prep: breach feature ablation.**
  Провести после отчёта Stage 4.3, до финального плана Transformer Stage 5.0. Цель: понять, на каких группах признаков держится breach-модель (`time`, фрактальные каналы, ATR, price/front/back и т.д.) и не является ли сигнал в основном календарным фильтром. Результат не должен выбирать торговый winner; он нужен для проектирования Stage 5.0.

- [ ] **Stage 5.0-prep: AUC→PF sensitivity.**
  Проводить только как `DIAGNOSTIC_ONLY` после Stage 4.3. Цель: оценить, насколько сильное улучшение breach-ранжирования теоретически нужно, чтобы fixed Stage 4.2 rule приблизился к PF-gate. Метод смешивания предсказаний с истинными labels является oracle-like диагностикой и не должен трактоваться как прогноз реальной модели.

- [ ] **Отдельный план: trailing / partial exit mechanics.**
  Проводить после Stage 4.3, если loss attribution или TP-policy comparison подтвердят, что фиксированный TP/SL или fav-based TP плохо фиксируют благоприятный ход. Это новая execution-механика, не исправление Stage 4. Перед выводами нужны синтетические тесты симулятора, порядок high/low внутри H1-бара, ambiguous cases, block bootstrap, spread/slippage stress и MT4/tester parity.

- [ ] **Отдельный план: чистый candidate-cycle для найденной Stage 4.3 зоны.**
  Если Stage 4.3 найдёт ячейку с PF > 1.15, BS_p05 около/выше 1.0, trades/year >= 30 и без концентрации прибыли в одном году, не превращать её в winner напрямую. Нужно написать отдельный план с `val-select`/`val-eval` или permutation test, повторяющим весь процесс выбора.
