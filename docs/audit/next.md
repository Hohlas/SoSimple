## Ретроспектива
Проект близится к году, стабильного положительного результата нет. Нужна полная ретроспектива.
Изучи все отчёты в docs/reports/ и страницы wiki/. Составь docs/audit/results.md со следующей структурой:
1. Хронология этапов — для каждого этапа: цель, гипотеза, что сделано, количественный результат (метрики), вывод (подтверждена/опровергнута гипотеза).
2. Что работает — решения с измеримым положительным эффектом, с указанием метрик.
3. Что не работает — подходы, которые пробовали и получили отрицательный результат, с указанием причины.                          
4. Нерешённые проблемы — вопросы, которые остаются открытыми.
5. Накопленные ограничения — известные ограничения данных, моделей, пайплайна, которые сужают пространство поиска.                 
                                               
Критерий включения: факт влияет на выбор дальнейшей стратегии. 
Исключай: баги инфраструктуры, опечатки, коммиты, рефакторинг без изменения поведения.
Для каждой метрики указывай конкретные числа, а не "улучшилось/ухудшилось".

# Мозговой штурм
На основе docs/audit/results.md проведи мозговой штурм. Цель — найти направления, которые ещё не пробовались, но могут дать результат.
Для каждого направления укажи:
 - какая нерешённая проблема из ретроспективы закрывается
 - ожидаемый эффект и риски
 - сложность реализации (низкая/средняя/высокая)
 - какие данные или эксперименты нужны для проверки
