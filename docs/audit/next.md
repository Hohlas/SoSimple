# Мозговой штурм
На основе docs/audit/results.md проведи мозговой штурм. Цель — найти направления, которые ещё не пробовались, но могут дать результат.
Для каждого направления укажи:
 - какая нерешённая проблема из ретроспективы закрывается
 - ожидаемый эффект и риски
 - сложность реализации (низкая/средняя/высокая)
 - какие данные или эксперименты нужны для проверки

# Ретроспектива v2

Проект близится к году, стабильного положительного результата нет.
Порог успеха: PF ≥ 1.3 на out-of-sample с учётом спреда и проскальзываний,
подтверждённый bootstrap CI (нижняя граница > 1.0).
Нужна полная ретроспектива.

Источники (в порядке приоритета):
1. CHANGELOG.md — индекс всех этапов с краткими выводами.
2. docs/reports/ — канонические отчёты (verdict: PASS/FAIL/DIAGNOSTIC_ONLY).
3. wiki/research/ — синтез отчётов по направлениям.
4. docs/superpowers/roadmap.md — текущий план и закрытые треки.

Составь docs/reports/retrospective.md (не более 4000 слов) со структурой:

1. Вердикт по проекту (1 абзац)
   Достигнут ли порог успеха. Если нет — какая главная причина.

2. Направления исследований (вместо плоской хронологии)
   Сгруппируй этапы по направлениям (сигналы, фильтры, таргеты, модели,
   исполнение). Для каждого направления:
   - Цель направления и основная гипотеза.
   - Ключевые этапы: что сделано, вердикт (PASS/FAIL/DIAGNOSTIC_ONLY),
     количественный результат (PF, Sharpe, win rate — конкретные числа).
   - Итог направления: что дали все этапы в совокупности.
   Используй вердикты из header отчётов, не придумывай свои.

3. Что работает
   Решения с измеримым положительным эффектом. Для каждого:
   метрика до, метрика после, размер выборки, вердикт.

4. Что не работает
   Подходы с отрицательным или нулевым результатом. Для каждого:
   что пробовали, конкретные числа, почему не сработало (гипотеза).

5. Эволюция понимания
   Как менялось представление о проблеме за год. Какие убеждения
   оказались неверными и когда это стало ясно.

6. Нерешённые проблемы
   Открытые вопросы, блокирующие прогресс. Для каждого:
   что известно, что нужно выяснить, предлагаемый подход.

7. Накопленные ограничения
   Ограничения данных, моделей, пайплайна, методологии,
   которые сужают пространство поиска.

8. Рекомендации
   Что пробовать дальше (с обоснованием). Что закрыть окончательно
   (с обоснованием). Приоритеты на следующий квартал.

Критерий включения: факт влияет на выбор дальнейшей стратегии.
Исключай: баги инфраструктуры, опечатки, рефакторинг без изменения
поведения, коммиты.
Для каждой метрики указывай конкретные числа и размер выборки,
а не «улучшилось/ухудшилось».
При противоречии между отчётом и wiki — доверяй отчёту.
