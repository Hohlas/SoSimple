# idea-check — часть 2 брэйншторма (процедура для opencode)

Исходная реализация: `workflow/idea_check.js` (рантайм Qoder). Этот файл — транслированная
процедура под стек opencode: те же фазы, промпты и правила, исполняем не рантаймом, а
агент-оркестратором через инструменты Task / Write / bash / TodoWrite.

Назначение: читает `docs/audit/brainstorm-raw.json` (результат idea-brainstorm) → фильтр
жёсткого запрета → спор «автор идеи × критик» на каждую гипотезу (3 раунда, досрочный выход
при признании фатального аргумента) → синтез-арбитр с правом только понижать вердикты →
итоговый список в `docs/audit/brainstorm-filtered.md`.

Целевая модель: дешёвая (deepseek-v4-flash-free) для всех вызовов.

## Контрактные ограничения

- Контекстное окно субагента ~150K. Основной вход каждого агента — `docs/audit/retrospective.md`
  (~2K слов), читается целиком.
- `knowledge-rag` (`search_knowledge`) — только точечная проверка фактов; отчёты
  `docs/reports/` и `ML/reports/` целиком не читаются.
- Вход — файл `docs/audit/brainstorm-raw.json` от части 1.
- Кластеризации нет: каждая гипотеза спорится индивидуально — итог не зависит от случайного
  слияния идей в группы. Раунды внутри пары последовательны, пары — параллельны. Каждый
  раунд — НОВЫЙ вызов агента с передачей всей предыдущей переписки пары в промпте
  (долгоживущих агентов нет).
- Анти-сговор: вердикт меняется только под новые аргументы, а не под уверенность тона;
  досрочный выход — по признанию фатального аргумента автором ПРИ предварительном вердикте
  критика «убита» (иначе обязателен раунд 3 — защита от послушных уступок модели-автора),
  а не по «согласию сторон»;
  арбитр вправе только понижать вердикты критика, не повышать.
- Потолок числа гипотез в споре — `MAX_IDEAS = 30` (стоимость = гипотезы × 2–3 вызова).

## Трансляция примитивов рантайма

| JS-примитив | Эквивалент в opencode |
|---|---|
| `phase('...')` | TodoWrite (пункт) + текстовое объявление фазы |
| `agent(prompt, {phase, label})` | Task-инструмент, субагент explore, промпт = промпт роли |
| `parallel([...])` | несколько Task-вызовов в одном сообщении |
| `log(message)` | текст в выводе оркестратора |
| Write/bash внутри субагента | выполняет сам оркестратор (субагенты read-only) |
| `parseJson/normalizeResult` | та же логика, выполняет оркестратор |
| досрочный выход / статусы | оркестратор решает, что логировать |

Оркестратор проверяет: ответ должен быть валидным JSON без markdown-обёртки; агенты возвращают
вердикты только из тройки `выживает | условно | убита`. Статус `без спора` присваивает
оркестратор при сбое агента или бракованном вердикте — агенты его не возвращают.
Проверка JSON применяется к фильтру жёсткого запрета и раундам 1–3 споров; ответ арбитра — готовый
markdown-документ, проверке JSON не подвергается.

## Фаза 1 — Чтение входа

**TodoWrite**: "Фаза 1: Чтение входа brainstorm-raw.json".

Прочитать `docs/audit/brainstorm-raw.json`. Это сырые гипотезы от части 1. Ничего не
редактировать, не дополнять и не переформулировать. Если файл отсутствует —
`ABORT: файл docs/audit/brainstorm-raw.json отсутствует, сначала запустите idea-brainstorm`.

Валидировать: `hypotheses` — массив записей с `name` и `essence` (непустые), `tags` — массив
(по умолчанию `[]`). Если гипотез нет вообще — ABORT.

`log('Загружено гипотез: N.')`.

## Фаза 2 — Фильтр жёсткого запрета

**TodoWrite**: "Фаза 2: Фильтр жёсткого запрета".

Сформировать блок всех идей (для каждого пункта: название, суть, тупик, источник edge, теги).
Отправить Task-агенту:

> Ниже — сырые гипотезы о новых источниках trading edge, собранные независимыми
> генераторами (с пересекающимися векторами). Ретроспективу перечитывать не нужно.
>
> {rawBlock}
>
> **Задача — ТОЛЬКО фильтрация, без переписывания:**
> 1. Удали идеи, нарушающие жёсткий запрет: классические индикаторы (RSI, MACD, скользящие
>    средние и т.п.) и прочие примитивные отжившие методы. Больше ничего не удалять: новизну
>    проверяет спор.
> 2. Названия гипотез верни ДОСЛОВНО, как в списке — по ним идёт связка.
>
> Ответ строго валидным JSON без markdown: `{"kept":["..."], "removed":[{"name":"...","reason":"..."}]}`

Обработать ответ:
- Связать по дословному `name`; источник истины — исходные формулировки из raw.json.
  Пустой `kept` — ABORT.
- `removed` — залогировать; идеи, пропавшие без записи в `removed` —
  `log('Внимание: фильтр потерял N идей...')`.
- Кластеризации нет: каждая гипотеза дальше спорится индивидуально.
  Промежуточного файла `brainstorm-ideas.md` больше нет.

**Потолок**: если гипотез > `MAX_IDEAS = 30` — отброшенные попадают в `droppedIdeas`
(log + протокол арбитра, не исчезают молча). `log('Гипотез в спор: N.')`.

## Фаза 3 — Споры (автор × критик, на каждую гипотезу)

**TodoWrite**: "Фаза 3: Споры".

Пары параллельны (Task-вызовы в одном сообщении, по одному на гипотезу); раунды внутри пары
последовательны.

Блок идеи для промптов:
```
Название: {name}
Суть: {essence}
Обходимый тупик: {deadend | 'не указан'}
Откуда edge: {edge_source}
Теги: {tags.join('; ')}
```

### Раунд 1 — атака критика

> Ты — критически настроенный рецензент количественных исследований. Атакуй гипотезу и
> найди её слабые места. Не защищай и не ищи оправданий. Это раунд 1: после твоей атаки
> автор получит слово, затем ты подведёшь черту.
>
> Контекст: проект SoSimple (Forex, personal research). Порог успеха: PF ≥ 1.3 на строгом
> out-of-sample с bootstrap CI (нижняя граница > 1.0). За ~6 месяцев ни одна система его
> не прошла.
>
> Вход: прочитай `docs/audit/retrospective.md` ЦЕЛИКОМ. База проверки новизны — секция 2
> (пройденные направления) и секция 4 (что не работает). `knowledge-rag` — только точечная
> проверка фактов вне ретроспективы.
>
> Выполни по порядку:
> 1. **Новизна.** Найди в ретроспективе (секции 2 и 4) аналог с ТЕМ ЖЕ механизмом edge.
>    Совпадение темы или слов — НЕ доказательство: нужна точная цитата из секции,
>    описывающая тот же механизм. Аналог есть → `preliminary_verdict` "убита",
>    в `retrospective_ref` — секция и цитата.
> 2. **Атака.** До трёх самых уязвимых мест (данные, стационарность, исполнение, размер
>    выборки, происхождение edge).
> 3. **Фальсификация.** Спроектируй убивающий эксперимент: что проверить, метрика, конкретный
>    порог/число, которое убивает идею, стоимость (часы/дни). Эксперимент НЕ проводить.
>    Если убивающий тест в рамках проекта не формулируется — `falsifiable=false` с объяснением.
>
> Ответ строго валидным JSON без markdown:
> `{"novelty":{"duplicate_of":null,"retrospective_ref":null}, "vulnerabilities":["..."], "falsification":{"test":"...","metric":"...","kill_threshold":"...","cost":"часы/дни","falsifiable":true}, "preliminary_verdict":"выживает|условно|убита"}`

Не распарсился → статус `no_debate` (спор не состоялся).

### Раунд 2 — защита автора

В промпт передаются блок идеи (формат выше) и полная атака раунда 1 (JSON). Текст:

> Ты — автор гипотезы ниже. Критик её атаковал. Задача — честная защита по существу,
> НЕ защита любой ценой.
>
> Правила:
> - Отвечай на каждый аргумент по существу. Не пересказывай суть идеи заново.
> - Если аргумент фатален и неустраним (например, точная цитата из ретроспективы о том же
>   механизме edge) — признай явно: `concession=true` и укажи, какой аргумент принят.
>   Честное признание ценнее плохой защиты.
> - Можешь проверить цитату, прочитав названную секцию ретроспективы.
> - Слабый механизм «кто платит» допустимо признать и уточнить — это не фатально.
> - Не выдавай предположения за факты; спекуляции помечай [гипотеза].
> - Ответ — до 200 слов.
>
> Ответ строго валидным JSON без markdown:
> `{"concession":false, "accepted_arguments":[], "defense":"..."}`

Не распарсился — не рвать спор: `defense` = технический сбой с сырым текстом, передать критику.

**Досрочный выход**: `concession === true` И предварительный вердикт критика `убита` →
статус `conceded`, вердикт `убита`, rationale = «Автор признал фатальный аргумент
критика: ...» + принятые аргументы. Раунд 3 не нужен. Если предварительный вердикт мягче
(`условно`/`выживает`), уступка НЕ убивает идею автоматически — раунд 3 обязателен:
критик решает, действительно ли признанный аргумент фатален (защита от послушных уступок
модели-автора, убивающих идею строже, чем её атакующий); в протоколе раунда 2 пометить
«ПРИЗНАЛ аргумент, но предварительный вердикт не «убита» — спор продолжен».

### Раунд 3 — итог критика

В промпт передаются блок идеи, атака и защита (JSON):

> Ты — тот же критик из раунда 1. Подведи черту: конспект «за и против» и финальный вердикт
> для независимого арбитра.
>
> Правила:
> - Вердикт меняется ТОЛЬКО под новые факты и аргументы из ответа автора — не под
>   уверенность тона и не потому, что автор возражает. Защита без содержательного — сохрани
>   предварительный вердикт.
> - Если автор признал аргумент (concession=true), но твой предварительный вердикт не был
>   «убита» — реши по существу, действительно ли признанный аргумент фатален для идеи. Само
>   по себе признание автора не обязывает убивать идею, если ты в раунде 1 не счёл её убитой.
> - Не дополняй и не улучшай гипотезу.
> - Уточни фальсификацию только если защита дала новые данные.
> - Потенциал (1–5): правдоподобие устойчивого edge ТОЛЬКО по механизму «кто платит»
>   (поле `edge_source`) и результатам спора; числа не выдумывать.
>
> Ответ строго валидным JSON без markdown:
> `{"name": "...", "pros":["..."], "cons":["..."], "novelty":{"duplicate_of":null,"retrospective_ref":null}, "vulnerabilities":["..."], "falsification":{...}, "potential":1, "potential_why":"одно предложение", "verdict":"выживает|условно|убита", "rationale":"одно предложение"}`

Вердикт вне тройки или не распарсился → статус `no_debate`.

### Сборка

Приоритет сортировки вердиктов: `выживает < условно < убита < без спора`. Вывести
`log('Вердикты споров: ...')`.

**Протоколы споров** — оркестратор пишет `docs/audit/brainstorm-protocols.md`
(аудит вердиктов без чтения чата). Структура: заголовок `## {name}` + строка
«Статус» (полный спор / досрочный выход: автор признал фатальный аргумент
при предварительном вердикте «убита» / спор не состоялся), блок идеи, затем
дословные JSON-ответы: раунд 1 — атака критика; раунд 2 — ответ автора;
раунд 3 — итог критика (для досрочного выхода: «пропущен» + итог досрочного
выхода; при сбое агента: «нет — сбой агента»). Писать КАК ЕСТЬ, без правок.

## Фаза 4 — Синтез-арбитр

**TodoWrite**: "Фаза 4: Синтез-арбитр".

Собрать протокол каждого спора:
- заголовок `### {name}` + блок идеи + вердикт критика и потенциал;
- статус `no_debate` — «СПОР НЕ СОСТОЯЛСЯ (ошибка агента). Вердикт: без спора.»;
- раунд 1: новизна (аналог/ссылка), уязвимости, фальсификация, предварительный вердикт;
- раунд 2: «ПРИЗНАЛ фатальный аргумент — ...» (conceded), либо
  «ПРИЗНАЛ аргумент, но предварительный вердикт не «убита» — спор продолжен» + текст
  защиты, либо просто текст защиты;
- раунд 3 (если был): за / против / итог.

Далее — промпт арбитра:

> Ты — арбитр брэйншторма. Ниже — протоколы споров «автор идеи × критик».
>
> Вход: 1) протоколы споров; 2) прочитай в `docs/audit/retrospective.md` секции 2 и 4 —
> первоисточник для проверки «убита за переупаковку»: цитата критика должна реально
> описывать тот же механизм edge; 3) при наличии — идеи, НЕ ОЦЕНЁННЫЕ из-за потолка.
>
> Полномочия:
> - Вправе ПОНИЗИТЬ вердикт («выживает» → «условно» → «убита»), если конспект или
>   ретроспектива показывают мягкость критика.
> - ПОВЫШАТЬ вердикты запрещено: если критик убил идею, она остаётся убитой.
> - Своих оценок потенциала не выдумывать — использовать числа критиков как есть.
> - Записи «без спора» — технический сбой агента, а не свойство идеи: не помечать их
>   [нефальсифицируема] и не выносить по ним суждений.
>
> Напиши файл `docs/audit/brainstorm-filtered.md` со структурой:
> 1. Короткий список выживших (вердикт «выживает», при нехватке — добирай из «условно»;
>    всего ≤ 10), строго по убыванию потенциала. Для каждой: суть (1–2 предложения),
>    обходимый тупик, убивающий эксперимент с метрикой и порогом, стоимость, потенциал,
>    пометки [радикальная]/[спекуляция]/«условно». [нефальсифицируема]
>    — в конец списка с объяснением. Идеи «без спора» в короткий список НЕ включать — вывести
>    отдельным примечанием в конце документа; туда же идеи, не оценённые из-за потолка,
>    с пометкой «не оценивались».
> 2. Таблица-сводка: идея | вердикт | потенциал | обходимый тупик | убивающий результат |
>    стоимость.
> 3. Список убитых: идея | причина | ссылка на секцию ретроспективы (если «за переупаковку»);
>    «автор признал аргумент» — если досрочно.
> 4. Если понизил чей-то вердикт — перечисли отдельной строкой с обоснованием.
>
> Правила: не улучшать/дополнять/воскрешать убитые идеи; числа и цитаты из протоколов не
> выдумывать заново; спекуляции помечать [гипотеза].
>
> Файл писать НЕ нужно (ты read-only). Верни в ответе ПОЛНЫЙ текст документа
> `brainstorm-filtered.md` в markdown, ничего не сокращая; после текста — короткая сводка:
> сколько выжило / условно / убито / понижено арбитром и топ-3 выживших кратким списком.

Оркестратор записывает возвращённый текст КАК ЕСТЬ в `docs/audit/brainstorm-filtered.md`
(без правок и сокращений). Если ответ обёрнут в fenced-блок (```` ```markdown ... ``` ````) —
снять обёртку перед записью, в файл она попасть не должна; итоговая сводка после текста
документа в файл тоже не записывается.

## Примечания для оркестратора

- Каждый раунд спора — Отдельный Task с полной предшествующей перепиской пары в промпте.
- Вердикты из тройки; всё остальное — статус `no_debate`.
- Понижение вердиктов арбитром — только в одну сторону.
- Результат части 1: `docs/audit/brainstorm-raw.json`; результат этой части:
  `docs/audit/brainstorm-protocols.md` (протоколы споров) и
  `docs/audit/brainstorm-filtered.md` (итог).
