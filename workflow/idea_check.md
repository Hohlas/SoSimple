# idea-check — часть 2 брэйншторма (процедура для opencode)

Исходная реализация: `workflow/idea_check.js` (рантайм Qoder). Этот файл — транслированная
процедура под стек opencode: те же фазы, промпты и правила, исполняем не рантаймом, а
агент-оркестратором через инструменты Task / Write / bash / TodoWrite.

Назначение: читает `docs/audit/brainstorm-raw.json` (результат idea-brainstorm) → разметка
кластеров без слияния → спор «автор идеи × критик» на кластер (3 раунда, досрочный выход
при признании фатального аргумента) → синтез-арбитр с правом только понижать вердикты →
итоговый список в `docs/audit/brainstorm-filtered.md`.

Целевая модель: дешёвая (deepseek-v4-flash-free) для всех вызовов.

## Контрактные ограничения

- Контекстное окно субагента ~150K. Основной вход каждого агента — `docs/audit/retrospective.md`
  (~2K слов), читается целиком.
- `knowledge-rag` (`search_knowledge`) — только точечная проверка фактов; отчёты
  `docs/reports/` и `ML/reports/` целиком не читаются.
- Вход — файл `docs/audit/brainstorm-raw.json` от части 1.
- Спор идёт на кластер, не на идею: один представитель + заметка о соседях по кластеру.
  Раунды внутри пары последовательны, пары — параллельны. Каждый раунд — НОВЫЙ вызов агента
  с передачей всей предыдущей переписки пары в промпте (долгоживущих агентов нет).
- Анти-сговор: вердикт меняется только под новые аргументы, а не под уверенность тона;
  досрочный выход — по признанию фатального аргумента автором, а не по «согласию сторон»;
  арбитр вправе только понижать вердикты критика, не повышать.
- Потолок числа кластеров в споре — `MAX_CLUSTERS = 20` (стоимость = кластеры × 2–3 вызова).

## Трансляция примитивов рантайма

| JS-примитив | Эквивалент в opencode |
|---|---|
| `phase('...')` | TodoWrite (пункт) + текстовое объявление фазы |
| `agent(prompt, {phase, label})` | Task-инструмент, субагент explore, промпт = промпт роли |
| `parallel([...])` | несколько Task-вызовов в одном сообщении |
| `log(message)` | текст в выводе оркестратора |
| Write/bash внутри субагента | выполняет сам оркестратор (субагенты read-only) |
| `parseJson/normalizeResult` | та же логика, выполняет оркестратор |
| досрочный выход / статусы | оркестратор решает, что логировать |

Оркестратор проверяет: ответ должен быть валидным JSON без markdown-обёртки; агенты возвращают
вердикты только из тройки `выживает | условно | убита`. Статус `без спора` присваивает
оркестратор при сбое агента или бракованном вердикте — агенты его не возвращают.
Проверка JSON применяется к разметке кластеров и раундам 1–3 споров; ответ арбитра — готовый
markdown-документ, проверке JSON не подвергается.

## Фаза 1 — Чтение входа

**TodoWrite**: "Фаза 1: Чтение входа brainstorm-raw.json".

Прочитать `docs/audit/brainstorm-raw.json`. Это сырые гипотезы от части 1. Ничего не
редактировать, не дополнять и не переформулировать. Если файл отсутствует —

Валидировать: `hypotheses` — массив записей с `name` и `essence` (непустые), `tags` — массив

`log('Загружено гипотез: N.')`.

## Фаза 2 — Разметка кластеров

**TodoWrite**: "Фаза 2: Разметка кластеров".

Сформировать блок всех идей (для каждого пункта: название, суть, тупик, источник edge, теги).
Отправить Task-агенту (промпт из idea_check.js, строки 111–131):

> Ниже — сырые гипотезы о новых источниках trading edge, собранные независимыми
> генераторами (с пересекающимися векторами). Ретроспективу перечитывать не нужно.
>
> {rawBlock}
>
> **Задача — ТОЛЬКО разметка, без переписывания:**
> 1. Разбей гипотезы на кластеры по совпадению механизма edge (кто платит и почему эффект
>    устойчив) — даже при разной упаковке. Близкие по теме, но разные по механизму идеи —
>    разные кластеры. Одиночные идеи получают свой кластер.
> 2. Удали идеи, нарушающие жёсткий запрет: классические индикаторы (RSI, MACD, скользящие
>    средние и т.п.) и прочие примитивные отжившие методы. Больше ничего не удалять: новизну
>    проверяет спор.
> 3. Названия гипотез верни ДОСЛОВНО, как в списке — по ним идёт связка.
>
> Ответ строго валидным JSON без markdown: `{"items":[{"name":"...","cluster":1}], "removed":[{"name":"...","reason":"..."}]}`

Обработать ответ:
- Связать имена с кластерами (по дословному `name`). Пустая разметка — ABORT.
- `removed` — залогировать; потерянные при разметке идеи — `log('Внимание: разметка потеряла N идей...')`.
- Источник истины — исходные формулировки (не переписывались при разметке).
- Сгруппировать в кластеры с сохранением порядка появления.

**Промежуточный артефакт** — оркестратор пишет `docs/audit/brainstorm-ideas.md`:
`# Сырые гипотезы брэйншторма (разметка кластеров)`, без ранжирования, один кластер = один
механизм edge; для каждой идеи заголовок `## {name} [кластер N]` и строки: суть / обходимый
тупик / откуда edge / теги.

**Потолок**: если кластеров > 20 — отброшенные попадают в `droppedClusters` (log + протокол
арбитра, не исчезают молча). `log('Кластеров в спор: N.')`.

## Фаза 3 — Споры (автор × критик, на кластер)

**TodoWrite**: "Фаза 3: Споры".

Пары параллельны (Task-вызовы в одном сообщении, по одному на кластер); раунды внутри пары
последовательны. Представитель кластера — `members[0]`; если в кластере больше одной идеи, в
промпт добавляется заметка о соседях. Вердикт распространяется на весь кластер.

Блок идеи для промптов:
```
Название: {name}
Суть: {essence}
Обходимый тупик: {deadend | 'не указан'}
Откуда edge: {edge_source}
Теги: {tags.join('; ')}
```

### Раунд 1 — атака критика (промпт из строк 239–275)

> Ты — критически настроенный рецензент количественных исследований. Атакуй гипотезу и
> найди её слабые места. Не защищай и не ищи оправданий. Это раунд 1: после твоей атаки
> автор получит слово, затем ты подведёшь черту.
>
> Контекст: проект SoSimple (Forex, personal research). Порог успеха: PF ≥ 1.3 на строгом
> out-of-sample с bootstrap CI (нижняя граница > 1.0). За ~6 месяцев ни одна система его
> не прошла.
>
> Вход: прочитай `docs/audit/retrospective.md` ЦЕЛИКОМ. База проверки новизны — секция 2
> (пройденные направления) и секция 4 (что не работает). `knowledge-rag` — только точечная
> проверка фактов вне ретроспективы.
>
> Выполни по порядку:
> 1. **Новизна.** Найди в ретроспективе (секции 2 и 4) аналог с ТЕМ ЖЕ механизмом edge.
>    Совпадение темы или слов — НЕ доказательство: нужна точная цитата из секции,
>    описывающая тот же механизм. Аналог есть → `preliminary_verdict` "убита",
>    в `retrospective_ref` — секция и цитата.
> 2. **Атака.** До трёх самых уязвимых мест (данные, стационарность, исполнение, размер
>    выборки, происхождение edge).
> 3. **Фальсификация.** Спроектируй убивающий эксперимент: что проверить, метрика, конкретный
>    порог/число, которое убивает идею, стоимость (часы/дни). Эксперимент НЕ проводить.
>    Если убивающий тест в рамках проекта не формулируется — `falsifiable=false` с объяснением.
>
> Ответ строго валидным JSON без markdown:
> `{"novelty":{"duplicate_of":null,"retrospective_ref":null}, "vulnerabilities":["..."], "falsification":{"test":"...","metric":"...","kill_threshold":"...","cost":"часы/дни","falsifiable":true}, "preliminary_verdict":"выживает|условно|убита"}`

Не распарсился → статус `no_debate` (спор не состоялся).

### Раунд 2 — защита автора (промпт из строк 287–314)

В промпт передаются блок идеи (формат выше) и полная атака раунда 1 (JSON). Текст:

> Ты — автор гипотезы ниже. Критик её атаковал. Задача — честная защита по существу,
> НЕ защита любой ценой.
>
> Правила:
> - Отвечай на каждый аргумент по существу. Не пересказывай суть идеи заново.
> - Если аргумент фатален и неустраним (например, точная цитата из ретроспективы о том же
>   механизме edge) — признай явно: `concession=true` и укажи, какой аргумент принят.
>   Честное признание ценнее плохой защиты.
> - Можешь проверить цитату, прочитав названную секцию ретроспективы.
> - Слабый механизм «кто платит» допустимо признать и уточнить — это не фатально.
> - Не выдавай предположения за факты; спекуляции помечай [гипотеза].
> - Ответ — до 200 слов.
>
> Ответ строго валидным JSON без markdown:
> `{"concession":false, "accepted_arguments":[], "defense":"..."}`

Не распарсился — не рвать спор: `defense` = технический сбой с сырым текстом, передать критику.

**Досрочный выход**: `concession === true` → статус `conceded`, вердикт `убита`, rationale =
«Автор признал фатальный аргумент критика: ...» + принятые аргументы. Раунд 3 не нужен.

### Раунд 3 — итог критика (промпт из строк 347–383)

В промпт передаются блок идеи, атака и защита (JSON):

> Ты — тот же критик из раунда 1. Подведи черту: конспект «за и против» и финальный вердикт
> для независимого арбитра.
>
> Правила:
> - Вердикт меняется ТОЛЬКО под новые факты и аргументы из ответа автора — не под
>   уверенность тона и не потому, что автор возражает. Защита без содержательного — сохрани
>   предварительный вердикт.
> - Не дополняй и не улучшай гипотезу.
> - Уточни фальсификацию только если защита дала новые данные.
> - Потенциал (1–5): правдоподобие устойчивого edge ТОЛЬКО по механизму «кто платит»
>   (поле `edge_source`) и результатам спора; числа не выдумывать.
>
> Ответ строго валидным JSON без markdown:
> `{"name": "...", "pros":["..."], "cons":["..."], "novelty":{"duplicate_of":null,"retrospective_ref":null}, "vulnerabilities":["..."], "falsification":{...}, "potential":1, "potential_why":"одно предложение", "verdict":"выживает|условно|убита", "rationale":"одно предложение"}`

Вердикт вне тройки или не распарсился → статус `no_debate`.

## Примечания для оркестратора

- Каждый раунд спора — Отдельный Task с полной предшествующей перепиской пары в промпте.
- Вердикты из тройки; всё остальное — статус `no_debate`.
- Понижение вердиктов арбитром — только в одну сторону.
- Результат части 1: `docs/audit/brainstorm-raw.json`; результат этой части:
  `docs/audit/brainstorm-ideas.md` (промежуточный) и `docs/audit/brainstorm-filtered.md` (итог).
