The repository is organized as a data-processing → ML-training → inference pipeline with four cooperating sub-projects wired together by shared CSV contracts and the `Nero.csv` time-series source:
- `data_processing/` ingests raw `MT/MQL4/Files/Nero.csv`, sorts fractals per row, labels signal/predict/UpDn/trailing-stop targets, normalizes features, and emits `_labeled.csv` plus `.npy` caches consumed downstream.
- `statistics_eda/` computes streaming Welford/reservoir statistics and reconciles ML predictions against MT4 trade logs via `signal_tracer.py`.
- `ml_pipeline/` builds PyTorch sequence models (Transformer, BiLSTM, CNN1D, hybrids) on the labeled data, optimizes hyperparameters with Optuna, and exports checkpoints plus frozen rules for OOS evaluation.
- `api_server/` exposes FastAPI endpoints and a telemetry watcher that continuously reads live `Nero.csv`, runs online-safe preprocessing, and returns ML predictions; exported signals are written as `ml_signals.csv` consumed by `metatrader_integration/` MQL4/MQL5 libraries (`lib_ML_Signal.mqh`).
The cross-cutting contract is the `_labeled.csv` schema (fractal columns + target labels) and the `ml_signals.csv` exchange format between Python and MT4. Tests in `tests/` assert parity across all stages using synthetic fixtures, while `docs/` and `wiki/` maintain methodology specs, audit reports, and an integrity map of the whole repo.
