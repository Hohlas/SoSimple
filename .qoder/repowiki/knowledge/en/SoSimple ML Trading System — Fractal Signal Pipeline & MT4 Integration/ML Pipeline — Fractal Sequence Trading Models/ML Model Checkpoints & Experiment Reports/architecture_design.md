Two flat artifact directories under ML/ serve as the output sink of training and evaluation pipelines:
- `ML/checkpoints/` holds serialized PyTorch model weights (`*.pt`) named by architecture (bilstm, cnn1d, transformer, hybrid, entry_path_dual_stream, etc.) and task suffix (`_regression`, `_updn`, `_tb`, `_signal_archetype_cls`, `_trade_outcome_cls`, `_trade_pnl_reg`). Each `.pt` is paired with a sibling `<name>_result.json` containing metrics like `best_f1_macro`, `best_epoch`, `num_parameters`, `training_time`, and per-class F1 scores. A single `pll_normalizer_v1.pkl` stores preprocessing state.
- `ML/reports/` is a flat collection of human-readable Markdown summaries, JSON artifacts, CSV tables, and Optuna study logs. Subdirectories group related experiments by feature pipeline or hypothesis (e.g. `entry_path_v1_*`, `take_skip_*`, `fractal0_*`, `transformer_direction/`). Top-level files include architecture comparison markdowns, Optuna study JSONs (`optuna_study_<task>_<timestamp>.json`), and stage-gated diagnostics (`stage4_*.json`, `stage5_*.json`).
There is no code in this module — it is purely an artifact store consumed by downstream trading/evaluation code via path conventions rather than imports.
