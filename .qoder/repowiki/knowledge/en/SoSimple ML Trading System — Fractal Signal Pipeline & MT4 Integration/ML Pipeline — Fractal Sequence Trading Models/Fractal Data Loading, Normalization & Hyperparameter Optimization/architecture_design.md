Four cohesive modules form the data-to-training pipeline:
- `data_loader.py` is the core: it parses `fractal0..fractal99` columns from `DATA/Nero_{train,val,test}_labeled.csv` into `(n, 100, 29)` tensors, computes derived features (ATR_ratio, hour_sin/cos, time_pos, log_shift, delta_shift, ATR-distance), builds `FractalSequenceDataset`/`EntryPathDataset` PyTorch `Dataset`s, caches intermediate `.npy` arrays in `DATA/` with timestamp-based invalidation, and exposes `create_data_loaders()` as the single entry point. It imports task-specific target splitters from sibling `ML/*_task.py` modules via a central `TASK_TARGET_COLUMNS` registry.
- `pll_normalizer.py` implements a group-wise Piecewise Linear-Log scaler (`PLLGroupScaler`) fit only on train, applied per-feature-group to the 3D tensor; `PLLFeatureNormalizer` orchestrates groups and no-norm indices, with pickle `save/load` for persistence.
- `utils.py` provides shared helpers: deterministic seed setting, classification/regression/binary metrics, parameter counting, and device selection — consumed by training scripts.
- `optimize.py` wraps `train_model` from `ML.train` inside an Optuna study using TPESampler + MedianPruner, defining a `suggest_hyperparameters` space per model (bilstm, transformer, cnn1d, hybrid) and saving best params + full trial history under `ML/reports/`.

Dependency direction: `optimize.py` → `train.py` → `data_loader.py`; `data_loader.py` depends on sibling `entry_path_*`, `trailing_stop_target_*`, `take_skip_trailing_stop_*` task modules but not vice versa. All files resolve `PROJECT_ROOT = Path(__file__).resolve().parent.parent` to reach `DATA/` and `docs/schemas/`.
