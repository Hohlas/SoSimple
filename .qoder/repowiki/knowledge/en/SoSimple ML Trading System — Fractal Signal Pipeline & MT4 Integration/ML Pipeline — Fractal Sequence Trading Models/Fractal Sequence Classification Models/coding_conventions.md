- Every classifier implements a `forward(x: Tensor, mask: Tensor | None = None) -> Tensor` signature where `x` has shape `(batch, seq_len, features)` and the output is logits of shape `(batch, num_classes)`, ensuring interchangeability through the registry.
- Transformer-based models consistently prepend a learnable `cls_token` parameter of shape `(1, 1, d_model)`, concatenate it with the projected sequence, apply `PositionalEncoding`, and extract the CLS output at index 0 for classification heads.
- Padding masks follow a consistent convention: callers pass `mask` where `True` means valid position, and models invert it (`~mask`) when constructing `src_key_padding_mask` for `nn.TransformerEncoder`, always prepending a `True` entry for the CLS token.
- Multi-output transformer variants return a `dict[str, torch.Tensor]` with named keys per head (e.g., `'ret'`, `'path_reg'`, `'path_cls'`, `'q10'`, `'q50'`, `'q90'`) rather than tuples or lists.
- Each model file begins with a standardized header block documenting purpose, language version, external dependencies, usage example, and key architectural notes (input shapes, layer counts, default parameters).
- Dual-stream transformer variants accept both a sequence tensor `x` and an `engineered` feature tensor, project the engineered features through a small MLP, and fuse them with the CLS token representation via concatenation followed by a linear projection.
