The module is organized as a flat collection of `torch.nn.Module` subclasses, each implementing a distinct architecture for sequence classification over fractal price data. The core entry point is `__init__.py`, which defines a `MODEL_REGISTRY` mapping string names (`bilstm`, `cnn1d`, `transformer`, `hybrid`) to classes and exposes a `get_model(name, **kwargs)` factory function — this is the only public API surface for model instantiation. Four foundational architectures live in dedicated files: `BiLSTMClassifier` (bidirectional LSTM with concatenated last hidden states), `CNN1DClassifier` (three Conv1D blocks with global average pooling), `TransformerClassifier` (encoder with learnable CLS token and sinusoidal positional encoding), and `HybridCNNLSTMClassifier` (Conv1D feature extractor feeding a bidirectional LSTM). A shared `PositionalEncoding` component in `transformer.py` is reused by all transformer-based variants. The remaining files are task-specific transformer extensions that follow a dual-stream pattern: a sequence stream (fractal tokens) processed by a Transformer encoder with a CLS token, optionally fused with an engineered-feature stream via concatenation + MLP, then split into multiple heads returning a `dict[str, torch.Tensor]`. These include `entry_path_transformer.py`, `entry_path_dual_stream_transformer.py`, `entry_path_v1_quantile_transformer.py`, `take_skip_dual_stream_transformer.py`, `trailing_stop_target_quantile_transformer.py`, and `fractal_breach_transformer.py` (which additionally includes a `TokenSelector` utility for static token selection based on price corridors and distances). Dependency direction is one-way: specialized transformers import from the base `transformer.py`; no cross-imports exist between sibling model files.
