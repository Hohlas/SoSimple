The pipeline is organized in four dependency layers defined in README.md: Layer 1 core (`losses.py`, `utils.py`, `data_loader.py`, `experiment_logger.py`) provides shared data loading, normalization, loss functions and logging; Layer 2 (`models/`) registers PyTorch model classes behind a unified interface consumed by training scripts; Layer 3 (`train.py` → `optimize.py`) wires DataLoader + model + optimizer through Optuna trials; Layer 4 (`evaluate_test.py`, `threshold_analysis.py`, `compare_architectures.py`) performs OOS evaluation and threshold selection. Task-specific pipelines (`entry_path_task`, `take_skip_trailing_stop`, `baseline_experiments`) reuse the same core layer to build feature matrices, construct labels, train models, and export predictions into the shared `checkpoints/`, `plots/`, and `reports/` artifact directories. Cross-cutting concerns — live-safe auditing (`live_safe_audit.py`, `live_safe_audit_registry.py`), conformal calibration (`conformal/`), telemetry reconciliation (`telemetry_daily_reconciliation.py`, `online_tester_reconciliation.py`), and cross-instrument robustness benchmarks — all consume the same checkpoint/report artifacts produced by the training/evaluation layer, forming a single experiment graph rather than isolated sub-projects.
