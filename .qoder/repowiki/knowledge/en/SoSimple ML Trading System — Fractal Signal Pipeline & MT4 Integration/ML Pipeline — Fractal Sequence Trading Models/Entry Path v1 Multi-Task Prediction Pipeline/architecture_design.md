The module is organized as a layered pipeline around a single shared task definition in `entry_path_task.py`, which centralizes constants (target names, class maps, feature column lists), the core model factory (`build_entry_path_model`), feature splitting (`split_entry_path_features`), export frame construction (`build_entry_path_export_frame`), and markdown reporting. `entry_path_feature_bank.py` provides row-wise engineered features derived from fractal columns across multiple windows (5/10/20/50/100) and metrics, consumed by the main task's feature builder. `entry_path_level_targets.py` builds candidate direction signals from fractal0 and evaluates baseline PnL against OHLC paths, serving as an upstream gate before modeling. `entry_path_trade_filter.py` implements two scoring candidates (A: raw ret24; B: weighted combination of ret12/ret24, edge12/edge24, path6) with percentile-rank normalization, grid/threshold evaluation across coverage targets, period stability checks, and sequential hold-bar filtering. `entry_path_v1_quantile_task.py` extends the base task with a quantile-specific model (`EntryPathV1QuantileTransformer`), pinball loss, interval coverage/width metrics, and report generation. `entry_path_v1_quantile_ensemble.py` aggregates predictions across multiple seed checkpoints via mean quantile averaging or majority vote. Dependency direction is strictly one-way: quantile modules import from the base task; no cross-imports between feature bank, level targets, and trade filter except through the shared task constants.
