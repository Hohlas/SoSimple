The module is organized as a flat collection of independent entry-point scripts plus one FastAPI server:
- `api_server.py` defines the FastAPI application with a lifespan hook that loads a PyTorch transformer checkpoint from `ML/checkpoints/`, reads Optuna best params from `ML/reports/optuna_best_params_transformer_regression_updn.json`, and exposes `/` (health) and `/predict` (POST) endpoints. The `/predict` endpoint accepts a `PredictRequest` Pydantic model containing an ATR value and exactly `N_FRACTALS` fractal strings, runs them through `processing.online_causal_preprocessing.preprocess_online_frame`, parses via `ML.data_loader.parse_fractals_to_3d`, performs inference, and thresholds predictions by theta to emit BUY/SELL/FLAT.
- Batch generators (`generate_signals.py`, `export_entry_path_v1_signals.py`, `export_entry_path_v1_quantile_signals.py`, `export_take_skip_trailing_stop_v2_signals.py`) are self-contained CLI tools invoked via `python -m API.<script>`; they load checkpoints/rules from `ML/checkpoints` and `ML/reports`, run inference over train/validation/test splits, and write `MT/MQL4/Files/ml_signals.csv` or research exports.
- `telemetry_signal_watcher.py` is a long-running daemon that polls `MT/MQL4/Files/Nero.csv`, applies causal preprocessing, invokes the same export functions, and appends new rows to `ml_signals.csv` in append-only fashion, persisting state in JSON under `ML/reports/<mode>/runtime/`.
- All scripts share dependencies on `ML.*` (data loaders, models, task-specific exporters) and `processing.online_causal_preprocessing` for live-safe feature normalization; there is no internal cross-import between the API scripts — each is independently executable.
- `test_api_client.py` is a standalone HTTP client against the running server.
