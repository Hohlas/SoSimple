# Отчёт По Этапу

Workflow для фиксации завершённого этапа без потери контекста.

## Когда использовать

- Пользователь явно просит закрыть этап.
- Пользователь просит подготовить подробный отчёт этапа.
- Пользователь просит синхронизировать `report`, `CHANGELOG.md` и `CONTEXT_HANDOFF.md`.

## Когда нужен полный отчёт

- Изменилось поведение кода, влияющее на результаты, сигналы, торговую логику, CLI или формат данных.
- Добавлен или существенно расширен инструмент или исследовательский сценарий.
- Получены новые результаты с практическими выводами.
- Исправлен баг, меняющий интерпретацию результатов.
- Завершён план/спек-этап, пригодный для handoff.

## Workflow

1. Определи дату и короткую тему этапа.
2. Создай или обнови `docs/reports/YYYY-MM-DD-topic.md`.
3. Проверь, нужен ли `CHANGELOG.md` по правилам репозитория; если да, добавь короткую запись со ссылкой на report.
4. Проверь, нужно ли обновить `CONTEXT_HANDOFF.md`.
5. Обнови `.claude/memory/` только если изменились устойчивые знания или правила.
6. Если пользователь явно просит commit или явно просит закрыть этап вместе с отчётом, `CHANGELOG.md` и `CONTEXT_HANDOFF.md`, после коммита свяжи report с commit hash.

## Правила

- `report = полный итог`
- `CHANGELOG = короткая история`
- `handoff = текущее состояние`
- `memory = долгоживущие знания`
- Не делать `git push` без явной просьбы пользователя.
- Не обновлять `CHANGELOG.md` для чисто документационных правок без продуктового изменения.
