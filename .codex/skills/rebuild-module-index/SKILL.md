# Регенерация MODULE_INDEX.md (Codex-friendly)

## Когда использовать
- Пользователь явно просит пересобрать `MODULE_INDEX.md`.
- После массовых изменений структуры модулей.

## Принципы
- Не придумывать статусы модулей: переносить из текущего `MODULE_INDEX.md` или отмечать `⚠️` для ручной проверки.
- Не читать большие файлы целиком без необходимости.

## Шаги

### 1) Собрать список кодовых модулей
```bash
rg --files -g '*.py' -g '*.mq4' -g '*.mqh' -g '*.ipynb' \
  -g '!**/.git/**' -g '!**/.venv/**' -g '!**/__pycache__/**' -g '!docs/archive/**'
```

### 2) Извлечь минимум метаданных
- `Назначение` из file header/первого блока комментариев.
- `Вход -> Выход` из header или оставить `-`.
- `Docs` строить по шаблону `docs/<category>/<file>.md`, если файл существует.

### 3) Обновить таблицы по директориям
- Секции: `processing`, `statistics`, `API`, `MT/MQL4`, `ML`.
- Колонки: `Модуль | Назначение | Вход -> Выход | Docs | Статус`.

### 4) Валидация перед завершением
```bash
rg -n "^\| \[" MODULE_INDEX.md
wc -l MODULE_INDEX.md
```

Проверить:
- битые ссылки отсутствуют;
- новые файлы попали в нужный раздел;
- удаленные файлы убраны.

## Best practices
- Если header неполный, не блокировать обновление индекса: ставить `-` в пропущенных полях.
- Если есть неоднозначность по статусу, явно помечать как `⚠️` и указывать это в отчете пользователю.
