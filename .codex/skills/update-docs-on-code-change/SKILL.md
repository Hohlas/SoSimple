# Синхронизация документации (Codex-friendly)

## Когда использовать
- Пользователь просит обновить документацию после изменений кода.
- Добавлен новый модуль и нужно создать docs + запись в индекс.

## Область
Применяется к `*.py`, `*.mq4`, `*.mqh`, `*.ipynb`, `*.md`.

## Шаблон file header

### Python (.py)

```python
# =============================================================================
# Файл: [filename.py]
# Назначение: [одна строка]
# Обновлён: [YYYY-MM-DD]
# Входные данные:
#   - [путь/файл] (откуда: [источник])
# Выходные данные:
#   - [путь/файл] (куда: [назначение])
# Использование:
#   python [filename.py] [аргументы]
# Примечания:
#   - [важные ограничения]
# =============================================================================
```

Обновлять header при изменении: назначения, входов/выходов, CLI-интерфейса. Не обновлять при рефакторинге внутренней логики.

### MQL4 (.mqh / .mq4) — только если есть явная #include-связь с задачей

```cpp
//+------------------------------------------------------------------+
//| Файл: [filename.mqh]                                             |
//| Назначение: [одна строка]                                        |
//| Обновлён: [YYYY-MM-DD]                                           |
//| Зависимости: [файл.mqh]                                          |
//+------------------------------------------------------------------+
```

**Кодировка MQL4: UTF-16LE.**

## Режимы

### 1) `doc this <path>` или `document <path>`
1. Проверить наличие file header; если нет — создать по шаблону выше.
2. Создать/обновить `docs/<category>/<module>.md`.
3. Добавить/обновить строку в `MODULE_INDEX.md`.
4. Если модуль участвует в pipeline, синхронизировать `docs/DATA_FLOW.md`.

### 2) `sync docs` / `обнови документацию`
1. Найти измененные файлы:
```bash
git diff --name-only -- '*.py' '*.mq4' '*.mqh' '*.ipynb' '*.md'
```
2. Для каждого файла обновить связанный `.md` из mapping.
3. Убедиться, что в docs отражены:
- назначение;
- входные/выходные данные;
- способ запуска;
- ограничения/предпосылки.

### 3) `create module <name>`
1. Создать кодовый файл с корректным header.
2. Создать `docs/<category>/<name>.md`.
3. Добавить модуль в `MODULE_INDEX.md`.
4. При необходимости добавить шаг в `docs/DATA_FLOW.md`.

## Правила качества
- Не дублировать подробные docstrings в `.md`; в `.md` оставлять обзор и ссылки.
- Не писать в `CHANGELOG.md` только из-за правок docs.
- Проверять размер документов:
```bash
wc -l docs/**/*.md
```

## Common mistakes
| Ошибка | Исправление |
|---|---|
| docs не обновлены после изменения CLI параметров | Обновить секцию `Использование` |
| новый модуль есть в коде, но нет в `MODULE_INDEX.md` | Добавить строку в соответствующий раздел |
| дублирование описаний между несколькими docs | Оставить одну source-of-truth страницу, в остальных ссылки |
| запись в `CHANGELOG.md` только за docs-правки | Убрать запись, если не было продуктового изменения |

## Wiki cross-check

После обновления документации проверь, не затронуты ли wiki-концепты:

1. Прочитай `wiki/index.md` — найди wiki-страницы, связанные с изменёнными модулями.
2. Если изменение меняет поведение, интерфейс или выводы, отмеченные в wiki-странице — обнови wiki-страницу или добавь пометку о необходимости ревизии.
3. Запусти `python wiki/wiki.py status` — убедись, что нет broken links.
