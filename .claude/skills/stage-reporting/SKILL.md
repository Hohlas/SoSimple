# Отчёт по этапу

Workflow для фиксации завершённого этапа без потери контекста.

## Когда использовать

- Пользователь явно просит закрыть этап.
- Пользователь просит подготовить подробный отчёт этапа.
- Пользователь просит синхронизировать `report`, `CHANGELOG.md` и `CONTEXT_HANDOFF.md`.

## Когда нужен полный отчёт

- Изменилось поведение кода, влияющее на результаты, сигналы, торговую логику, CLI или формат данных.
- Добавлен или существенно расширен инструмент или исследовательский сценарий.
- Получены новые результаты с практическими выводами.
- Исправлен баг, меняющий интерпретацию результатов.
- Завершён план/спек-этап, пригодный для handoff.

## Workflow

1. Определи дату (YYYY-MM-DD HH:MM) и короткую тему этапа.
2. Создай или обнови `docs/reports/YYYY-MM-DD-topic.md`; в поле `Related commit` поставь `pending`.
3. При новых фичах, breaking changes, багфиксах, результатах экспериментов с выводами обнови `CHANGELOG.md`, добавь в него КОРОТКУЮ запись со ссылкой на report.
4. Проверь, нужно ли обновить `CONTEXT_HANDOFF.md`.
5. Обнови `.claude/memory/` только если изменились устойчивые знания или правила.
6. Обнови wiki-синтез: обнови или создай соответствующие страницы в `wiki/research/` и `wiki/concepts/`, добавь запись в `wiki/log.md`, запусти `python wiki/wiki.py generate`. Включи всё это в коммит.
7. Создай git commit со всеми изменёнными файлами этапа, без `git push`.
8. Обнови поле `Related commit` в report, заменив `pending` на реальный hash коммита.

## Правила

- `report = полный итог`
- `CHANGELOG = короткая история`
- `handoff = текущее состояние`
- `memory = долгоживущие знания`
- Не обновлять `CHANGELOG.md` для чисто документационных правок без продуктового изменения.

---

## Правила заполнения CONTEXT_HANDOFF.md
CONTEXT_HANDOFF.md - это рабочий handoff для следующего ИИ агента в следующей сессии, а не история проекта и не полный отчёт. Он должен содержать только актуальный лаконичный контекст текущего состояния работы над проектом. При закрытии этапа его не нужно дополнять/раздувать, а переписать/сжать до актуального состояния.

## Образец заполнения CHANGELOG.md

```markdown

## [YYYY-MM-DD] — Краткое описание
### Добавлено/Изменено/Исправлено
### Результаты
### Вывод
<!-- ссылка на отчёт: docs/reports/YYYY-MM-DD-topic.md -->

```
